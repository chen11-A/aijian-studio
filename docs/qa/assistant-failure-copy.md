# 助手失败提示：美术／画面说明／人物提取

本批只收尾真实软件固定失败提示和本地能力前置，不统一模型正文、用户小说或供应商有效原因，不代表文案表 262 项全部完成。

## 实际消费者与排除

`ProWorkspace.finishTurn` 经 `film/notices.ts:presentNotice` 把 text 存进聊天；plain string 即使命中 legacy／RULES，其原整句 detail 仍可能直接成为聊天正文。`next/wiring/noticeCopy.ts:statusLine` 是另一条状态栏消费者。因此不能因识别出 code 就把旧整句算已替换。

已正确覆盖并保持原样：`ART_APPLIED_UNSAVED` 的状态栏最终显示“美术的建议已经放进去，还没保存上”；可靠字段卡的 `PROMPTER_SUGGESTION_READY`／`PROMPTER_FIELDS_APPLIED`／`PROMPTER_APPLIED_UNSAVED` 已准确区分待确认、已应用、未保存。全局 NOTICE_COPY、旧识别常量、118／106 历史文案基线、已持久化 reason 均未修改。

## 本批修改

- `actions/art.ts`／`prompter.ts`：保留原请求、解析、有效正文和生成次数；无可用结果时返回原失败身份的结构化提示，聊天与状态同步说明本次没有修改。无 code 的不可用回答沿用原阶段失败码；有真实 code／短屏幕原因时保留，不把会员限制或模型不可用换成格式失败。空回复不再显示空消息，本回归的完整请求抄回仍判为不可用，不把原请求转储到聊天。
- `actions/cast.ts`：空／错误回答明确“本次没有新增人物或场景”，不写猜测；真实账号／供应商原因及 code 仍保留。原离线提取规则、同步执行时序、项目／epoch／notice guard 不变。
- `completeAgent`：缺文字桥、未登录、无工程分别复用既有码；账号拒绝／登录过期的精确提示仅在原 `!connected` 零派发门内选择，不因多订阅短暂不同步新增拒绝策略。没有工程时实际 UI 不提供助手按钮；不虚构能点击的“无工程生成”路线。
- 公共 foreground 异常用原角色失败码的短句，同时保持原错误边界；不把底层 Error 的路径／stack／私有标记显示给用户。
- 旧的非字段卡画面说明路径：按真实 editor apply conflict 区分 BUSY／过期／没有改动等，保留实际 conflict code；已应用未保存复用原专有码，不再混为“镜头已变更”。合法模型文本中的网址仍完整保留，未新造内容过滤器或改 provider prompt。

`agent-failure-notice.ts` 只组装显示数据。真实 GrokTextResult.detail 合同规定为短屏幕原因、不是 raw body／token；本批保留这些合法原因，不建立全局错误日志尾截取或启发式脱敏引擎。模型成功正文不经此 helper 改写。

## 回归及边界

新增真实 Pro 控件回归覆盖两助手的请求抄回、不可用／空回复、请求已返回会员拒绝／模型不可用、底层异常、缺桥、未登录、缺方法、账号已拒绝和登录过期，共 22 场景；另验证未开工程时没有助手动作且零派发。固定前置 0 completeText，已返回失败仅原 1 次请求，均无视频调用、无建议和无创作字段变更。状态栏及聊天实际消费者均断言；供应商原因保留、异常私有标记不出现。

原画面说明宿主另补 BUSY 未修改、真实 editor apply 后保存失败两条；后一条保留实际 prompt 字段、旧 poster／takes，不能假称未应用。人物 action 仍证明无解析结果不猜人、不覆盖较新的通知；原美术事务、字段确认、保存失败、迟到媒体／换工程、undo 回归保留。

已实跑：最终同源 **11 文件 329 项通过**，覆盖原完整 Pro 及字段／事务／scope／notice 联合。正式 Web build（含 `tsc -b`）、目标 ESLint／Prettier／diff 检查通过。全部模型／原生调用均为受控替身，没有真实会员调用或付费生成；本批未改原 244＋本地库 16 态脚本／CI 门，不用已有 Chrome 结果代替本源码验证。

后续未做：其他助手／动态成功句及残余界面称呼须按真实消费者另查；未全仓替换“提示词”等内部字段／供应商 schema 名，未改变合法模型和用户文字。现存写入握手、付费／历史准备、字段确认和媒体策略不属于本批重写范围。

具体保留项：无镜头前置句的“提示词工程师”称呼、旧非字段卡成功标题“提示词 · 镜头”与动态成功句仍待后续显示用语核对；本次没有借词表改选择 guard 或把它们当失败。人物成功通知的合法名字仍留详情，其他助手的用户／模型正文不做机械替换。
