# Prepared generation API54 — intermediate core

This checkpoint supplies the actual signed sidecar protocol behind the native fixed-reference helper checkpoint 51cc2b5. It is not the completed automatic-image/fresh-project/continuity feature. No external provider or paid account was used.

## Implemented boundary

Migration 54 adds seven private execution/target/stage/dependency/slot/retirement/arm tables. Existing video51, recovery52 and StoryFilm53 policies, limits and rows retain their semantics. Six migration fixtures compare the original table SQL and preserved rows while excluding only the seven explicitly named new tables; new tables must be empty.

Native account-attested raw bytes register the original effective recipe and fixed-reference evidence. Execution shape, local IDs, versions and group do not create different failure buckets. A stage reserves the original StoryFilm policy only immediately before its actual image dispatch. Parent and video policy configuration are checked before new image work; no default limit is supplied and no speculative video reservation is created. `VIDEO_UNCONFIGURED` and `VIDEO_INPUT_FAILURE_LIMIT` distinguish the video configuration gate from parent configuration.

The private arm fixes raw body SHA plus ordered source role/index/canonical identity/SHA/MIME. The actual StoryFilm consumer rechecks those sources and uses internal immutable bytes before compiling with the original API producer. The legacy HTTP 500-character source fields are unchanged. Replacing bytes at the same path or switching a source alias cannot be authorized by the old arm.

Actual first transport adopts the existing prerequisite hold once or reserves its own confirmed slot. A PENDING/UNKNOWN original input blocks new executions even if the configured limit is raised. Missing output is UNKNOWN, not proof of no request. Retirement only releases genuinely unsent work; known completed images retain a consumed failure when execution is abandoned; uncertain work remains occupied. Picture completion alone never releases the parent. Known readable video success remains independent from later local assembly failures.

Prepared-only cache-v2 binds the complete recipe and all three product SHAs. A coherent completed bundle survives later partial writes. Cache metadata is not authorization; the actual consumer still verifies readable media. An unproved legacy cache is not promoted to a current prepared cache. Unscoped legacy53 consumers retain their existing cache behavior.
