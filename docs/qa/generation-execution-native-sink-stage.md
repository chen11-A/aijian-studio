# Protected native generation sink stage

This checkpoint implements transient native registry/owner retirement, closed prepare/retire IPC registration and optional protected image/local-frame dispatch routing. Missing protected hooks reject without entering legacy dispatch. It is not the completed API54 factory or an authorization based on issued IDs: trusted canonical/source/ledger verification and required video/cache/local capabilities remain necessary before dispatch.

The image driver delegates to the existing production serializer/downloader/file writer. Only the synchronous final fetch invocation records a POST dispatch. A failed reservation is distinct from a sent request. Any download/byte-read/write exception after POST still calls the private observation adapter and returns WRITE_UNCONFIRMED, never the proven-unsent cleanup. A written image survives an unknown lineage ACK; no automatic retry is introduced.

Controlled regression evidence: `/tmp/generation-execution-still-throws-before.log` has four new failures and five existing passes. `/tmp/generation-execution-still-throws-after.log` has 4 files/33 passes (registry 11, execution IPC 4, library IPC 9, image driver 9). The four cases exercise download rejection, HTTP failure, arrayBuffer failure and a real EISDIR write failure with preserved sentinel bytes. These are fake HTTP plus actual local file operations, not signed API54/Grok/paid generation evidence. Desktop typecheck and owned ESLint/Prettier pass; logs use the generation-execution-native-sink prefix. Original source/helper stages are separate and are not added to this count.

## Native service lifecycle checkpoint

The native lifecycle service is kept separate from the not-yet-complete canonical/source/cache/ledger adapter. Its prepare callback is required, returns the native registration only after all required checks, and is not implemented by a renderer supplied table. The service parses exact local scope, serializes preparation per project, captures its own owner epoch and the real owner predicate, matches the returned project/hash/ordered slots to the original request, and only then publishes the registry result. Explicit owner disposal blocks a late registration even if the caller reuses the same owner object. Failed publication retires the completed private execution. Slot/all retirement invalidates captured dispatch predicates synchronously before awaiting private cleanup; failed cleanup does not revive a lease or claim HTTP stopped/UNKNOWN released.

Controlled native lifecycle/registry/IPC result: 3 files/22 passed (`/tmp/generation-execution-service-tests-delivery.log`), consisting of service 6, registry 12 and IPC 4. This overlaps earlier registry/IPC counts. Desktop types, owned lint/format and diff checks pass. No main/preload capability is advertised by this module alone, no HTTP protocol is invented, and the full native factory still requires the backend's actual per-slot cache/local and final wire-byte/role binding adapters. The private video IPC checkpoint separately retains the legacy third-argument parser, while four-argument protected requests use the exclusive main callback or fail closed.

The sandbox preload now preserves the public fifth still, third extraction and fourth StoryFilm execution contexts on their fixed channels. Legacy argument counts remain exact; an explicit null context is forwarded for main rejection instead of silently downgraded to the legacy path. No account, private arm or dependency graph is added. New forwarding plus existing last-frame/policy preload tests pass (3 files/4 tests, `/tmp/generation-execution-preload-tests.log`). The prepare/retire capabilities themselves are not advertised until the real native factory is composed; context forwarding is not a claim that API54 is ready.

The backend's current real observation protocol defines every null output observation as UNKNOWN, including a fully received non-2xx response; it never permits another POST for the same stage. The protected driver therefore brands every dispatched empty-output result (retaining a more specific fixed native/account failure where present), observes it and never routes it through proven-unsent cleanup or the old unbranded retry path. Two additional cases cover a 503 and a 200 without output; the image driver has 11/11 passing (`/tmp/generation-execution-null-output-tests.log`). A future explicit known-FAILED observer outcome must come from the backend's typed protocol, not a guessed status field. Native typecheck is `/tmp/generation-execution-null-output-types.log`.

## Final canonical queue handoff

`film-generation-queued-dispatch.ts` reuses the existing `transactFilmProject` queue. Reservation/arming must occur outside it. Inside it, the actual project is re-read without a series fallback, the native bounded canonical/source-body verifier runs, and the captured owner/account/retirement predicate is checked immediately before synchronous transport entry. The provider Promise is captured with both outcomes observed, while the transaction completes immediately; later project saves can finish while HTTP remains held. This helper performs no save, no permission calculation and no HTTP protocol construction. The future real factory must supply the trusted verifier and source/ledger adapters; their presence is not inferred here.

Six real-FS/original-queue tests pass (the final queue/driver joint is 2 files/17, including 11 overlapping driver tests, `/tmp/generation-execution-queued-driver-tests.log`): a later ordinary save finishes during held transport, retirement during verification sends nothing and preserves the queued save, missing episode/series fallback is rejected, already retired owner never verifies/dispatches, an immediate transport rejection does not poison the queue, and the actual protected driver preserves the final queue gate’s trusted fixed code rather than treating it as raw transport text. Teardown releases only this fixture's held promises, awaits all started operations, then removes its own temporary directory. Formal native types pass (`/tmp/generation-execution-queued-driver-types.log`); this remains a local native building block, not the composed API54 factory, source authorization or real provider proof.

## Original output-byte witness

The one `requestStill` writer gains only a main-only synchronous callback for its validated original response bytes. Serialization and the legacy `{path, reason}` result remain unchanged. The protected driver captures SHA from those bytes, then, only after the write succeeds, uses the existing bounded `readMedia(expectedSha256)` check on the actual path. A successful private observer receives that original SHA so it can recheck immediately before recording lineage; the SHA is not added to the public result, project, history or archive. Download/write failures and an unverified current file do not emit a successful witness. Existing files are retained when confirmation is unknown.

Controlled real-file before: `/tmp/generation-execution-bytes-witness-before.log` fails because a replacement at the same path can otherwise be recorded as a successful output. Separate legacy still 1/9 and reference-wire 3/24 selected tests pass; skipped cases are not claimed. Native typecheck, owned ESLint/Prettier and diff checks pass. This closes the native building block's byte witness, not the still-missing full main/API54 composition or real provider execution.
