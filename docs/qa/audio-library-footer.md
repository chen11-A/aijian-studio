# 本地素材待核对入口：页脚裁切

正常沙箱 Chrome 首轮本地库门（run 42315848425／job 128228118197，source aadd979）有四个 `library-unknown-recovery` 组合真实失败，尚不能写成 16 态通过。

1280×800 中待核对按钮位置为 `(559.6,777,160.7,26)`，页脚裁切框为 `(0,776,1280,24)`，任务入口换行至 `y=803`。1920×1080 同样出现 26px 按钮超出 24px 页脚和第二行任务入口。两画幅均命中原 `control-clipped-without-scroll` 门，未取得匿名 artifact，不声称已目视截图。

源码原因是 `pro.css` 只让 `.sb-left`／`.sb-right` 使用横向 flex，而 `.sb-mid` 为普通块，内部 `.task` 的 flex 块另起一行；`.btn.sm` 高度 26px 也超过固定 24px 页脚。局部补丁把 `.sb-mid` 纳入原横向对齐规则，并仅将该区直系小按钮设为 20px，保留完整按钮、文案和原任务入口。没有修改页脚高度、几何阈值、缩放、状态数量、浏览器参数或产品行为。

正式 Web build（含 `tsc -b`）、Prettier 与 diff 检查通过。正常沙箱的新 16 态正向由 CI 复验；本机沙箱受限，没有用禁用沙箱或样式注入冒充已通过。
