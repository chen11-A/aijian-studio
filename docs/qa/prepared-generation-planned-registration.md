# Planned reference registration adapter

This native-only checkpoint builds on 127f677's private forecast protocol. The existing four-argument `buildGenerationRegistration` remains fail-closed for consumed missing references. A native factory may explicitly pass a fifth `{plannedReferences:true}` **only after** it has the actual protected image driver, whole-input comparison, private lineage checks, account/current lifecycle and final dispatch gate connected. No renderer option or public ABI was added. This opt-in does not make continuity, mixed per-slot cache or all-selected-pipeline scopes supported.

The opted-in builder delegates to the same original selectors/reducers and returns the complete typed forecast/source mapping. Every actual stage's private origin receives its exact forecast prompt/model/aspect, ordered recursive reference graph and `referenceMode:"planned-v1"`. Side/back stages obtain their front creator input through that same graph. A factory must use `verifyGenerationStageImage` on the actual current input before the provider send and may not assume a marker is a file or an output.

`CanonicalGenerationPlan.intentStages` is an identity-only view compiled from restored original intent, not issued work. If current scene/frame outputs already exist, actual `stages` can be empty while `intentStages` retains their original creators. The forecast maps actual stage IDs by exact kind/target/view only for dispatch locators; creator graphs contain no such IDs. This prevents an automatic output saved into the project from creating a different failure bucket after restart, without scheduling another image request. No new scope, stage dependency set or provider quantity is accepted from the renderer.

The additive `restoreGenerationIntent` final optional argument `{originalShot,firstNewTakeId}` is a main-owned queue snapshot. Its final validation delegates to `compileQueuedCanonicalGenerationTarget` → the original `generationVideoBody` and strict `parseStoryFilmCreate`. This preserves the original reviewed first automatic take-selection transition; wrong first IDs and true later creative edits fail. The caller must still enforce the original prefix/new-tail slot mapping (3cf shared queue helper). The helper neither clears/rebinds a stored seven-part review nor authorizes arbitrary take IDs.

Actual closed CJS/native integration: opted-in missing-reference registration, exact registered stage origins, current output/restored original intent equivalence across a subsequent execution, zero actual new stages on that reuse, one/three-version reviewed queue transitions and wrong-ID/creative-edit negatives all pass. Default registration's original missing-capability refusal stays tested. The initial new queued comparison failed because it compared a strict parsed body with the producer's untrimmed/empty optional shape; the assertion now compares both through the same original strict parser (`/tmp/prepared54-planned-queued-first.log` retained). Final one-test integration passed in 1.48s (`/tmp/prepared54-planned-queued-after.log`); desktop typecheck, target ESLint/format and diff checks accompany this checkpoint. API/schema/contracts were not changed relative to 127f677; no external provider or actual paid account was used.
