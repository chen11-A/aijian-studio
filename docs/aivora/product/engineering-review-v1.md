## 1. 优先裁决建议（按冲突优先级）

### 1.1 Q10：任务详情 hash vs API55 私有 cache/path/recipe/SHA（高）

**冲突段落**

- 上位规范 `ui-engineering-standards.md`（f59affe 与本地副本一致）任务队列信息契约：「任务详情必须显示……精确 `artifact_id/version_id/hash`」（约 :27）。
- API55 合同冻结决议：`cache`、`canonical_path`、`snapshot_sha256`、`runtime_recipe`、`parts` 只给签名后的 main；「上述私有字段不进入 `FilmGenerationExecutionResult`、preload 或 renderer」。`canonical_path`、来源 SHA、运行配方不是 renderer 授权事实。
- 编码规范：Electron Renderer 禁止 Node 集成；跨边界只认生成契约；日志不得含签名 URL 等敏感材料。
- 规格 Q10（:714）及 §14.0：v1 已撤「短哈希摘要」；renderer **不新增** cache/path/recipe/SHA；短摘要不得当安全替代。

**建议（默认守既有合同，不自改合同）**

1. v1 任务详情只显示：**中性状态**（如「输入已核对 / 未核对 / 不可核验」）、产品层 `entityId` 与版本序号（`vid`/`seq`，例如「女孩外貌 v3」）、公共面已有中性标签（最多 `CLIENT_IMAGES` / `STORYFILM_CACHE`）、岗位、步骤、尝试次数、成本分项、合法动作。
2. **完整或截断的 SHA、路径、recipe、私有 cache 对象不得下传 preload/renderer，也不得画在 UI 上。** 截断哈希仍是 SHA 材料，不是安全替代。
3. 上位规范 :27 的 `hash` 项在 v1 **明确不满足**，作为已知差异记录，等合同提案另审；不以改 OpenAPI、补 409 到生成 schema、或把私有字段塞进公共 `PREPARED` 来迁就 UI。
4. 若确需不透明展示 ID：由 main 单独铸造与 SHA 无推导关系的显示别名（例如「准备号 A3F2」），映射只留在签名后的 main；这须另列**待审合同提案**，本审查不起草、不落库。
5. 既有 409 `INPUT_UNVERIFIABLE` vs 生成 schema 仅列 200/422，仍是合同未闭合项，不在本审查范围修。

### 1.2 UNKNOWN / 预约未结算 vs 预研 A5/C5 泛重试（高）

**冲突段落**

- API55：`UNKNOWN` 留在原失败桶；提高 N、新 execution、新 offer、输出 SHA 或临时路径都不能解锁；缓存读取不结算它。
- 规格 §6 第 3 步（:337）、R04（:488–491）、GX3（:188）、附录 C（:833）：UNKNOWN 和预约未结算只有「核对结果」，点击不建任务、不发请求；只有**明确失败 + 结算已确定 + 预算与权限允许**时，经确认框按现有任务合同建 1 个新 Attempt；从不自动重试。
- 预研 A5/C5 曾建议「接口/瞬时失败可在预算内同参重试」。

**建议**

预约/账本门优先于 A5/C5。结果不明或预约未结算时，UI 不得出现会发请求的「重试」。A5/C5 只在规格已写的 ①–③ 同时满足时适用。质量失败走「改条件后再生成」，不得借质量分类绕过 UNKNOWN 核对。不得把该建议写成自动重试或改额度规则。
