## 2. 最重要的设计决定

| # | 决定 | 理由（证据） |
|---|---|---|
| D1 | **唯一专业工作区，8 个阶段**：小说、剧本、角色场景、分镜、画面、视频、剪辑声音、导出。不新增“普通模式”。一键成片只是同一阶段链的**自动推进器**，停在相同的门上 | 用户核心诉求是“下一步点什么不明确”（O12/O13） |
| D2 | **全局唯一主下一步**由一个纯函数从项目数据派生。任何页面、任何时刻，唯一的 primary 按钮始终是 `nextAction`，只在一处呈现（顶栏或页面内，二选一，见 §6）；其余所有动作都是 secondary | O12 多入口；4A-U09 |
| D3 | 人物出场、固定外貌、场景、时长、声音意图都改成**结构化字段**，带稳定 ID 和版本。生成请求只从结构化字段组装；正文文本只用于描述。字段冲突时**阻断**，不只提醒 | O4/O5/O6/O8/O11；用户要求“不许只靠提示词” |
| D4 | 画面到视频之间加**人工采用门**：先核对“应出现的人、不应出现的人、外貌要点”，采用后才能生成视频。自动看图审片属于 P2，等会员能力测试 | O6 无法只靠生成前约束消除；4A-B05 要求先测能否看图（:924） |
| D5 | 内容版本不可变、版本号单调不复用；上游修改沿生成依赖做**传递闭包**失效，把全部下游标成“待更新”（§4.1、§8）。资产保留、可查看，但不能作为新生成的输入；导出时必须显式处理 | O8 改了外貌却没有任何提示 |
| D6 | **声音意图必须显式**。没有可听声音时，导出前必须二选一：“静音导出”或“先去做声音”。“有 AAC 轨”永远不等于“有声音”。是否兑现声音意图由声音覆盖、意图兑现、测量诊断和人工试听**联合**判定，任何单一响度阈值都只是诊断（§3.3 G7） | O16/O17/O18 |
| D7 | 时长用**测量值**说话：镜头目标时长 → 请求参数 → 生成后探测实际时长 → 时间线 → 导出探测。每一环都显示探测到的实际秒数；不设容差、不出偏差提示、不作通过/失败断言（【用户裁决】①） | O3、O18（15.29s 与 15.0s 有差） |
| D8 | 公司式分工 = 每个阶段有一个**负责岗位**（编剧/美术/导演/摄影/剪辑/声音/制片），只在界面上标注和用作助手默认角色，不新增智能体。开发分工另见 §9 | 用户诉求；AI 助手已有“正在和：编剧/导演/美术”下拉（截图） |

## 4. 数据模型（拟议，阶段之间传递的“真实数据”）

### 4.1 版本、事件、有效性（统一策略）

本规格只采用下面这一种策略：

1. **内容版本不可变。** 每次修改实体内容都生成一个新的内容版本 `vid`（全局唯一、永不复用），同实体内展示序号 `seq` 单调递增（“女孩外貌 v3”）。版本之间用 `parents[]` 组成修订 DAG。旧版本永不改写、不删除。
2. **当前选中引用 `head`。** 每个实体有一个 `head` 指向当前选中的内容版本。撤销、重做、“换回旧版本”只是**移动 `head`** 到已有 vid，不产生新内容版本，也不让任何 seq 回退。
3. **事件序号与内容版本分开。** 所有修改、撤销、重做、选中、锁定都追加一条事件（事件只移动 head 或产生新版本，从不改写已有版本或 basis），事件序号 `eventSeq` 全局单调递增；撤销本身也是一条新事件。
4. **生成依赖记录精确版本。** 生成物保存 `basis: InputRef[]`，每项是 `{entityId, vid, edge:"gen"}`，表示它是用哪些上游的哪个内容版本做的。
5. **有效性派生，不存储，传递闭包。** `valid(x) ⇔ 对 basis 中每一项 r：head(r.entityId) == r.vid 且 valid(r.entityId 的 r.vid)`。只有原引用**完全恢复**（head 指回同一个 vid）才 VALID；用户手动把文字改回原样会生成新 vid，仍然 STALE（可以用「换回 v2」移动 head 来恢复）。
6. **v1 不提供“确认仍适用”旁路。** 内容版本和它的 basis 都不可变。上游改了以后，下游即使内容看起来不需要变，也只能：复核后需创建新派生版本；不改写历史 basis、不自动使媒体 VALID，已有真实生成物不能换记为用新输入生成；过期素材必须重做后才能导出，v1 没有沿用旧成片的导出入口（【用户裁决】③）。VALID 只来自两种情况：① head 指回确切的原始版本（撤销/换回）；② 用新输入真实生成出新派生版本。不能靠人工确认把 STALE 洗成 VALID。“轻微文本更改的复核辅助”（例如只改错别字时帮用户判断影响）列为 P2，不在 v1。
7. **两类边。** `gen` 边 = 实际参与生成的输入，沿它传递 STALE。`ref` 边 = 只用于参照复核、不参与生成（例如小说原文 → 场次，只用于覆盖检查），沿它只产生“需复核”提示，**不**传递失效。一个字段只要实际进入生成请求，就必须是 `gen` 边，不能降成提醒。

```ts
type InputRef = { entityId: string; vid: string; edge: "gen" | "ref" };
type Version<T> = { entityId: string; vid: string; seq: number; parents: string[]; content: T; basis: InputRef[]; provenance: Provenance };
type Head = { entityId: string; vid: string; setByEventSeq: number };
type Event = { eventSeq: number; at: string; by: string; kind: "edit"|"undo"|"redo"|"select"|"lock"; entityId: string; toVid: string; basis?: InputRef[] };
type Provenance = { by: "user"|"ai:writer"|"ai:director"|"ai:art"|"import"; at: string; fromProposalId?: string; review: "suggested"|"accepted"|"userEdited" };
type Validity =
  | { state: "VALID" }
  | { state: "STALE"; direct: InputRef[]; via: string[] }  // direct：版本不匹配的输入；via：传递而来的上游实体
  | { state: "BLOCKED"; missing: MissingItem[] }
  | { state: "UNKNOWN" }                                  // 已提交但结果未确认，禁止自动重提（对齐既有 UNKNOWN 语义）
  | { state: "FAILED"; code: string };
```

与上位规范对齐：AI 结果先作为草稿，区分“建议 / 已接受 / 人工修改 / 已失效”（ui-engineering-standards.md:19）——前三者是 `provenance.review`，“已失效”是派生的 STALE。

### 4.2 各实体（每个都按 4.1 版本化）

| 实体 | 关键字段（拟议） | 说明 |
|---|---|---|
| SourceText | `text, importedFrom, charCount` | 小说原文。Scene 对它只有 `ref` 边 |
| Scene | `title, locationIds[], timeOfDay, text, sourceSpan` | 地点和时间必填（O2），没有就 BLOCKED，补齐入口是场次标题 |
| Character | `name, kind:"human"\|"animal", gender?, ageBand?, voiceId?` | 沿用 C8。animal 可以没有性别和声音。`voiceId` 只在该角色有说话行（对白/旁白/画外音）时才需要 |
| LookSpec | `characterId, fixed:{key,label,value}[], notes, locked` | `fixed` **全部参与生成**（gen 边）。`notes` 是备注，**不参与任何生成请求**，界面标“仅备注，不会发给 AI”，改动不触发失效。旧版的 freeText 字段取消：要参与生成就写进 `fixed` |
| Portrait | `characterId, angle:"front"\|"side"\|"back"\|"face", assetId`；basis 含 LookSpec、Character、画风 | **正面是唯一最小必需**；其他角度是按能力的可选扩展（4A-B03 从正面改图） |
| Location | `name, description` | — |
| LocationPlate | `locationId, timeOfDay, assetId`；basis 含 Location、画风、所属 Scene 的时间 | 地点空镜（4A-B10） |
| Prop | `name, ownerCharId?, fixed:{key,label,value}[]` | 固定材质/花色等，参与生成 |
| Shot | 由三个**独立版本化的部件**组成：`visual {sceneId, order, shotPolicy: "character"|"establishing", framing, motion, description, locationId, cast: CastEntry[], excludedCast, propStates[], refPolicy?}`（`establishing` = 明确空镜，见 §4.4）、`timing {targetDurationSec}`、`sound: SoundIntent` | 三个部件分别有 vid，改时长不会让画面失效（§8）。basis 都含所属 Scene |
| CastEntry | `{charId, entrance:"present"\|"enters"\|"exits", positionHint?}` | 出场必须结构化；`firstAppearanceShotId` 派生 |
| PropState | `{propId, state}` | 每镜可变状态，参与生成 |
| StillTake | `shotId, assetId, acceptance?: {by, at, checklist}`；basis 含 shot.visual、cast 的 Portrait/LookSpec、LocationPlate、Prop、画风 | 必须“采用”过（R13）才能作为视频首帧 |
| VideoTake | `shotId, assetId, measuredDurationSec, hasAudioStream`；basis 含已采用 StillTake、shot.visual、shot.timing、参考集合、（口型镜头）角色声音 | 时长来自探测 |
| SoundClip | `shotId, itemId, lane, assetId, measured?`；basis 含 shot.sound、（对白）角色声音 | — |
| Timeline | `clips:{shotId, videoVid, in, out}[], lanes`；basis 含各镜 shot.timing、选中 VideoTake、SoundClip | — |
| ExportJob | `settings, audioDecision:"WITH_AUDIO"\|"SILENT_BY_USER", qc, outputs[]`；basis 含 Timeline；basis 中有任何 STALE 就不能创建（【用户裁决】③） | — |

```ts
type ItemStatus = "suggested" | "accepted" | "rendered";       // suggested 只是文字建议
type ClipRef = { entityId: string; vid: string };              // 只有 rendered 才有
// 说话方式：对白 / 旁白（含内心独白）/ 画外音。没有说话行 = 本镜无台词，不等于静音
type SpeechMode = "dialogue" | "narration" | "voiceover";
type SpeechLine = {
  id: string;
  mode: SpeechMode;
  speakerId: string;                                           // 说话人（角色 ID）
  text: string;
  delivery?: string;                                           // 说法，例如“轻声”
  voiceId?: string;                                            // 声线；有说话行时才需要
  voiceRef: "own" | "authorized" | "none";                     // 参考人声：用户声明，系统不得推断
  status: ItemStatus; clipRef?: ClipRef;
};
type BedItem = { id: string; lane: "ambience" | "sfx" | "score"; label: string; status: ItemStatus; clipRef?: ClipRef };
type SoundIntent =
  | { mode: "silent"; reason?: string }                       // 仅表示：整镜明确不要任何声音
  | { mode: "sound";
      speech: SpeechLine[];                                    // 可为空：无台词
      beds: BedItem[];                                         // 可为空：环境、音效、配乐可多条并存
      intentionalGaps?: { inSec: number; outSec: number; note?: string }[]; // 有意留白区间
    };
```

规则：
- `mode` 二选一：`silent` 只代表“整镜明确无声”，不带任何条目；`sound` 要求 `speech` 与 `beds` 合计至少 1 条。
- 说话方式与环境/音效/配乐**不互斥**，可以同时存在；`speech` 为空（无台词）而 `beds` 有内容是合法的，此时**不需要声线**。不能把“无台词”当成整镜静音（【代码审查报告】A1 现状：无台词时对白合成返回静音 PCM，需在新候选验证）。
- 未标注时不默认成对白，也不默认加配乐（【预研】A3 建议）。只有 `dialogue` 且说话人在 `cast` 里才建议做口型；旁白、画外音不做口型。
- `voiceRef` 由用户声明；只有音色描述或只上传了音频，**不得**推断为已授权（【预研】A3、C3 建议）。具体授权政策待定（Q13；见Q13建议）。
- “有意留白”是 `sound` 模式下用户声明的局部区间，与“无意静音”（有声意图区间里测得静音，且没有声明留白）分开记录。

### 4.3 合法性检查（生成前 gate，都是阻断）

| 规则 | 失败时 |
|---|---|
| V1 出场已显式确认：`shotPolicy=="character"` 时 `cast` 非空；`shotPolicy=="establishing"` 时 `cast` 必须为空。`cast` 为空且未选 establishing → BLOCKED「这一镜有没有人物还没确认」，**不回退到全员，也不回退到按正文点名**。镜头正文里点名的角色（按角色名和别名匹配）必须 ∈ `cast`；`cast` 不能含 `excludedCast` | BLOCKED「镜头 3 正文写了‘老人’，但出场角色里没有。」+「去改出场」链接 |
| V2 **只针对本镜 `cast`**：其中每个角色（human 与 animal）都有锁定 LookSpec 和 **VALID 正面定妆照**。这是唯一最小必需；侧面、背面、脸部特写是按能力的可选扩展，缺了不阻断。未出场的角色、空镜都不适用 V2 | BLOCKED「老人还没有正面定妆照」+「去出定妆照」链接 |
| V3 必需参考集合 = cast 每个角色的正面定妆照 ∪ 地点空镜 ∪（仅视频）已采用首帧。总数不得超过当前能力上限（沿用 3J-B07 的 ≤5 首帧 / ≤13 视频；【代码审查报告】C4 所载现状：有地点图时人物最多 4 张 + 1 地点图，否则 5 张，视频另最多 12 或 13 张，超限由 `STILL_CAST_LIMIT` 挡住；这是实现选择，不是厂商承诺，以能力表为准）。**超限时 BLOCKED，不得静默或自动裁掉任何身份参考。** 可选角度只在必需集合之外还有容量时按固定规则附加，并在请求清单逐项显示 | BLOCKED，列出「上限 5 张 · 需要 6 张：女孩正面、老人正面、猫正面、路人正面、门前空镜、首帧」，给两条出路：①「去调整镜头」（减少出场或拆镜头）；② 能力表里标明**支持**的替代策略（例如多人合成参考板），须用户逐镜点「采用这个策略」确认，确认写入 `shot.visual.refPolicy`（属于内容版本，改动会失效）。未经确认不得丢掉任何身份引用 |
| V4 `locationId` 必填并存在，且地点空镜 VALID | BLOCKED「这一镜还没选地点」+「去选地点」链接 |
| V5 `targetDurationSec` ∈ 会员可选值（截图可见 2/3/4/5/6/10） | BLOCKED「会员视频没有 7 秒，可选 6 或 10 秒」+「去改时长」 |
| V6 角色 kind=human 时，性别、年龄段已填（O9） | 阻断「锁定外貌」（因此间接阻断该角色出场镜头的出图）；声线按性别过滤（C8），只在有说话行时需要 |
| V7 有说话行的镜头：每行有说话人和声线 | BLOCKED「镜头 2 的对白还没选声线」+「去选声线」。只有环境/配乐的镜头不适用 |

## 5. 阶段规格（8 阶段）

每阶段共用的状态枚举：`未开始 / 缺输入 / 可开始 / 处理中 / 结果未确认 / 失败 / 待确认（有 AI 提案未采纳） / 待更新 / 完成`。顶部阶段条显示“名称 + 状态 + 计数”，例如「画面 2/3 · 1 待更新」。下表“主下一步”只是该阶段内 `nextAction` 可能取到的值，同一时刻全局只有一个（§6）。

| 阶段 / 负责岗位 | 输入 | 输出 | 完成条件 | 主下一步（按优先级） | 典型禁用原因 → 补齐入口 |
|---|---|---|---|---|---|
| 1 小说 / 编剧 | 文件或粘贴 | SourceText | 有原文 | 「导入小说」 | — |
| 2 剧本 / 编剧 | SourceText | Scene[]（含地点、时间） | 每场有正文、地点、时间；C9 覆盖 ok | 采纳提案「放进剧本」→「让编剧分场」→ 补地点 →「下一步：角色场景」 | “第 1 场还没写地点”→「去写地点」链接（场次标题编辑框） |
| 3 角色场景 / 美术 | Scene、正文中的角色 | Character + 锁定 LookSpec + 正面定妆照（可选其他角度）；Location + 空镜；Prop | 按实际被引用集合（§4.4）：镜头 cast 并集中每个角色（含动物）都已锁定且有 VALID 正面定妆照；每个被引用地点都有 VALID 空镜。未被引用的角色不影响完成 | 「锁定外貌」→「给出场角色出正面定妆照（还缺 N 张）」→「出地点图」；次级「补其他角度（可选）」 | “老人性别没写”→「去选性别」；“外貌已改，定妆照是旧的”→ 主下一步变成「按新外貌重出」 |
| 4 分镜 / 导演 | Scene、角色、地点；**目标：镜头数和时长**（不要求先锁完所有角色） | Shot[]（结构化 shotPolicy、cast、地点、道具状态、时长、声音意图） | V1、V4、V5 通过；合计时长落在目标内 | 「让导演拆镜头（目标 3 镜 × 5 秒）」→ 采纳 →「下一步：画面」 | “镜头 3 正文有老人，出场里没有”→「去改出场」 |

### 5.1 各阶段补充

- **剧本：** AI 提案卡显示“现在 X → 建议 Y”（4A-U11 既有），采纳会产生 Scene 新内容版本，提供「撤销」（O1 已有，保留；撤销按 §4.1 移动 head）。
- **分镜：** “让导演拆镜头”的请求**带结构化目标** `{shotCount:3, perShotSec:5, totalSec:15, tolerance}`，而不是让用户在聊天框里手打（O3）。返回提案后先做本地校验，不符合目标时卡片显示“9 镜 39 秒，超出目标 15 秒”，主按钮是「按目标重拆」，「放进分镜」禁用。出场角色由导演结构化输出，再经 V1 交叉校验（O4）。
- **画面 → 视频分开两个阶段**（O13）。阶段条计数各自独立。
- **剪辑声音：** 声音建议（O16 的虚线标签）显示为“建议 · 未生成”，按钮「生成这 5 条声音」。生成后片段显示波形；没有波形不能标“已生成”（4B-U02 既有）。镜头可设为“本镜静音”（`mode:"silent"`），或在有声镜头里框选“有意留白”区间。

## 6. 唯一主下一步：选择算法（R01）

任何再次提交（包括质量不合格后的改条件生成或同参重出）都必须先满足既有预约/账本结算确定、预算与权限允许的条件；质量分类不能绕过 UNKNOWN 核对门。

纯函数 `nextAction(project, tasks) → {stage, actionId, label, enabled, reasons[], fixLinks[]}`，按以下顺序取**第一个**命中项：

1. 当前作品有 `UNKNOWN` 任务 → 「核对 镜头 N 的结果」（禁止自动重提）。
2. 有运行中任务 → primary 变成不可点的进度态「生成中 2/3 · 已等 2 分 10 秒」，次级按钮「停止」。不提供第二个主动作。
3. 有**明确** `FAILED` → 「重试 镜头 N」，且必须同时满足：① 状态是明确失败（不是 UNKNOWN、REMOTE_UNKNOWN、RECONCILIATION_REQUIRED 或预约未结算）；② 预约/账本结算状态已确定；③ 预算和权限允许。点击打开确认对话框（显示同一输入、剩余预算、本次最多增加多少），确认后经**现有任务合同**创建下一个 Attempt；**从不自动重试**。不满足 ①–③ 时，primary 是「核对结果」或「查看原因」，只查询状态，单击绝不重发。【预研】A5/C5 的“疑似瞬时失败同参重试”只在 ①–③ 都满足时适用，不覆盖 UNKNOWN 和预约未结算规则；结果不明先核对。质量失败（采用门不符合）不走本分支，primary 是「改条件后再生成」，次级「同参重出（需确认，提示未改条件时同类问题可能复现）」。
4. 从最早阶段起，第一个 `BLOCKED` 项 → `enabled:false` 的生成/推进动作 + 原因 + `fixLinks`（独立的「去补齐」链接，见 R02）。
5. 第一个被下游**选用**的 `STALE` 项 → 「更新：<项>」（例如「按新外貌重出女孩定妆照」），次级「查看影响」。v1 没有“确认仍适用”：复核后需创建新派生版本；不改写历史 basis、不自动使媒体 VALID，已有真实生成物不能换记为用新输入生成；过期素材必须重做才能导出（§4.1 第 6 条，【用户裁决】③）。
6. 有未采纳的 AI 提案 → 「采纳」（次级「不要」）。
7. 当前最早未完成阶段的推进动作（见 §5 表）。
8. 全部完成 → 「导出」。

界面规则（全局唯一 primary）：

- **任何页面、任何时刻，唯一 primary 始终是 `nextAction`。** 本页其他局部动作（例如在剪辑页“替换片段”、在角色页“补其他角度”、分镜页顶部“生成这一场”而 nextAction 不是它时）一律 secondary 样式，不得使用主色或主按钮尺寸。
- **只在一处呈现：** 当前页 == `nextAction.stage` 时，primary 呈现在页面的上下文位置（例如该镜头卡或该阶段操作区），顶栏只显示一行非按钮文字“下一步：见下方”；当前页 ≠ `nextAction.stage` 时，primary 只呈现在顶栏「下一步：画面 · 补齐镜头 2」（点击跳到该阶段并聚焦），页面内不再出现 primary。两处的 actionId 相同，但永远不会同时以 primary 形式出现。
- 「一键成片」是 secondary，= “自动连续执行 nextAction，直到遇到门（第 4、6 步，或画面采用门、费用确认、声音决定）”。
- **计数作用域：** “恰好 1 个 primary”只在当前活动作用域内计数。没有模态时，作用域是工作区（顶栏 + 页面）；模态打开时，作用域是该模态，模态内恰好 1 个 primary（确认），背景工作区整体设为 `inert`（不可聚焦、不可点击、不进入可访问性树），背景 primary 不可访问、不计数。所以任何时刻可访问的 primary 都恰好 1 个，不存在“全局 1 个 + 模态另算 1 个”。

## 7. 交互规格（反馈、长任务、保存）

### 7.1 点击接受反馈（R03）

区分两个阶段，分别验收：

1. **对话框未 ready（不受理）：** 生成对话框打开后、`ready` 事件之前，确认按钮呈 `aria-disabled="true"`，显示“正在准备…”。这期间的点击、Enter、Space **全部不受理**：不建 task、不排队、不在 ready 后补发。按钮外观明确是不可用态（不是可点外观），解决 O14 那种“看起来能点、点了没反应”（O14 根因仍待复核）。ready 超过 2s 未到，显示「重新打开」。
2. **ready 之后（受理一次）：** ready 之后的第一次激活（点击 / Enter / Space）立即受理：100ms 内出现按下态，0.5s 内出现任务（queued/running；数值来自开发计划 C1 :431 的既有设计，属于**建议，不是现有实现或已批准的断言**）。随后按钮转为「已在生成」进度态。
3. **去重：** 同一 `actionKey = 动作 + 实体 ID + 输入 vid 集合` 在任务未结束时重复激活（双击、连点、顶栏和页面各点一次），都只聚焦已有任务，不新建。

文本输入：外貌、文件名、作品名在失焦或回车时提交；IME 组合输入期间（compositionstart 到 compositionend）不提交、不截断。保存后状态栏回显“已保存：<前 20 字>”，方便人工核对（O8/O9/O19；根因待复核）。

### 7.2 处理中 / 超时 / 失败（R04）

> 总控审查口径：Q1–Q12 中的阈值**不改现有 timeout 和测试断言**。下表除“现有”列外都是建议，待总控排期后另定。

| 任务 | 软提示（建议） | 硬超时 | 超时后（建议） |
|---|---|---|---|
| 文本 AI（编剧、导演） | 60s：“导演还在写，已等 1 分钟” | **现有 4 分钟**（【代码审查报告】U3 `DIRECTOR_SCENE_BUDGET_MS = 240_000`），不加长；原稿的 6 分钟撤回 | 状态“超时，可重试”，保留已收到的部分；晚到的结果显示为“迟到的建议”，必须手动采纳，**不能自动写入**；超时留下的初稿只能查看，未通过镜数/时长/出场校验就不能「放进分镜」（R08） |
| 出图 | 3 分钟 | 沿用现有（10 分钟仅为待定建议） | 转 UNKNOWN（结果未确认）。提供「核对结果」，不自动重提 |
| 视频 | 5 分钟 | 沿用现有（15 分钟仅为待定建议） | 同上 |
| 导出 | 按进度条 | 无进度 2 分钟 | 「停止并保留日志」 |

- 界面超时用语以后端账本为准：后端 `UNKNOWN` 显示“结果未确认”，不显示成“失败”（【代码审查报告】A6：现状界面超时写 `failed`）。
- 进度只显示真实数（完成数/总数、已等时间），不放假进度条。
- 任务详情遵守上位规范的任务队列信息契约（ui-engineering-standards.md:22-36）：当前步骤、输入版本、执行位置、尝试次数、成本分项、最后检查点、下一项恢复动作；`REMOTE_UNKNOWN` 禁止重试，`SUCCEEDED + stale` 只能“查看影响、创建新版任务”，不覆盖旧产物。
- 失败信息：一条白话原因 + 一个动作（C7 既有）。技术细节放在“看详情”。
- 失败后旧版本保留（截图“旧版本都留着，可以随时换回来”是既有行为，保留）。

### 7.3 保存与重开（R05）

- 每次结构变更自动保存；状态栏右侧显示“已保存 · 19:02”或“正在保存”。
- 重开时：从数据派生全部阶段状态（§4.1），不读缓存的勾选状态；运行中任务在重开后统一显示“结果未确认”，等待核对（不自动重提）。
- 作品名：作品菜单「重命名」。改名后作品列表、窗口标题、导出默认文件名**同步**更新（O20 待复核）。
- 导出文件名：导出对话框里是可编辑输入框（【用户裁决】⑤，见 R05）；用户改过的名字必须用于输出，完成提示里回显实际写出的文件名（O19 旧观察仍待复核）。

### R01 统一阶段状态与唯一主下一步 — P0
- 价值：直接解决“下一步点什么不明确”。
- 范围：8 阶段条；`nextAction()` 纯函数；全局唯一 primary 的单处呈现规则（§6）；其余入口降为 secondary。不含视觉重设计（见 §14）。

- 按钮：任何时刻活动作用域内可访问的 primary == 1（模态打开时作用域为模态，背景工作区 `inert`）；primary 的 actionId == `nextAction.actionId`；只出现在顶栏或页面内其中一处。
- 失败恢复：默认 F3。
- 数据失效：每次数据或任务变更后重算；不存储完成标志。
- 验收：① §6 的 8 个分支各 1 个夹具，输出 actionId 符合预期；② GC-15 的 8 个阶段截图，可见 primary 恰好 1 个且 actionId 一致（G10）；③ 当前页 ≠ nextAction.stage 时，primary 只在顶栏，页面内 0 个；④ O12 场景（分镜页、画面 0/3）只出现一个 primary「生成这一场的画面」，“生成画面/生成视频/一键成片/导出成片”都是 secondary。

- 数据失效：采用记录属于该 StillTake 版本；StillTake STALE 时采用记录保留但不再满足门。
- 验收：UI 夹具：不勾完不能采用；任一“不符合”不能采用；采用记录存盘并可重开；L5 中 G9 人工通过。

### R14 时长真实传递与测量 — P0
- 价值：成片时长与计划一致（O3、O18）。
- 范围：Shot.timing → 视频请求参数 → 生成后 ffprobe 测 `measuredDurationSec` → 时间线 → 导出后再测。各处**只显示实测秒数**（例如“5.3 秒”），不设容差、不出偏差提示、不作通过/失败断言（【用户裁决】①）。请求侧可选秒数与界面一致（【代码审查报告】A8：现状界面 2/3/4/5/6/10、请求夹到 1–15）。
- 前置：默认 F1；V5。
- 输入→输出：timing → 请求参数；媒体文件 → 测量值。
- 按钮：不因时长差异增加任何阻断或 primary；默认 F2。
- 失败恢复：探测失败显示“没测出时长”，不当作通过。
- 数据失效：§8 Shot.timing 行。

- Owner：BE（探测，如果在媒体模块）/ FE（显示）。

### R15 声音意图与导出前显式声音决定 — P0
- 价值：避免把静音片当成品交付（O16–O18），同时尊重有意静默和有意留白。现状来源见 H3（【代码审查报告】A1–A4、A9、U5），需在新候选上验证。
- 范围：SoundIntent（§4.2：silent 只代表整镜明确无声；sound 下说话方式与环境/音效/配乐可同时存在；无台词 ≠ 静音；只有环境/配乐时不需要声线；参考人声授权由用户声明、不推断（见Q13建议）；有意留白区间）；条目三态（suggested / accepted / rendered）；剪辑声音阶段完成条件；导出前声音区显示 G7a/G7b 状态和 G7c 诊断标记；声音未兑现时 primary「先做声音」，次级「本片静音导出」；静音导出写一条静音音轨，导出记录 `audioDecision=SILENT_BY_USER`；有 AAC 轨仍不代表有声音（【用户裁决】②）。

- 验收：G7a–G7e、G8、GX2；−91 dB 夹具时导出对话框必须出现二选一，且绝不显示“都做好了”；有意留白区间内的静音不产生标记；L5 中 G7d 人工试听通过。

### R16 导出检查与结果真实性 — P0
- 价值：导出提示说的就是文件里真实的东西。
- 范围：导出前列出：未生成镜头、待更新项（有则阻断，【用户裁决】③）、声音决定与诊断标记、黑屏/定格/静音（既有 qc 规则）；各镜实测时长只显示；导出后探测输出文件并回显“实际：15.0 秒 · 音轨：有（逐镜诊断见详情）· 1920×1080 · 文件名”。
- 前置：默认 F1；R14、R15。
- 输入→输出：Timeline + audioDecision → 文件 + 导出记录（含 basis、qc、audioDecision；文件名为用户输入值）。
- 按钮：有未处理项 → primary「去修 N 处」；全部处理 → primary「导出」。
- 失败恢复：导出失败或无进度 2 分钟 → 「停止并保留日志」；不覆盖上次成功文件。
- 数据失效：导出后时间线或其上游再变 → 该导出记录标 STALE（“导出后又改过”）。

- Owner：BE（探测）/ FE（对话框）。

### R17 公司式分工呈现 — P1

- 数据失效：不涉及。

- Owner：FE；PX 文案。

### R18 一键成片 = 同一阶段链的自动推进 — P1
- 价值：想省事的用户也走同一条专业链，不另开普通模式。

- 前置：R01、R13、R15。

- Owner：FE；BE 只有在流水线编排位于 Python 时才参与（4A-B01 既有）。

### 14.1 布局与密度（基准 1440×900，最小 980×680；附加 1280×800、1920×1080）
- UI-L1 在 100% 文本大小和系统缩放下，≥980×680 时页面本身不出现整页滚动条（沿用硬规则 2）；只有列表、聊天、属性面板在区内滚动。**可达性优先：** 文本放大到 200% 或系统缩放后，面板可以重排、折叠为抽屉或允许整页滚动，任何必要内容和操作都不得被裁切或隐藏（WCAG 1.4.4、1.4.10）；“不允许整页滚动”不能作为裁切内容的理由。验收：4 种分辨率 × 8 阶段截图 + 200% 文本缩放下 8 阶段截图，检查无裁切。
- UI-L2 间距刻度只用 4px 倍数：4 / 8 / 12 / 16 / 24 / 32（token）。面板内边距 12，分组间距 16，卡片间距 8。验收：样式审查中，非刻度值 = 0（图标内部除外）。
- UI-L3 字号用相对单位（rem）定义：正文 13px，次要信息 12px，最小 12px；面板标题 14px/600，页标题 16px/600；行高 ≥1.4。时间码默认 12px 等宽；若采用 11px 例外，必须同样用 rem 定义、随文本缩放放大，并经总控确认（上位规范最小正文 12px）。中文不得被截断，放不下就省略号加悬停/聚焦可见全文（沿用硬规则 3）。
- UI-L4 桌面可点击目标 ≥24×24 CSS px（WCAG 2.2 SC 2.5.8 AA 最低值）；触屏 ≥44×44（上位规范 :44）；主按钮高度 32px，工具栏图标按钮 28px。
- UI-L5 阶段条：8 段等高（32px），每段“序号 + 名称 + 状态徽标/计数 + 岗位”，当前段用品牌色，完成段打勾（只有完成条件满足时才打勾，沿用 3J-U22）。宽度不足时名称收为序号 + 图标，并保留可访问名称。
- UI-L6 右侧属性栏宽度 320–360px；默认展开“必填/有问题”的分组，“高级”默认收起（渐进披露）。

### 14.2 主次与状态
- UI-S1 活动作用域内可访问的 primary 恰好 1 个：无模态时在工作区内，且是 nextAction；模态打开时在模态内（确认），背景工作区 `inert`、背景 primary 不可访问；危险动作用 secondary 加红字，不用品牌色。
- UI-S2 状态色：只用于状态，不用于装饰；每种状态都同时有**文字或图标**，不能只靠颜色区分（WCAG 1.4.1）。文本对比度 ≥4.5:1，图标/边框/焦点环 ≥3:1（WCAG 1.4.3 / 1.4.11）。
- UI-S3 不可用按钮旁边直接显示一行原因（12px 次要色），旁边是独立可用的「去补齐」链接；不可用按钮本身不导航（R02）；不能只靠悬停提示。
- UI-S4 STALE 资产：缩略图左上角显示“待更新”徽标，图像 60% 不透明，不能隐藏或删除。UNKNOWN：显示“结果未确认”加「核对」。

### 14.3 键盘、焦点、播报
- UI-K1 全部操作可只用键盘完成：Tab 顺序与视觉顺序一致；阶段条用左右箭头切换（roving tabindex）。
- UI-K2 焦点环：2px 实线、偏移 2px、对比 ≥3:1；不得被遮挡（WCAG 2.4.7 / 2.4.11）。
- UI-K3 对话框打开时焦点进入第一个可操作控件，Esc 关闭，关闭后焦点回到触发按钮；对话框 ready 前确认按钮为 `aria-disabled` 且不受理（R03 第 1 段）。
- UI-K4 状态播报：任务开始、完成、失败，以及“已保存”，通过 `role="status"`（礼貌）播报；阻断错误用 `role="alert"`，一次只播一条（WCAG 4.1.3）。
- UI-K5 `aria-disabled` 按钮：可聚焦，`aria-describedby` 指向可见原因；pointer、Enter、Space 均被拦截且不导航。「去补齐」链接激活后，焦点落在目标字段，字段的说明文字用 `aria-describedby` 关联原因。

### 14.4 异步反馈（与 R03/R04 一致）
- UI-A1（建议值，非现有、未批准）ready 后首次激活：100ms 内出现按下态；0.5s 内出现任务或对话框；超过 1s 的操作显示进度（真实计数和已等时间）。
- UI-A2 运行中按钮显示“生成中 2/3 · 已等 2:10”，宽度不跳动（预留宽度或用等宽数字）。
- UI-A3 状态栏消息 5 秒淡出（既有），错误不自动消失，需要手动关闭或修复后消失；尊重 `prefers-reduced-motion`。

### 14.5 React 状态与幂等（实现检查项）
- UI-R1 阶段状态、`nextAction`、有效性都在渲染时从项目数据**派生**（纯函数 + memo），不在 state 里另存一份“已完成”标志。审查时搜索重复的完成态 state，应为 0。
- UI-R2 生成动作以 `actionKey = 动作 + 实体 ID + 输入 vid 集合` 去重；挂起中重复触发会返回同一个 task。StrictMode 双调用 effect 不产生两次提交（effect 只订阅，提交只在事件处理函数里发生）。
- UI-R3 异步返回时比对“发起时的输入 vid”与当前 head，不一致就作为“迟到结果”，不写入（R04）。
- UI-R4 受控输入支持 IME：组合期间不提交、不截断（R03）。
