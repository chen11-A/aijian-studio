## Persistence chain common to all rows

`film/project.ts:writeFilm` serializes whole project. `upgradeFilm` spreads project, scene, character and shot records, normalizes operational fields; it does not whitelist away custom plan metadata. Desktop `film-library.ts:prepareProject/materializeMedia/withoutSessionUrls/writeProjectNow` recursively retains non-media fields and serializes whole object; temporary media URLs are deliberately treated separately. Thus fields absent after parsing/application cannot be restored by save/hydrate. No additional save-layer dropping of the already projected fields below was found.

## Implemented follow-up (same work session)

The gaps above describe the read-only baseline. B08 now adds typed `WriterPlan`/`SceneWriterPlan`/`WriterCharacterPlan` and `SceneDirectorDeclaration`, not an opaque raw response:

- Writer root title/logline/hook/cliffhanger/count and same-response characters/locations -> `FilmProject.writerPlan`; raw first_paragraph/brief -> `FilmCharacter.writerPlan.firstParagraph/brief`; declared actor traits actually apply to normalized `FilmCharacter.gender/ageBand` and matching voices, subject to existing user locks. Existing portraits and reference images remain intact, actor identity remains protected when portraits exist, absent characters are untouched.
- Scene interior is boolean (as fixtures/schema specify), remaining context/proposed text/dialogue/beats/estimate -> `FilmScene.writerPlan`. `writerSceneContext` supplies the proposal as guidance only while the source snapshot is current; actual source/coverage remain authoritative. It does not treat estimated seconds or declared dialogue count as measured results.
- `planWriterDraft` returns optional `writerPlan`; `prepareWriterTransaction(base, scenes, writerPlan?)` carries before/after characters, locations and optional plan presence, in the same atomic CAS/undo as scene replacement. Root connected UI confirmation to this third argument. Automatic writer/script and legacy storyboard apply the same reply immediately within their existing stale-request guards; no additional cast request is used to repair lost fields.
- Director segment `sourceNo` and `declaredSeconds` preserve source numbering/duration without modifying operational numbering or duration. Each segment retains typed `sceneDeclaration` (source scene ID/title/rhythm/declared total seconds, resolved scene ID, match status). Matching scene rhythm enters generation guidance; total estimate never sets duration. Merge retains all original segment declarations; JSON/hydrate retains them.
- Correction to the baseline matrix: existing `matchDirectorScene` includes positional/single-scene fallbacks, not strict rejection for every unknown ID. New declaration consumption is stricter: exact ID or unique matching title/place is `matched`; otherwise `needs_review`, retained but not put into generation prompts. Existing shot-target matching behavior is not expanded by B08.
