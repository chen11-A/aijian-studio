# AIVORA 开发线收拢与 Windows 首发计划

## 基线与范围

- 开发汇合线：`aivora/dev`。这次接入 `973e746` 集成基线和四步界面、受控文本来源抽取两笔修复。提前整合是为了统一后续开发，不代表发布验收通过。
- 保留现有生产工作台：「剧本 → 角色与场景 → 分镜 → 剪辑」。保留已有工程、定稿版本、恢复与导出。高级控制折叠，不改变普通和专业操作的质量标准。
- 模型中心沿用现有凭证库和预算、授权检查。本轮只接通受控文本来源抽取；生图、视频和配音的新适配器另做，不把配置校验冒充联通。保留导出 −16 LUFS。
- 不用旧补丁包，不动 `main`、旧标签或发布，不强推、不在本次清理中删除分支。

## 顺序与验收

1. **冻结开发基线。** 核对开发线包含 `973e746` 和两笔修复，记录开发线的实际 SHA。该集成基线的既有 CI 为 20/20，但不能算这批新提交的 CI。新改动定向通过前端 209 项、后端 62 项，类型、构建、Lint、格式和接口契约通过。本地全量桌面 3 项媒体超时，隔离重跑 3 项过，不能把全量判绿；全量 Python 和网页、1280×800 布局仍需确认。
2. **先出 Windows 候选，不先发版。** 按同一提交验证 CI，再构建非发布安装包。用中文和空格路径跑《晚照书店》：全新安装 → 打开旧工程或导入 → 选版与配音 → 导出并试听 MP4 → 覆盖重装读回项目和设置。记录安装包 SHA-256；这轮不调用未经批准的付费服务。
3. **只接入确有用途的新能力。** 优先修复 CI 和 1280×800 布局问题。继续沿用已支持的模型通道；按生图、视频、配音逐个接入并验证取消、预算拒绝、重试不重复派发、失败不覆盖旧版本。大规模 UI 重写、数据库迁移和后台目录搬迁不阻断首发。
4. **分支清理只出候选清单。** 先核对分支尖端是否已经进入最新开发线，再查开放 PR、未合补丁、测试记录以及构建引用。区分已包含、内容等价待核、仍有独有改动三类。各类保留完整 SHA 和用途；删除前另行确认清单。

既有细项与验收证据见[开发计划](开发计划.md)、[当前进度](当前进度.md)和[分支清理准备](分支清理准备.md)。
