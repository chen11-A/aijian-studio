## 0. 分工和规则

## 分工（2026-11-04 定稿，替换以前所有说法）

- **GPT**：后端、业务逻辑、接口、测试、打包；**所有合并和打 tag 只由 GPT 做**。
- **Claude**：全部界面，加上内置智能体提示词和界面文案。
- **Grok 助手**：审核、用用户的真实 SuperGrok 会员装包实测、写问题单（编号、现象、文件:行、负责人、验收标准）、最后的完整审核、交付 Windows 向导安装包和 SHA256。**Grok 不改代码。**
- **交叉审核**：Claude 看 GPT 的后端改动；GPT 按接口核对 Claude 的界面接线；Grok 最后装包实测把关。
- 任何人都不合并 main、不强推；没有用户明确同意不删分支。工作线是 `aivora/dev`（见 分支说明.md）。

交付方式：Claude 在共享文件夹 `linux\AIVORA\` 放 zip 或补丁（附 SHA-256、文件清单、测试结果），或推到 `claude/work`；GPT 在 `gpt/work` 上做，每阶段从 `aivora/dev` 打 tag 发 Linux 包和 Windows 安装包并报两个 SHA256；Grok 出审核报告和问题单（交 GPT 放进 `docs/aivora/问题单/`）。

硬规则（每项验收都默认包含）：

1. 只用 Grok 会员，不接任何按次付费的服务。
2. 不整页滚动：窗口 1280×800 和 1920×1080 下，页面本身不能出现滚动条；只有长列表、聊天记录、属性面板在自己区域内滚动。
3. 不重叠、不截字（文字放不下就换行或省略号加悬停提示，不能被切掉一半）。
4. 界面不出现术语（LUFS、dB、prompt、token、JSON、shot id 这类）。专业数值只能放在“细调/高级”里。
5. 不放假数据：没有的东西显示空状态，不放示例色块、不放虚构作品。
6. 界面参考剪映专业版、Premiere、达芬奇：专业但不乱，每屏只有一个主按钮。
7. 口型同步只做“画面里有人开口、脸是特写或中近景”的镜头；旁白和画外音一律不做；失败就保留原视频，在任务中心标“口型未对上，可重试”。
8. 最终交付：带向导的 Windows 安装包（能选安装位置、可选桌面快捷方式、装完可直接启动）。

## 2. 前后端接口约定（两边照这个并行写）

所有数据都存在作品的 `project.json` 里，或通过 `window.aijian.*` 事件推给界面。字段名用英文，界面显示中文。

**C1 任务进度（定妆照、生成画面、生成视频、配音、口型、导出）**

```ts
// 与 Claude 的 next/TaskCenter.tsx 的 TaskItem 一致
type TaskItem = {
  id: string; // 例：scene-2-shot-6-take-1
  shotId?: string; // 界面显示成「第 2 场第 6 个镜头」
  title?: string; // 没有镜头的任务，例：「林晚的定妆照 · 侧面」
  version?: string; // 「A 版」
  kind: "video" | "image" | "voice" | "lipsync" | "export"; // lipsync、export 是新增，GPT 补
  status: "queued" | "running" | "uncertain" | "requeued" | "failed" | "done";
  attempt: number;
  reason?: string; // 白话原因，例：「Grok 拒绝了这张图」
  suggestion?: string;
  waitedSeconds?: number;
};
type BatchProgress = {
  batchId: string;
  label: string;
  done: number;
  total: number;
  failed: number;
  running: boolean;
};
// 事件：window.aijian.onTask(cb: (tasks: TaskItem[], batches: BatchProgress[]) => void)
```

规则：点了按钮 **0.5 秒内**必须有一条 queued 或 running 的任务出现；任何任务最终都要落到 done 或 failed，不能一直转圈。

**C2 导出前检查报告**：沿用 GPT 的 `packages/aivora-qc`（7c0eea5）schemaVersion 1，字段见 Claude 的 `next/qcReport.ts`：`issues[{id,severity:"warn"|"block",time,timeLabel,end,type,message,suggestion,action,detail,scope?}]`。GPT 另外提供 `ShotSpan[] = {id,start,end}`（每个镜头在成片里的起止秒），界面用它把时间换成“第几场第几个镜头”。

**C3 声音四层**（与 `next/volume.ts` 一致）：每场存 `sound = { mood, master: 0–100, lanes: {dialogue,ambience,sfx,score}: 0–100, duckMusic: boolean }`。默认 100/50/70/20，对应 0/−6/−3/−14 dB（换算公式 20×log10(音量/100)）。界面只显示 0–100 的滑块，换算由 GPT 做。

**C4 多选一（版本）**：GPT 把 `FilmTake` 转成 `TakeOption = {id,label:"A 版",status:"ready"|"generating"|"failed",verdict?:"可用"|"建议重做"|"必须重做",notes?,imageUrl?,statusText?}`，并给 `aiChoiceId`（审片选的）和 `selectedId`（用户选的）。新手一键成片：自动采用 AI 选的，标“AI 选的，可换”。

**C5 字幕样式 id（统一）**：最终只用这 4 个 id：

| id       | 界面名   | GPT 要做                                                                                        | Claude 要做               |
| -------- | -------- | ----------------------------------------------------------------------------------------------- | ------------------------- |
| `white`  | 清楚白字 | 不变                                                                                            | 把 `clear` 改名为 `white` |
| `bar`    | 底条字幕 | 不变                                                                                            | `band` → `bar`            |
| `yellow` | 醒目黄字 | 不变                                                                                            | `bold` → `yellow`         |
| `film`   | 电影字幕 | 在 `aivora-media/subtitles.mjs:1` 的 STYLES 里用 `film`（小一号字、柔和阴影）**替换** `variety` | 保留 `film`               |

**C6 封面**：`CoverEditor` 的 `{title, subtitle, aiMark, backgroundUrl}` → GPT 调 `createCovers({title, aiLabel: aiMark, time})`。AI 标识默认开，可关，关时提示一次“部分平台要求标注 AI 生成”。

**C7 提示消息**：后端和逻辑层不再直接给界面写长句。统一返回 `{ code: string, text: string, detail?: string }`，例：`STALL_RETRYING`（“导演一分钟没回话，正在自动重试”）、`EXPORT_DONE_DRAFT`。界面按 `docs/design/copy-zh.md` 把 code 换成最终文案，text 只作兜底。GPT 在 INTEGRATION 里列出所有 code。

**C8 人物属性**：`FilmCharacter.gender: "男" | "女" | ""`，`ageBand: "儿童" | "少年" | "青年" | "中年" | "老年" | ""`，必须是普通字段（能存进 project.json）。界面在角色页显示两个下拉框，可改；改了以后 GPT 重新挑声音。

**C9 原文覆盖检查**：导演写完每场后，GPT 给出 `coverage = { sceneId, ok: boolean, lastLine: string, missingLines: string[], missingTail: string | null }`。界面在分镜页场次标题旁显示“这一场结尾还没拍到：……”，并给“补上结尾”按钮（调用 GPT 提供的 `fixCoverage(sceneId)`）。

**C10 未分配的动作**：动作指导写的、对不上任何镜头的动作，存到 `film.unassignedBeats = [{sceneId, text}]`，界面在分镜页显示“有 N 个动作没对上镜头”，可以拖到某个镜头上。绝不按序号硬塞。

**C11 口型状态**：每个版本 `take.lipSync = "none" | "pending" | "done" | "failed"`，加 `lipSyncReason`。只有 `lipSyncEligible(shot) = 有人在画面里说话 && 景别是特写/近景/中近景/中景 && 不是旁白/画外音` 时才会是非 none。失败时任务中心显示“口型未对上，可重试”。

**C12 一键成片进度**（4a）：`pipeline = { steps: [{id:"writer"|"art"|"portraits"|"director"|"action"|"performance"|"prompter"|"stills"|"review"|"video", label, status, done, total}], current }`。界面显示一条步骤条，不显示智能体内部文字。

**C13 场记提醒**（4a）：每个镜头 `continuity: [{kind:"missing_look"|"prop"|"gaze"|"axis"|"cut", text}]`，界面在分镜卡角上显示小黄点，点开看白话说明。

## 3. 交接顺序（每个阶段都按这个走）

3j 界面已按 `claude/aivora-ui` 的 Git 提交交付：每笔只做一个编号，格式“类型(范围): 中文说明 [编号]”，作者 chen11-A；Claude 提交保留协作署名。无法推送时用 `git format-patch` 导出并附 SHA-256，不等待 ZIP 才能整合。整合后任务书只维护 `docs/aivora/`，后续阶段分支依《分支说明》从现有 `aivora/dev` 开。接口已有/仅类型的状态以 `next/INTEGRATION.md` 为准。

1. Claude 交界面（zip/补丁或 `claude/work`），附 SHA-256 和文件清单。GPT 交后端（`gpt/work`）。
2. 交叉审核：GPT 按接口核对 Claude 的接线；Claude 看 GPT 的后端改动。各写一段意见。
3. GPT 把两边合进 `aivora/dev`（`git merge --no-ff`，Claude 的 zip 单独一个提交并写 SHA），跑全部检查，打 tag，发 Linux 包和 Windows 安装包，报两个 SHA256 和按编号的“已修/未修”表。

## 4. 阶段 3j：把核心流程修稳（当前阶段）

目标：用 2000 字测试小说，从导入到出第一段视频，不丢原文、不配错声、不卡住、界面不乱。

### 4.1 后端（GPT）

**3J-B01 每场结尾被截掉（P0）**

- 现象：第 1 场镜头停在「但我得还」，后面的「你来晚了」、照片、刹车声都没有镜头；第 2 场停在刀划过去，后面周烈逃跑、警笛都没有。
- 原因/位置：`film/project.ts:546-549` 的 `shotBudget` 算出上限（每 50 字 1 镜、最多 16），`:685-686` 直接 `varied.slice(0, budget)` 把超出的镜头丢掉，丢的正好是结尾。GPT 审计 P1-05 还指出：上限只在每个场景块里各算一次（`:571-583`），同一场两个块会变成 32 镜并出现 16 个重复 id（`:628-632` 每块序号从头开始）；短于 80 字的场完全不限（`:546-549`）。
- 负责人：GPT后端
- 要做什么：
  1. 把“目标镜头数”（每 40–60 字 1 镜，每场最多 16）写进导演的请求里，让导演**合并相邻节拍**，而不是写多了再砍。
  2. 导演回来超过上限时，**不丢**：先按场次合并所有块、重新编唯一 id，再合并相邻的同人物同地点镜头直到不超上限；合并后的镜头保留两边的台词。
  3. 每场写完做“原文覆盖检查”（接口 C9）：该场最后一句台词和最后一句叙述，都必须出现在某个镜头里；没出现就自动再请导演“只补结尾”一次，仍失败就把 `coverage.ok=false` 交给界面提示，不能静默。
- 验收：用测试小说跑三场导演，`project.json` 里第 1 场能找到「你来晚了」和刹车声的镜头，第 2 场能找到周烈逃跑和警笛；每场镜头 ≤16；所有镜头 id 不重复。加回归测试：用 GPT 审计里的“重复块”和“短场 20 镜”两个反例。
- 依赖：无。
