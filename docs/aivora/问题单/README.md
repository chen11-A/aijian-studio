# 问题单格式

Grok 助手实测或审核发现问题后写问题单，交给 GPT 提交到这个文件夹。Grok 不改代码。

- 文件名：`<编号>-<一句话>.md`，例如 `T-3J-001-第一场结尾没有镜头.md`。
- 编号：`T-<阶段>-<三位序号>`，例如 T-3J-001、T-4A-012。修复提交的说明里写上这个编号。

## 每张问题单必须写

```
编号：T-3J-001
严重程度：P0（不能用）/ P1（主要流程出错）/ P2（小问题）
负责人：GPT 或 Claude（只写一个；两边都要改就拆成两张）
版本：tag 或提交号，安装包 SHA256
现象：用户看到什么（简单中文，附截图文件名）
复现步骤：1. … 2. … 3. …
位置：文件:行（能定位就写，不确定写“待负责人定位”）
验收标准：怎样算修好（能实测的说法，例如“第 1 场有「你来晚了」的镜头”）
状态：待修 / 已修待测 / 已通过 / 不修（写原因）
```

## 流程

1. Grok 写 → 2. GPT 提交到 `docs/aivora/问题单/` → 3. 负责人修，提交说明带编号 → 4. GPT 合进 `aivora/dev`、发新版 → 5. Grok 实测，把状态改成“已通过”或写明还差什么。
