# AIVORA 界面设计稿

7 个界面的静态 HTML 原型、一份界面说明、两份走查意见和全部截图。只是设计稿，没有改软件代码，也没有接到软件里。这是第二版。

## 怎么看

用浏览器直接打开 `index.html`，里面有每个界面的截图和各个状态的链接。也可以直接打开某个原型，在网址后面加 `?state=状态名` 切换状态，例如 `01-home.html?state=confirm`。不需要联网，也不需要安装任何东西。

## 第二版改了什么

- 首页去掉了「成片 / 草稿」和「画风」两个选项，只留画面方向；去掉了「雨夜巷战」示例入口。
- 任务中心每种状态只突出一个按钮：关闭后重新打开是「查一下，再接着做」，查完是「接着做 47 段」。顶栏的「导出成片」在所有界面都是普通按钮。
- 导出前检查只留两种按钮：每条问题一个「去修」，右下角一个「直接导出」。
- 声音面板默认只显示这一场的配乐情绪和一个 0 到 100 的音量；台词、环境声、音效、配乐四层音量和时间线放进「细调」；界面上不再写分贝。
- 正文里的镜头写成「第 2 场第 17 个镜头」，内部编号和时间只做后面的小字。
- 原型里的数据换成新的测试小说（三场：雨夜旧书店、码头仓库、医院走廊），参考图按每个镜头最多 13 张加 1 张首帧。

## 设计依据

- 只保留专业工作区：所有界面用同一个外壳，顶栏是作品、剧本 · 角色与场景 · 分镜 · 剪辑和导出成片，和 `docs/SPEC.md` 一致。新手首页是这个外壳在没有作品时的样子，不是另一个「普通模式」。
- 参考剪映、Premiere、DaVinci：左边列表，中间监看和时间线，右边属性；按钮按区域分组，每一屏只有一个主按钮，不挤成一排。
- 一屏放下：登录、设置、表单、弹窗和详情栏都不滚动，只有长列表在自己的区域里滚动，整页不滚动。
- 简单中文，不用术语；不放假数据。界面上的数字都能说出来源；不知道的（剩余额度、要等多久）就不显示。
- 只用用户自己的 Grok 会员：会用额度的按钮写清用几张图或几段视频；意外关闭后先查清楚，再决定要不要重发。
- 现有决定照旧：草稿和成片用不同的视频模型（首页默认成片，草稿在作品设置里）、每镜默认 2 个版本、自动重试最多 2 轮、视频本身不出声、界面不写响度单位（`docs/decisions/2026-10-24-v030-product.md`）。

## 原型里的数据

人物、台词、场次、镜头、时长和数量都来自测试小说《雨夜旧书店》（`packages/aivora-prompts/fixtures/test-novel-2000.txt`）和 `packages/aivora-prompts/` 的提示词示例：3 场，65 个镜头，正片 4 分 31 秒，加 3 秒片头共 4 分 34 秒，33 句台词；每镜 2 个版本共 130 段视频。声音面板用声音设计示例 2 的第 2 场，一选多用审片示例 2 的第 2 场第 17 个镜头。原型里没有真实生成的画面，画面位置放的是表示光线的色块。

## 检查

```bash
AIVORA_CHROMIUM=/path/to/chrome node docs/design/tools/check-layout.mjs --shots
```

脚本用根目录开发依赖里的 `playwright-core` 打开每个原型的每个状态，分别在 1280×800 和 1920×1080 下检查：页面不整体滚动，元素不超出窗口，内容不被意外裁掉（只允许写了省略号的单行文字和写明行数的多行文字），文字和按钮互相不重叠，字号不小于 12 像素，每个按钮都有名字，控制台没有报错。`playwright-core` 不自带浏览器，要用 `AIVORA_CHROMIUM` 指向本机的 Chromium 或 Chrome；仓库没装依赖时，可以用 `AIVORA_PLAYWRIGHT` 指向别处的 `playwright-core` 文件夹。加 `--shots` 时同时重新生成 `screenshots/`。

## 没有覆盖的

- 原型是静态的：拖放、播放、按帧走、浏览器登录、「去修」跳到剪辑后的样子和真实等待时间都没有做出来，走查也就没走到这些。
- 走查是按两类用户的视角写的专家走查，不是真人测试。正式验收按 `docs/development/ui-engineering-standards.md`，要找真实用户完成任务并记录。
- 剧本、角色与场景、分镜这几个现有界面没有重画；场记检查出的连贯问题还没有单独的界面（见专业剪辑师走查 P11）。
