# 走查意见：第一次用的小白

这是按「第一次用的人」的视角，对着 `docs/design/` 的原型逐屏走一遍写下的意见，属于专家走查，不是真人测试。原型只有静态画面，所以等待时间、真实生成质量、浏览器登录这些体验没有走到。正式验收仍要按 `docs/development/ui-engineering-standards.md` 的要求，找真实用户完成同样的任务并记录。

## 这个人和这次的任务

- 平时刷短视频，会用微信，会把文件拖来拖去，没用过剪辑软件，也没用过 AI 生成视频。
- 有 Grok 会员，但不知道会员额度怎么算。
- 手里有一篇 1500 多字的小说《雨夜旧书店》（txt）。
- 任务：做出第一部能发出去的短片。不想研究参数。

## 问题清单

| 编号 | 严重 | 界面           | 问题                                                                                                     | 建议                                                                                                                                                                                                  |
| ---- | ---- | -------------- | -------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| N1   | 高   | 首页、任务中心 | 不知道要等多久。为了不放假数据，准备和生成都没有时间估计，第一次用的人容易以为卡住了，或者不敢离开电脑。 | 显示真实的「已经用了多久」和「做好几段、一共几段」；全部做完时发系统通知；首页保留一个「回到进度」的入口。不显示猜出来的剩余时间。                                                                    |
| N2   | 高   | 开始生成前     | 额度焦虑：78 段视频看不出多少，也不知道够不够。                                                          | 在弹窗里写「会员用量可以在 Grok 网站上看」并给链接（要先确认 Grok 有这个页面）；版本数旁边直接写换算，例如「选 1 个：视频 39 段」。第一次的默认版本数是否改成 1，需要产品确认（现在作品设置默认 2）。 |

## 要点

1. 点击次数达标：拖入小说时，已登录 2 次、没登录 3 次就能做出成片；最坏情况（没登录、用选择文件）正好 5 次。
2. 第一次用的人最大的不安是「要等多久」和「额度够不够」。这两件都不能编数字，只能用真实进度、做完通知和 Grok 官方用量页来缓解。
3. 会花额度的按钮都写了用几张、几段，意外关闭后先查再重发，这两点让人敢点。
4. 要减少「两个按钮不知道点哪个」的地方：恢复横幅、导出前检查都应该只有一个明确的下一步。
5. 和专业剪辑师的分歧（分贝、时间码精度、默认采用推荐版本）用「默认简单、高级里给全」的方式处理，不分成两套界面。
