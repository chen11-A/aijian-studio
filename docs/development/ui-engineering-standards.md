# Aijian Studio UI 工程规范

目标是让电影生产流程在长时间创作中仍然清晰、快速、可恢复。界面评价同时看视觉品质和任务完成效率；装饰不能牺牲信息密度、可访问性或状态可见性。

## 设计语言

- 使用统一 design token 表达颜色、间距、圆角、阴影、字号和动画；业务组件不得散落新的魔法值。
- 深色工作台以中性石墨背景承载素材，单一紫色品牌色只用于主动作、当前步骤和焦点，不把所有信息都做成强调色。
- 中文正文优先系统无衬线字体，影片标题和章节可有限使用衬线字体；最小正文 12px，操作文字不得依赖极细字重。
- 采用 4px 基础节奏与 8px 主间距。对齐、层级和留白先于渐变、阴影和动画。
- 图标必须有文字或可访问名称；不使用仅靠颜色表达成功、失败、警告或选中。

## 创作便利性

- 主流程始终显示“当前步骤、输入版本、任务状态、预计成本、下一步动作”。长任务必须可离开页面并在任务队列恢复查看。
- 高频动作在一到两次操作内完成；破坏性动作显示具体影响范围，支持撤销时优先撤销而不是确认弹窗。
- AI 结果先作为草稿，清楚区分“建议、已接受、人工修改、已失效”；不能用视觉效果掩盖审批状态。
- 空状态说明用户为什么来到这里、需要什么输入、完成后会发生什么；错误状态提供可执行恢复动作。
- 专业参数采用渐进披露：默认展示导演/剪辑可理解的意图，高级区再展示模型、seed、采样和供应商字段。
- 任务队列不显示模糊的“处理中”：每项至少显示当前制作步骤、输入版本、执行位置、尝试次数、预计或实际成本、最后检查点和下一项恢复动作。
- 恢复动作使用电影团队能理解的语言（如“继续生成”“核对供应商任务”“重新导出”），技术状态码作为次级信息保留，不能代替可操作说明。

### 任务队列信息契约

任务详情必须显示：工作流/节点、负责岗位、上游 Gate、精确 `artifact_id/version_id/hash`、accepted/stale 状态、阻断的下游、执行位置、Attempt 编号、检查点时间、等待原因和合法动作。成本分开显示 `reserved/accrued/billed`、币种、预算上限和“再试一次最多增加多少”，不能只显示一个估算总数。

| 技术状态                    | 主文案                   | 可用主动作             | 明确禁用                   |
| --------------------------- | ------------------------ | ---------------------- | -------------------------- |
| `RUNNING/WAITING_REMOTE`    | 正在执行 / 等待供应商    | 查看详情、请求取消     | 重复提交                   |
| `REMOTE_UNKNOWN`            | 供应商是否受理尚不明确   | 查看证据               | 重试、重新提交、标记已取消 |
| `RECONCILIATION_REQUIRED`   | 需要核对供应商任务       | 开始核对、登记核对结果 | 自动恢复提交               |
| `FAILED + SAFE_LOCAL_RETRY` | 本地步骤失败，可安全重试 | 重试                   | 隐藏原 Attempt             |
| `NOT_SUBMITTED`             | 供应商已确认未受理       | 创建下一 Attempt       | 复用旧 Attempt 改写历史    |
| `SUCCEEDED + stale`         | 已完成，但输入版本已变化 | 查看影响、创建新版任务 | 覆盖旧产物                 |

## 响应式与可访问性

- 桌面创作基准为 1440×900，最小支持 980×680；Web 审片同时验证 768px 与 390px 宽度。
- 所有交互支持键盘；焦点顺序与视觉顺序一致，焦点环清楚且不被移除。
- 语义标题不跳级，表单有 label，动态任务/连接状态使用合适的 live region。
- 正文和控件满足 WCAG AA 对比度；支持 `prefers-reduced-motion`，关键动作不依赖动画完成。
- 触屏目标建议不小于 44×44px；窄屏不隐藏审批结论、错误和成本等关键信息。

## 电影岗位专业 Gate

分镜导演界面必须同时看到 Coverage 用途、画幅安全区、镜头/表演/运动意图、连续性 Before/After、输入剧本与视觉资产版本，以及生成能力损失；在 9:16 画幅中可以不打开高级参数完成一次镜头计划和 G6A 审阅。

剪辑界面必须以有理数时间基准显示帧准确时间码，明确 A/V 同步、轨道 lock/mute/solo、离线媒体与代理回连、剪辑手柄、Picture Lock 影响和导出/渲染检查点。验收由真实剪辑师完成 trim/reorder/replace、补拍替换和崩溃后继续导出，不能只凭组件截图判定通过。

编剧界面必须覆盖 AdaptationLedger、Scene/Beat/Dialogue/Action、来源与 invented 标记、版本 diff、修改说明、审阅意见处置和 G3/G4 送审；故事圣经只读查看器不能冒充完整编剧工作台。

## UI 交付 Gate

每个界面切片必须提供：

1. 加载、正常、空、错误、禁用五类适用状态。
2. 单元/交互测试，以及 1440×900 和 390×844 的真实浏览器截图。
3. 零控制台错误与警告；关键请求状态码和响应契约正确。
4. DOM 可访问性快照：标题层级、地标、按钮名称和 live region 正确。
5. 键盘走查和 reduced-motion 检查。
6. 对“完成一个具体电影任务需要几步”的简短验收记录。
7. 对应岗位的真实任务记录：编剧、导演、剪辑 Gate 分别验收，不用同一份通用 UI 清单替代。

界面实现使用仓库指定的前端 UI 专业技能；视觉验收与电影团队验收分开，技术通过不等于导演/剪辑工作流通过。
