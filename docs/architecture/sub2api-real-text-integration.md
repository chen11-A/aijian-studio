# Sub2API 首发真实文本集成与验收

更新：2026-10-08。Sub2API 部署、桌面接通和真实受控调用属于首发验收，不能以下载源码、模拟响应或本地配置检查代替。

## 本轮代码修复

- 后端 `Sub2APIConfiguredReadinessData` 返回 `origin_mode`，旧桌面严格解码器却不接受该字段，导致合法响应变成 `READINESS_UNKNOWN`。桌面与 Web 已改为复用生成契约；严格校验保留，模式不明仍不能视为就绪。
- 真实任务与单次批准 scope 同样包含 `origin_mode`；桌面旧严格校验遗漏该字段，已同步修复并用 Python 真实仓储输出的合成 JSON 验证。前端批准回包须与原任务模式一致。
- 已保存的公网 HTTPS 和本机 loopback 连接都能执行只读配置检查。检查显示的是地址/凭据/执行器本地前置条件，不能宣称供应商可达或模型有权限。
- 本机连接的业务密钥轮换使用现有后端 CAS/单次操作与读回流程，不再因部署模式被 UI 一律禁用。切换尚未保存的模式时不允许轮换。
- 来源摘要必须先经现有提案人工接纳，再从剧本页明确读取并导入空白起稿。导入前复核当前摘要、内容哈希、版本和接纳记录；有变化则要求重新审阅。
- 起稿保留摘要原文，标题为“来源摘要 · 待改编”，只创建一个可编辑动作段。它不是生成完整剧本或分镜的证明，不自动保存或确认。
- 导入后的来源版本和接纳 ID 固定到本次编辑/保存。迟到的读取、重新核对和上游变化不能静默改绑；明确舍弃并权威重读才释放未保存绑定。已有持久剧本不被覆盖。

## 部署范围与官方来源

外部网关安装在独立服务目录，与 Apache-2.0 应用源码分离。本机服务仅绑定 `127.0.0.1`，不开放公网。依赖安装、数据库初始化、服务认证密钥和管理员账号设置是不同步骤，分别核实。

- 官方仓库：https://github.com/Wei-Shaw/sub2api
- 官方发布：https://github.com/Wei-Shaw/sub2api/releases/tag/v0.2.14
- 官方部署文档：https://github.com/Wei-Shaw/sub2api/blob/main/deploy/README.md
- 官方容器配置：https://github.com/Wei-Shaw/sub2api/blob/main/deploy/docker-compose.yml

官方 Compose 示例默认可能绑定所有网卡；本产品本机验证不得直接沿用公网监听默认值。Aivora 地址填写 origin，例如 `http://127.0.0.1:18080`，不加 `/v1`；应用在传输层使用 `/v1/chat/completions`。禁止把 Windows portproxy、`localhost`、LAN 地址或重定向当成已验证的本机实例。

## 仍需完成的真实验收

1. 核实运行中的网关服务身份、版本、进程/端口归属和跨进程可达性；安装目录或一次 setup HTTP 200 不等于持续可用。
2. 完成本地数据库/内部认证初始化；管理员密码由用户在安全界面设置。随后由用户连接有权使用的上游账号，并在安全界面生成/填写供 Aivora 使用的业务凭据。密钥不进聊天、仓库、日志或证据截图。
3. 在桌面配置精确 origin、部署模式、模型 ID，保存后重开读回。模型目录/本地就绪检查不得冒充真实推理。
4. 明确批准一次验证：仅发送下列合成来源正文和固定摘要指令，精确网关与模型以用户选定值为准，不发送真实小说、角色或其他项目资料。批准最多一次调用；未知结果不得重发。
5. 从桌面完成来源导入、来源审核、入队、单次授权、任务查询、真实摘要提案、人工接纳、权威草稿读回，再导入空白剧本、人工编辑、保存并重开；核对同一项目/剧集、源版本、接纳 ID 和保存内容。
6. 保留去密钥的请求/响应 ID、任务/尝试/批准/提案/来源版本/剧本版本，记录输入哈希、提供方实际 token 使用和能够核实的账单。金额未知继续显示 UNKNOWN。

> 黄昏，小岚在车站捡到一本蓝色笔记本。她根据扉页留下的书店名字找到失主，把笔记本归还。失主送给她一张空白明信片，小岚写下今天的日期，决定开始记录自己的故事。

## 费用边界

当前源提取实现持久约束为一次调用、禁止自动重试；费用状态为 `UNKNOWN`，预算执行为 `UNENFORCED`。当前传输请求没有输出 token 上限，因此不能把一次调用、20 秒传输截止或 1 MB 接收上限说成“最多花费某金额”。若用户要求金额上限，必须先在网关/上游建立并验证可强制执行的相应额度，再授权真实调用；中断客户端也不保证上游停止计费。
