# v0.3.0 product decisions

Date: 2026-10-24. The owner asked for the finished software and no questions.
When a call was still open, this panel decided it and the code follows.

## Panel

- 导演：镜头必须能拍，一场一事，名字只能来自用户写的剧本。
- 剪辑：成片先有起始画面再动，视频自己的声音关掉，免得盖过配音。
- 产品：按钮做不到就说明原因，不要假装成功。
- 周宁（第一次用）：先看到空作品，打开示例才进入雨夜巷战。上次写到一半，重新打开还在。
- 林可（熟练用户）：画风、镜头、人物改了就要进生成；确认之前不要改她已经改过的字。

## Decisions

1. **导演。** 登录后，「让导演拆镜头」把剧本、画风和人物交给当前文字模型，要求 JSON。解析失败先再要一次。还不对，就用离线拆镜，并说明原因。离线拆镜按用户自己的句子轮换景别，不再把「雨夜巷战 / 林夏 / 阿凯」写死进每一部片子。短片页的「用示例：雨夜巷战」仍使用那一套编排好的示例动作，只在示例按钮里。
2. **起始画面。** 每个镜头先按自己的画面描述生成一张起始图，再图生视频。角色定妆照只作参考。定妆照若只有本机文件、没有 https 网址，就不传 `reference_images`（这项会员登录还没验证），外貌写进提示词，界面说明原因。
3. **文字模型。** 专业工作台的编剧、导演、动作、表演、助手走已经登录的 Grok。没有 Grok、但有已核对的 ChatGPT 时，旧的审阅记录仍走 ChatGPT。两边都没有，就用离线拆镜。
4. **助手。** 发给 Grok 的正文前面带作品名、画风、人物和当前场。回复不会自动改作品。剧本页要点「放入分镜」才写入，而且跳过用户改过的字段。
5. **画风。** `STYLE_REALISM` 只是「写实电影感」预设的中文段落。作品可以换预设或改这段文字。默认句子与以前相同，旧片子的提示词不变。
6. **未验证的能力。** 参考图、首尾帧、视频编辑、延长、视觉审片、接口级 JSON schema 都没有在会员登录上验证。编辑和延长仅当模型列表里有 `grok-imagine-video` 才可点。审片先不打分，由用户选版本。JSON 只在提示词里要求，解析失败就降级。
7. **次数。** 每镜版本数默认 2，同时生成默认 2，自动重试最多 2 轮。都写在作品设置里，因为订阅额度未知。
8. **模型 id。** 放在 `model_config.py` 和前端 `capabilities.ts`。图像模型 `grok-imagine-image-2.0`，文档写明 2026-11-02 有图像模型下线。不猜替代 id。到期后若列表里没有它，生成按钮说明原因。
9. **旧的官方导演审阅。** 那套记录协议仍是 ChatGPT 的。Grok 上的导演是剧本页的智能体，不把两套记录混成一种。
