## 目标与已有基础

同一桌面内从已保存剧本/分镜进入真实媒体和声音任务，收回可追溯素材，完成装配、审片与正式输出。
图像验证只是先行任务，不能替代视频运动、中文口型、声音与完整成片验收。

复用制作请求 `episode_media_preparation`、原 `artifact_versions`、任务/尝试账本、凭据库、
原操作回执和真实素材/装配链。准备输入保存仍然零派发。现有 Sub2API 连接在
`provider_contracts.py` 中限定 TEXT；不得仅修改能力枚举就宣称媒体任务可运行。
媒体 submit/query/cancel/输出下载协议、精确服务版本和逐项能力仍需核实。

## 固定策略与首段交付

1. 作品总预算必须存在；分集子预算可选，但分集支出始终计入作品总额。
2. 确定超额时禁止派发；明确增加额度后，必须针对新预算修订重新确认，不自动恢复执行。
3. 预算、历史支出、未结预留或本次金额未知时，不按零处理。估价不是上游可强制执行的收费上限。
4. 同币种才比较，不自动换汇，不默认具体币种/金额/账号。

第一增量是纯本地预算判断：闭合金额与余额快照、总额/子额双重检查、明确阻断原因和单元测试。
输入中的作品累计已包含各分集，不再加一次分集累计；本次预留只加一次。
判断结果不创建任务、不持有授权、不消费额度，也不是派发许可。持久事务与生产消费者未接入前，
界面不得显示“预算保护已启用”。这一步不修改数据库、外部接口或现有执行器。

金额采用同币种整数微单位（1 单位 = 1,000,000 微单位），不使用浮点。
整数必须是非负安全整数，拒绝 bool、浮点、溢出及未知金额；结果不会四舍五入掩盖超额。
微单位是内部比较精度，不是价格、币种选择，也不表示供应商支持该计费粒度；超精度账单不得静默截断。

## 首段文件与风格

- `services/api/src/aijian_api/media_budget_policy.py`：纯本地不可变值对象及预算判断；不读取环境、网络、密钥或数据库。
- `services/api/tests/test_media_budget_policy.py`：金额边界、总额/子额、未知与错币种、剩余额度、无副作用测试。
- 本规格及预算决策文件记录策略；已有制作输入、任务账本和 TEXT 专用权限保持原样。

沿用现有 Python 3.12、严格 mypy、Ruff 100 列；API/渲染器后续仍使用现有 Pydantic/TypeScript 合同，
不增加依赖。不可变内部快照采用仓库已有的 dataclass 形式，例如现有 `Sub2APIDispatchPermit`：

```python
@dataclass(frozen=True, slots=True)
class BudgetAssessment:
    status: BudgetStatus
```

这是结构示例，不是对外已发布 DTO。现有数据库/回执仍在消费处核验，不能因值对象通过就相信外部输入。
