# AIVORA 完整产品需求与验收基线

日期：2026-09-24。范围：完整可使用的 Windows 桌面产品，不是首版、演示版或功能裁剪版。

本文统一已读取的产品需求、当前明确方向和23页导航中的交付要求；不是功能已完成的声明。历史原始 Word 尚未逐页复核，按钮级全量审计仍在进行，不能声称已穷尽历史文档中的每个细节。遗漏须补入本文，不另起竞争方案。当前开发继续，新增未定设计单独确认，不以整理文档为停工理由。

## 1. 产品终点与范围

AIVORA 让单用户在同一个桌面软件中完成：创建作品和分集 → 导入来源或原创构思 → 理解故事与编写剧本 → 确认角色、世界、场景和声音 → 分镜与动态预演 → 真实生成画面、动画和对白 → 多轨组装 → 审片修改 → 正式成片导出。

- 保留已选定的星夜之城界面及五阶段：故事、角色与世界、分镜、制作、审片。导出是交付动作，不新增第六阶段。
- 一份产品代码、一个集成主线、一套持久化真相；不另建网页产品或另一套 UI。现有技术目录名 studio-web 不代表交付独立网页。
- 以完整流程和下面全部要求作为终点。分批实现只表示依赖顺序，不缩小最终范围。
- 支持一部作品多集；至少用两集验证共享角色、服装、世界、场景、声音及素材版本。
- 支持约两万字真实来源及无原文原创两条路线；镜头数和时长按作品决定，不固定八镜头或30秒。
- 真实连续动作、身份一致性和高精度中文口型属于必需能力。静帧推拉、假素材或画外音不能替代。
- 不要求使用者安装开发工具或跳到 Blender、ComfyUI 等软件完成必需制作环节。外部 AI 服务仍需要合法可用的服务地址、凭据和授权额度。
- Sub2API 是明确要求接入的外部网关，不再列作“以后再选”。接入网关不等于其上游天然具备所有文本、图像、视频、语音能力。

## 2. 所有页面共同遵守的交互要求

以下 UI-01 至 UI-10 对每个页面、按钮、链接、菜单、图标动作、快捷键及弹窗生效。

1. UI-01：正式入口不出现开发用演示切页、模拟状态、重置演示、虚构余额、固定进度或样例作品冒充真实数据。测试 fixture 与正式运行隔离；不能只删除“演示”字样保留假行为。
2. UI-02：可点击操作必须完成明确动作：导航、打开对应编辑器、执行本地操作或提交真实任务。禁止空 handler、吞异常、仅弹“成功”却不保存。
3. UI-03：缺少前置条件时禁用并说明具体原因，提供到来源审核、模型设置等真实修复入口。开发期间的禁用不算功能完成；最终必需功能必须在前置条件满足后可用。
4. UI-04：导航和返回保留作品、分集、场景、镜头、时间码、版本和 AI 会话上下文；打开不同作品不得串数据。未保存离开必须有处理提示。
5. UI-05：提交立即提供处理中反馈，防重复提交；耗时任务显示真实任务状态。成功须能读取持久结果，失败说明原因和下一步。
6. UI-06：关闭重开恢复已保存数据及可恢复任务；保存失败不能显示已保存。结果未知与失败分开，不能自动重复收费任务。
7. UI-07：空态、加载、错误、无权限、未配置与内容失效状态清楚区分；无数据不注入默认样例。
8. UI-08：普通和专业模式共享相同数据和权限；专业模式只增加检查器，不自动批准内容。
9. UI-09：键盘焦点、编辑器输入、选择器、菜单、快捷键和窗口关闭可用；1600×900、1440×900及小窗无关键控件遮挡或无法操作。
10. UI-10：服务状态来自真实配置与探测记录；区分未配置、检查中、可连接、能力未验证、错误。不能永远写死“未连接”，也不能配置后直接宣称生成可用。

按钮验收记录固定字段：页面/控件名称、代码位置、前置条件、点击后动作或目的页、API/IPC、持久对象、等待/失败/恢复行为、测试证据、实机结果、负责人。每个可见交互都要有记录，不靠按钮数量推断覆盖率。

## 4. 跨页面必需能力

### F01 数据、版本和恢复

- 作品/分集/场景/镜头归属明确。来源、故事、剧本、视觉、声音、分镜、媒体、时间线、审片和导出绑定版本、父版本与哈希。
- AI 输出先成为提案，人工接受后形成正式版本；保留拒绝、变更与批准记录。
- 关闭/崩溃恢复不丢已保存内容，不把运行中任务改为成功。支持备份恢复，并在升级迁移前保护原数据。
- PictureLock或上游版本变化时，列出声音、字幕、口型、组装和母版的失效范围，执行最小必要重做。

### F02 一个 Aivora AI 助手

- 在当前作品/分集/镜头上下文下解释、提出修改、导航到结果和创建可审阅任务。
- 显示正在处理什么、输入范围、结果、失败和需要批准的动作；不能用固定回复冒充模型调用。
- 助手不能自行覆盖已批准产物、扩大上传范围或突破预算。更换作品隔离会话和返回结果。

### F03 Sub2API 和其他必要模型能力

- 复用产品服务边界、安全凭据库、模型路由和任务账本，不建立第二套后台真相。
- 外部连接校验准确 origin、HTTPS/证书和网络安全边界；局域网/本机例外需要具体部署决定，不能套用CPA端口豁免。
- 业务 API key 与管理凭据分开；渲染器、日志、导出包不保存明文密钥。密钥修改/删除有明确结果。
- 明确处理认证失败、限流、超时、无效模型、响应格式错误、服务不可达及未知结果。请求有可追踪标识。
- 文本接通不能代替图像、视频、语音、口型接通。完整交付需要每项必需能力对应实际可用且获授权的服务/实现；不支持的能力明确显示缺口并补齐。
- 付费、素材/声音/肖像上传、账号权限分别授权；不隐式回退到收费服务。预算未授权不自动花费，但不阻止本地代码实现和非外呼测试。

### F04 媒体真实性与质量

- 真实运动生成与 MotionProof；连续镜头角色、服装、场景和动作关系一致。
- 中文近景、侧脸、遮挡、快语速和双人对白分别检查口型；系统性音画偏移目标不超过1帧，另做口型自然度人工审核。
- 实际媒体解码、整数帧/有理帧率定位、原片/代理映射；损坏、缺失、超时和不支持格式有清晰处理。
- 素材来源、权利、技术参数、生成任务及引用关系可追踪；外部成片导入不能证明在软件内生成。

### F05 安装、运行、安全与交付

- Windows标准用户环境可安装、启动、正常关闭、升级和恢复；不依赖用户预装Node/Python/FFmpeg开发工具。
- UI之外的必需本地组件由受控启动和退出管理；启动失败有诊断入口，不留下假在线状态。
- 文件访问、外部响应、IPC和上传输入校验；诊断包脱敏，私有媒体和凭据不进仓库。
- 发行前核对字体、图片、媒体工具、模型及依赖许可；开发可用不等于可发行。
- 安装包、源代码基线、构建标识和界面版本对应同一交付，不另发界面不一致的旧版本。
