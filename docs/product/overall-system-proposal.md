### 0.3 责任切分（冻结）

规划书说“AI 是主执行者”，仓库说“AI 不能成为法律或创意责任主体”。两者同时成立，按下表切分：

| 权 | 持有者 | 含义 |
| --- | --- | --- |
| 执行权 | AI 默认 | 拆解、导演、美术、分镜、生成、配音、粗剪、改稿方案，能自动且可回退的都自动做 |
| 写入权 | 工作流引擎 | 只有通过 Schema / 规则 / 预算校验的 ArtifactProposal 能落成 DRAFT 版本 |
| 扣费权 | 预算预留 + 用户确认阈值 | 硬预算不得突破；首次进入高费用类别、费用跳变、能力降级必须问用户 |
| 创意否决权 | 用户 | 任何候选都可被否决；普通模式用短句，专业模式看证据 |
| 发布权 | 具名人类 | G8 / “确认导出”。AI 不得把成片标为已发布 |
| 权利豁免权 | 具名人类 | 未清权资产不可豁免；创意偏差才允许 waiver |

隐藏 Gate 名称不等于跳过 Gate。普通模式可以说“确认人物形象”，系统内部仍冻结 VisualBible 版本。

## 0.4 评审结论摘要

**一句话定位**  
Aijian Studio 不是“带 AI 的剪辑软件”，也不是“提示词生成器”。它是一套以用户创作意图为权威数据、以角色/场景/声音/动作等可复用资产为基础、以 AI Agent 与多模态模型完成主要制作工作、以时间线和审片批注完成验证与定点修改的 AI 原生漫剧/短剧生产工作台。

评审方必须一致同意：

- 普通模式与专业模式共用同一套项目数据、生成能力和质量标准；区别仅是信息密度、控制粒度和默认自动化程度。
- 编剧、导演、美术、摄影、声音、剪辑、连续性监督继续作为后台能力域；普通用户不逐个操作。
- 能由 AI 自动完成且可验证的工作，默认由 AI 完成；状态、版本、费用、任务恢复、依赖和发布条件仍由程序控制。
- 专业剪辑只保留 AI 漫剧生产需要的部分，不复制 Premiere / Resolve。
- 审片采用“完整看片 → 多时间点批注 → 审核完成 → AI 统一分析 → 批量修改”，而不是批注一条生成一条。
- 减少 Token 浪费的方法是取消重复推理、全量上下文、无条件多 Agent 会审和无意义真实模型测试；不是取消数据安全、费用、防重复扣费、恢复和结果验证。

| 核心问题 | 方案决定 |
| --- | --- |
| 软件是什么？ | AI 原生漫剧/短剧创作与制作工作台，覆盖故事到成片的生产闭环。 |
| AI 的地位？ | 主执行者，但不是数据库主人，也不是发布责任人。 |
| 是否保留导演/美术等角色？ | 保留为能力域。普通用户不接触；专业模式可查看决策。 |
| 是否做专业剪辑？ | 保留必要时间线：组装、审片、版本替换、声音/字幕、最终导出。 |
| 角色是否内置？ | 有系统示例资产，也支持 AI 创建和用户导入。示例资产必须有许可证；未清权标 `demo-only`，阻断正式发布。 |
| 如何接近预期？ | 意图验收单 + 资产锁定 + 参考输入 + 模型能力适配 + 预演 + 偏差定位 + 定点修改。 |
| 如何省 Token/费用？ | 按需 Agent、最小上下文、结构化事实复用、程序规则替代模型、批注统一处理、按风险验证、失败停止。 |

## 1. 产品定义与定位

Aijian Studio 面向小说、漫画、剧本和原创故事，把“故事理解—角色资产—导演分镜—图片/视频/声音生成—时间线组装—审片批注—AI 定点修改—导出发布”放进同一项目的可编辑生产流程。

核心竞争力不在“某一个模型生成得更好”，而在于用户意图、已批准资产、镜头状态和生成结果在同一数据体系中：系统知道一个镜头为什么存在、应该表达什么、用了谁、穿什么、在哪里、如何演、哪里错了、修改会影响什么。

### 1.1 产品不是什么

| 不是 | 原因 | 替代定位 |
| --- | --- | --- |
| 单纯 AI 视频生成器 | 只解决一次生成，不解决长流程一致性与修改 | 可反复修改、版本化、可追溯的生产系统 |
| 提示词工具 | 用户仍需理解大量模型细节 | 提示词是编译产物；用户维护意图与资产 |
| 传统 NLE 克隆 | 范围无限扩大，形不成 AI 原生优势 | 必要专业时间线；AI 负责大量剪辑与修改决策 |
| 纯 Agent 聊天系统 | 聊天记录无法成为可靠项目状态 | Agent 产出结构化候选，程序负责状态与版本 |
| 一键无人值守成片 | 不能保证所有创意判断正确 | 高自动化 + 用户关键节点审片和最终决定 |

### 1.2 产品原则

1. 用户意图优先于提示词。模型输入由已确认意图和资产编译得到。
2. AI 优先执行。能自动完成、可验证、失败可回退的制作工作，默认由 AI 完成。
3. 固定内容资产化，变化内容差异化。角色、服装、场景、声音、风格不在每个镜头重复描述。
4. 先对齐意图再花高额生成费用。高成本任务前完成故事、分镜、参考资产和风险检查。
5. 完整看片后统一修改。批注是修改输入，不是立即生成按钮。
6. 局部修改优先。只重生成确实受影响的镜头、声音或字幕；检查范围与付费重生成范围分开。
7. 普通与专业同质不同层。专业模式不是“质量更高”，普通模式不是阉割版。
8. **程序保真，模型探索。** 状态机、预算、幂等、权限、时间基、哈希由代码保证；模型只在规则内提案。

### 1.3 1.0 仍然不是的事（从 PRD 收回，防止本文把范围撑爆）

- 不训练自有基础模型。
- 不把 ChatGPT / Grok 网页会员当 API；不做账号登录自动化。
- 不做与 Premiere / Resolve 等价的通用 NLE。
- 不在手机上做复杂时间线精剪。
- 不做无人监督自动发布。
- 首版不做两个离线数据库的双向冲突合并。
- 不把“全动态电影级”或“完整长篇自动改编”写进 Creator Beta 口径。

## 2. 用户与使用模式

### 2.1 主要用户

| 用户 | 主要目标 | 系统替他承担什么 | 默认模式 |
| --- | --- | --- | --- |
| 个人创作者 | 从故事快速得到可发布漫剧 | 拆解、导演、美术、分镜、生成、基础剪辑、配音字幕、批量修改 | 普通 |
| 网文/漫画 IP 创作者 | 保持人物与设定，批量改编 | 来源理解、角色一致性、分集、资产复用、改编追踪 | 普通，专业可展开来源 |
| AI 漫剧工作室 | 多人效率与复用 | 任务分配、资产版本、批量生成、审片、费用与质量 | 专业 + 服务器形态 |
| 导演/生成师 | 精细控制重要镜头 | 镜头参数、参考输入、模型策略、版本比较 | 专业 |
| 剪辑/审片人员 | 看片、定位、形成修改单 | 时间码批注、影响分析、批量修改、自动替换 | 普通审片 + 专业时间线 |

岗位继续存在，但普通模式不按岗位做顶层导航。

### 2.2 普通模式

设计目标不是减少功能，而是隐藏制作术语。用户看到六个空间。镜头参数、模型差异、版本依赖和 Agent 分工由系统处理，只在歧义、费用变化或能力不足时打断。

典型输入：自然语言、故事文本、参考图/视频、已有角色、修改意见。  
典型修改：“第三镜她太害怕了，改成怀疑但保持镇定，衣服、背景、台词不要动。”

### 2.3 专业模式

展开同一份项目数据：ShotIntent、镜头参数、参考资产、连续性、PromptPlan、供应商能力、生成历史、版本依赖、时间线高级操作。

**硬规则（ADR-0005）：** 任何时刻切换普通/专业模式都不得复制项目、重建素材或触发重新生成。它只是同一数据的不同 UI 视图。模式不写入 Project Schema。

### 2.4 三种运行形态仍然有效

本文的“主工作区”默认按桌面创作端叙述，但不取消：

| 形态 | 谁用 | 说明 |
| --- | --- | --- |
| Windows 桌面 | 个人与小团队单机 | Electron + 本机 sidecar，随机回环端口 |
| 工作室服务器 | 局域网 / 私有云团队 | HTTPS + 认证 + PostgreSQL + 对象存储 |
| 手机审片 PWA | 外出审批与客户 | 只做看片、批注、审批、轻量上传；复杂精剪不做 |

桌面、服务器、PWA 共用同一领域模型和 ReviewRound 契约。PWA 是 Studio Beta 的形态交付，不是第二套产品。

## 3. AI 角色体系、权责与 Gate 映射

导演、编剧、美术等角色从“用户要分别操作的页面”改为“系统内部专业能力域”。AI 能自动完成的默认自动完成；只有关键分歧、费用明显增加、能力降级或用户主动展开时，才显示专业决策。

| AI 角色 | 核心职责 | 普通模式呈现 | 专业模式呈现 |
| --- | --- | --- | --- |
| 制片统筹 | 目标、时长、平台、预算、冲突 | 项目方案和风险提示 | 预算、依赖、任务策略 |
| 编剧 | 故事理解、改编、场景、对白 | 编辑剧本与故事 | 来源、改编账本、结构化场景 |
| 导演 | 叙事目的、表演、节奏、镜头意图 | “这一段准备这样拍” | ShotIntent、动作节拍、覆盖 |
| 美术/角色监督 | 角色、服装、场景、道具、风格 | 角色/场景卡片 | 资产版本、参考图、连续性 |
| 摄影/分镜 | 景别、构图、机位、运动 | 故事板和可播放分镜 | 镜头参数、首尾状态 |
| 声音导演 | 配音、情绪、语速、环境、SFX、音乐 | 试听与选择 | VoicePlan、Cue、混音规则 |
| 剪辑 AI | 顺序、节奏、声画、字幕、转场 | 自动粗剪和一键优化 | 时间线、J/L cut、版本替换 |
| 连续性监督 | 跨镜头衔接 | 只在冲突时提醒 | ContinuityState 与影响报告 |
| 审片 AI | 对照意图定位偏差 | 汇总问题与修改方案 | 逐镜差异、置信度与证据 |

### 3.1 Agent 调用原则

- 职责存在 ≠ 每次都要独立调用一个模型。一次调用可产出多个相关结构化输出。
- 只调用当前任务涉及的能力域。只改字幕，不重跑导演和角色监督。
- 数据库状态、参数合法性、预算、依赖、重试、防重复提交由确定性代码完成。
- 已批准事实从结构化存储读取，不让模型反复“重新理解”整个项目。
- 专业角色输出采用结构化 ArtifactProposal，不是长篇会议纪要。
- **模型不得改工作流拓扑，不得把 Proposal 写成已批准，不得自己确认 ChangePlan。**

### 3.2 Gate 在普通模式里怎么出现

内部仍使用 G0–G8，否则昂贵生成、权利和发布无法证明。对普通用户，Gate 是确认卡或静默检查，不是 13 步向导。完整表见 [附录 B](#appendix-gate-map)。摘要：

| Gate | 普通模式 | 可否自动过 | 专业模式 |
| --- | --- | --- | --- |
| G0 立项 | 创建项目时填写画幅、时长、风格、预算 | 创建即确认 | ProductionBrief / DeliveryProfile |
| G1 原文 | 不展示“G1”；解析失败或低置信度才打断 | 默认可自动 | 章节校对、SourceSpan |
| G2 圣经 | “确认人物和世界观” | 必须用户看过人物卡 | Canon、冲突报告 |
| G3 分集 | 单集项目静默；多集或时长冲突才问 | 单集可自动 | 分集卡、改编损失 |
| G4 剧本 | 故事空间里编辑/确认 | 用户离开故事空间且无冲突可视为确认 | 结构化 Scene/Beat |
| G4T 桌读 | 不展示；对白超时才提示 | 默认可自动 | Readthrough 报告 |
| G5 视觉 | “确认人物形象” | **必须确认** 才允许高费用形象生成 | VisualBible 版本 |
| G6A 镜头 | 分镜空间确认故事板 | 确认分镜即冻结 ShotPlan | Coverage、手柄 |
| G6B 生产就绪 | 不说“G6B”；缺能力/超预算/高风险镜头未验证则禁止完整视频 | **不得静默花视频费** | Animatic / MotionProof / 能力损失 |
| G7A 粗剪 | 进入审片空间即面对组装结果 | 生成完成后自动组装 | PickupList |
| G7B 画锁 | 导出或精修声音前用白话提示“改画面会重做声音” | 不自动锁死；导出路径才确认 | PictureLock |
| G7C 成片检查 | 导出前自动跑技术/字幕/声轨检查 | 自动检查，失败阻断 | Master 候选 |
| G8 发布 | 按钮文案「确认导出」 | **始终要人点** | 完整 QC 与 RightsLedger |

单用户允许自审，UI 必须标明。团队模板可要求双人审批。解冻已批准产物必须计算失效下游并确认费用。

## 4. 端到端用户体验

### 4.1 从故事到成片（普通模式叙述）

1. 用户创建项目，输入故事/小说/剧本，选择画幅、目标时长、风格方向和可接受预算。（G0）
2. AI 解析人物、事件、地点、关系和关键设定；原著锚点保留，原创内容标记为系统建议或用户决定。
3. AI 生成故事圣经、分集/场景方案和剧本。普通用户直接审内容。
4. 系统创建或绑定角色、服装、场景、道具、声音和风格资产。
5. 导演/摄影 AI 生成镜头计划和故事板，自动制作带临时对白的可播放预演。
6. 用户确认故事表达、人物形象和主要节奏；系统只对高风险镜头做最小技术验证。
7. 系统按镜头选择图片/视频/表演/声音生成方式，编译并执行。G6B 未满足时不能提交完整视频任务。
8. 结果进入时间线，剪辑 AI 完成粗组装和对白/字幕/音乐基础布局。
9. 用户从头完整审片，在任意时间点添加多个批注；看片过程不中断、不触发生成。
10. 用户点击“审核完成”。系统统一理解全部批注，生成修改清单、影响范围、费用和执行计划。
11. 用户确认后，系统批量执行局部重生成、配音、字幕或剪辑调整，并替换时间线中的对应版本。
12. 可继续新一轮审片，直至接受；发布检查通过后导出。

专业用户在同一步骤展开来源、ShotIntent、模型能力和版本依赖。不得要求普通用户先理解焦段、Seed 或 Agent 名称。

### 4.2 关键体验目标

用户不应该被要求成为提示词工程师、导演、摄影师、剪辑师和测试工程师。系统必须把这些知识变成默认方案、可视化预演、清晰差异和少量真正必要的选择。

### 4.3 失败时用户看到什么

不要弹出堆栈或“节点 screenplay.generate FAILED”。普通模式只允许四类可读结果：

1. 需要你做个选择（两个人物长得太像、时长超了）。
2. 这次生成没达到你刚才确认的要求（附证据帧）。
3. 继续会多花多少钱，是否仍要做。
4. 系统暂时无法安全继续（远程结果未知、权利不清、媒体损坏），并给出可执行下一步。

## 6. 角色、场景与可复用资产

### 6.1 内置角色与系统资产

内置示例资产的目的是让没有素材的用户也能走完流程，并提供可复用的动作/表情/场景/风格模板。不是限制用户只能用系统脸。

| 资产类型 | 系统内置 | 用户扩展 |
| --- | --- | --- |
| 角色 | 都市男女、古风、职场、少年/老人等示例 | AI 创建、单图/多图、导入原创 IP |
| 服装 | 日常、工作、正装、古装、雨夜 | AI 生成、参考图绑定、自定义 |
| 场景 | 室内/街道/办公室/医院/古风 | AI 创建、上传、项目复用 |
| 动作 | 走路、坐下、转身、开门、拥抱、打电话 | 参考视频、用户示范、外部工作流 |
| 表情 | 微笑、克制、怀疑、紧张、愤怒、悲伤 | 自定义表演意图/参考表演 |
| 声音 | 系统示例声线 | TTS、用户授权声音、录音 |
| 风格 | 国漫、日漫、韩漫、写实动漫、电影写实、古风 | 参考图和自定义 StyleProfile |

### 6.2 许可证硬规则（原文只提到风险，这里补执行）

- 每条系统资产必须有：许可证、用途边界、肖像/声音同意、能否进入正式成片、来源记录。
- 进入仓库前写入 RightsLedger 与 `third_party/provenance.yml` 同类审计。
- 未完成清权的资产标记 `demo-only`：可用于预演和学习，**G8 不可豁免**。
- 用户上传角色默认权利归用户声明；系统不把用户脸写成“系统示例”。

### 6.3 Character Bible

角色不是一张图片，而是版本化对象：Identity、Face/Hair/Body、Voice、Wardrobe、ReferenceSet、PerformanceProfile、Rights。镜头引用角色版本，不重复一大段人物提示词。

### 6.4 角色状态与连续性

每个镜头保存 ContinuityStateBefore/After：服装、湿/干、伤势、手持道具、位置、目线、动作接点。改变角色状态时只检查真正相关的后续镜头。

“数据库里没有改服装”只能保证设定没变，不能保证生成画面绝不改服装。必须区分 **意图锁定** 和 **像素保持**；靠参考输入和结果检查降低漂移，并在模型不支持局部精确编辑时明确告知。

## 7. AI 导演、分镜与表演控制

### 7.1 ShotIntent 是权威，提示词不是

导演 AI 的权威输出是结构化 ShotIntent，至少包括：叙事目的、观众要看懂的信息、主体、动作/表演、镜头范围、构图、摄影机运动、时间、声音、必须保持、禁止偏差、允许自由发挥、参考依据、验收重点。

### 7.2 从抽象情绪到可观察表演

| 用户表达 | 系统内部表演方案示例 |
| --- | --- |
| “她有点怀疑，但别太明显” | 短暂停顿；目光停留略增；嘴角收紧；头部动作很小；不皱眉、不后退 |
| “生气，但不能失控” | 语速略慢；停顿更重；眼神稳定；肩部紧张；不吼叫、不大幅挥手 |
| “强装镇定” | 呼吸短暂变化；动作克制；先回避再恢复目光；表情幅度小 |

这些是制作层可观察意图，不是视频模型原生物理参数。能否用文字、首尾帧、参考视频、姿态或表演驱动实现，由适配器决定。

### 7.3 分镜与预演

- AI 自动生成镜头表、故事板和参考拼图。
- 用户可以像看漫画一样确认人物、构图和故事顺序。
- 优先使用已批准角色/服装/场景参考，分镜不是每次从文字再造同一个人。
- 预演验证叙事、节奏和声画关系，不把低成本预演宣传成最终动态质量保证。
- 高风险镜头的 1–2 秒 MotionProof 在 G6B 内部发生；普通模式只看到“这几个镜头我们先试一下，以免整段白花”。

## 8. AI 生成与模型适配

### 8.1 三层编译

1. **ShotIntent**：供应商无关的创作权威数据。
2. **PromptPlan**：主体、动作、环境、连续性、负面条件、图片/视频/音频参考。
3. **CompiledRequest**：面向具体模型的文本、参考文件、参数、能力损失、预计费用。

用户可编辑任意层；改 CompiledRequest 只影响这一次尝试，改 ShotIntent 使所有供应商编译失效。普通模式默认不打开后两层。

### 8.2 最小必要信息，不是最短提示词

固定的角色、服装、场景和风格由资产和参考输入承担；文本主要描述当前镜头的变化。复杂动作或微表演若模型支持参考表演、关键帧、姿态或局部控制，优先用更直接的控制，而不是把提示词写到一千字。

### 8.3 模型能力分级

| 能力差异 | 系统动作 |
| --- | --- |
| 必需能力缺失 | 阻断生成，建议换模型或改制作方式 |
| 可改镜头方案规避 | 给出调整前后差异、费用和影响，用户确认后执行 |
| 非关键能力缺失 | 提示风险，可继续 |
| 无法稳定保持指定内容 | 告知重生成可能改变非目标细节，不伪装成局部精确编辑 |

### 8.4 候选、版本、扣费

每次生成进入候选池。批准指针与文件分离，任何替换都创建新版本。相同输入的未知远程任务不自动重提。提交前按最坏情况原子预留 `reserved` 预算，完成后记 `accrued` 并与供应商 `billed` 对账。

## 9. AI 审片、时间码批注与统一修改

这是相对普通生成器和传统 NLE 都应强化的体验，并 **提前到 Creator Beta**，而不是等到 Studio Beta 才做时间码评论。契约见 [ADR-0006](../architecture/ADR-0006-review-round-and-change-plan.md) 与 [审片 Schema](../contracts/review-annotation-and-change-plan.md)。

### 9.1 审片交互

1. 用户播放完整成片或某一段。
2. 在播放器或时间线当前时间点点“批注”。系统记录 timecode、镜头 ID、当前帧和相关资产版本。
3. 用户输入自然语言修改意见，可选“必须保持”和问题类型。
4. 保存批注后立即继续看片，**不触发生成**。
5. 整片看完后点“审核完成 · 生成修改方案”。
6. AI 一次读取本轮批注与必要上下文，合并重复项、识别冲突、形成 ChangePlan。
7. 系统展示预计重生成镜头、重新配音、字幕修改、纯时间线调整、费用与风险。
8. 用户确认后批量执行。完成后形成新审片版本，允许下一轮。

### 9.2 批注与计划不是聊天

批注、Round、ChangePlan 都是 Artifact。ChangePlan 必须列出每个 ChangeItem 的 `action`、`must_keep`、`invalidation` 和费用。用户拒绝则不执行、不扣生成费。

Creator Beta 自动执行白名单：`regenerate_video` / `regenerate_audio` / `edit_subtitle` / `timeline_adjust`。其余标 `needs_human`。

### 9.3 统一修改的成本意义

12 条批注可能只对应 4 个视频镜头、2 条配音、3 条字幕、2 处时间线调整、1 条重复。一轮共享当前成片上下文，优于 12 次独立 Agent 链。

### 9.4 反复审片

“审核完成”只结束本轮收集。每次批量修改后产生新的可审片版本，直到最终接受。最终接受仍不等于 G8；导出才走发布检查。

## 10. AI 原生剪辑与时间线

时间线是 AI 生成素材的组装、审片和局部替换平台，不是产品中心。能由 AI 完成的剪辑默认由 AI 根据节奏、对白和批注执行；用户需要时可手动干预。

### 10.1 保留与不深做

| 能力 | 是否保留 | 目的 |
| --- | --- | --- |
| 多轨视频/对白/旁白/SFX/BGM/字幕 | 保留 | 成片必须具备 |
| 帧级时间码、逐帧、Marker/批注 | 保留 | 精准审片 |
| Trim/Split/Replace/Ripple | 保留 | 手动修正与自动执行基础 |
| Slip/Roll/Insert/Overwrite | 专业模式，GA | 精细节奏 |
| J/L Cut、基础转场、Fade | 保留 | 声音和节奏 |
| Clip Version 切换 | 重点保留 | 多候选与重生成 |
| Proxy/原片回连 | 保留 | 高分辨率流畅剪辑 |
| 字幕、音量、基础 Ducking | 保留 | 成片后期 |
| 完整调色 / ACES / HDR | 不深做 | 交给专业 NLE |
| 复杂 VFX / 合成节点 | 不深做 | 交给 AE / Fusion / Nuke |
| 完整 DAW | 不深做 | 基础处理 + 外部工具 |

时间线 API 禁止浮点秒。转场占用手柄，手柄不足必须报错或由人选择缩短，不静默重复帧。

### 10.2 AI 剪辑

- 根据对白时长自动 Assembly / Rough Cut。
- 根据目标时长、节奏和镜头用途建议缩短/延长/替换。
- 自动基础 J/L cut、BGM Ducking、字幕同步和基础转场。
- 批注执行时自动定位并替换新版本。
- 所有 AI 剪辑可撤销，有说明，可切回之前 TimelineVersion。

## 11. 普通模式与专业模式界面

### 11.1 设计语言

专业创作工具的克制设计：深色工作区、清晰信息层级、适度圆角、紧凑但不拥挤、少量强调色表达状态。避免“大卡片 + 大圆角 + 渐变 + 霓虹”的低信息密度 AI SaaS 风格。

### 11.2 顶层信息架构

六个空间是 IA 根。专业控件放在右侧 Inspector 展开，不新增一套顶层导航。详见 [ADR-0005](../architecture/ADR-0005-casual-professional-views.md)。

### 11.3 桌面主工作区

- 左：项目导航与故事/角色/资产
- 中：播放器或分镜画布
- 右：当前上下文属性 / AI 助手 / 批注清单
- 下：可折叠时间线
- 顶：项目、普通/专业切换、预算/生成状态、全局搜索

切换控件旁边不写“高级模式质量更好”。应写“显示制作细节”。

### 11.4 审片界面

播放器保持最大视觉权重；时间线上方显示批注针；右侧清单按镜头和类型分组；点击批注跳转对应时间点。底部主按钮为「审核完成 · 生成修改方案」。

### 11.5 费用与风险在两种模式都可见

普通模式用一行：“预计生成 12 个镜头，大约 $4.2–$6.8，3 个镜头模型不太稳。”  
专业模式展开到每个 Shot 的 CompiledRequest 与 reserved 预算。

## 12. 意图准确性与质量闭环

### 12.1 意图验收单

进入重要镜头制作前维护短结构化约束，不让用户写长提示词。字段见审片契约第 5 节。普通模式把这些字段写成三个问题：要表达什么、什么不能变、什么算失败。

### 12.2 结果状态

| 状态 | 含义 |
| --- | --- |
| 生成完成 | 供应商返回了媒体，不代表符合意图 |
| 待核对 | 需要用户或审片 AI 对照意图检查 |
| 存在偏差 | 关键要求或连续性不满足 |
| 用户已接受 | 可作为当前批准资产继续使用 |

### 12.3 不用单一综合分掩盖关键错误

硬约束失败就是失败。“不能哭”却哭了 → 关键要求失败，即使其他指标 92 分。质量系统输出 `hard_fail / soft_deviation / unconfirmed`。

## 13. Token、模型调用与成本控制

### 13.1 Token 精简

| 浪费来源 | 改造方式 |
| --- | --- |
| 每个 Agent 反复读完整项目 | 按任务装载当前镜头、必要资产和前后连续性 |
| 已批准事实反复让模型总结 | 结构化事实直接读取 |
| 每个阶段都生成长 QA 报告 | 默认只输出结构化问题和必要解释 |
| 批注一条立即分析/生成一条 | 整片收集完后统一聚类和执行 |
| 模型做可确定的规则校验 | Schema、费用、参数、任务状态、依赖交给程序 |
| 失败后无限扩写提示词重试 | 设停止条件，区分参考资产 / 模型能力 / 镜头设计原因 |
| 全模型全场景重复真实测试 | 契约测试 + Fake Provider 为主；真实模型限额、有目的验证 |

### 13.2 成本衡量

不只看 LLM Token。分别记录文本理解、内容检查、图片、视频、声音、失败重试和人工活跃操作时间。最终关注：

- 每个被用户接受镜头的总成本
- 每可用成片秒成本
- 非目标内容误改导致的重做成本

### 13.3 批量修改的成本优势

统一处理一轮批注可以共享成片上下文、合并重复、发现同一根因，并一次计算依赖与预算。

## 14. 测试与质量策略

精简模型消耗，但不降低软件可靠性。研发测试与创作质量检查分开。

### 14.1 软件工程测试

| 测试层 | 默认策略 | 是否需要真实 AI |
| --- | --- | --- |
| 单元 / Schema / 迁移 | 自动化、确定性 | 否 |
| 状态机 / 恢复 / 重复提交 | Fake Provider + 故障注入 | 否 |
| UI / 时间线 / 依赖 | 固定夹具、E2E | 否 |
| 模型适配契约 | Mock/Fake + 少量真实 API | 仅契约变更时 |
| 质量漂移 | 固定代表性镜头与限额预算 | 按需 |
| 最终创作验收 | 真实素材，对照意图 | 需要 |

### 14.2 按变更影响选择测试

UI 样式变化不跑恢复矩阵。状态机变化必须跑恢复与重复提交。模型适配变化才跑受保护真实供应商测试。

**本文不取消 Phase 0 / Creator Beta 的工程门槛：** 六 kill 点恢复、`REMOTE_UNKNOWN` 不自动重提、黄金变更集漏失效为 0、密钥不进 Renderer。这些不是“浪费 Token 的真实模型测试”。

### 14.3 AI 阅读日志

测试由脚本执行。AI 默认只读失败摘要、相关堆栈和必要代码。成功日志留存但不回灌模型。

## 15. 系统架构与核心数据模型

沿用模块化单体：React + TypeScript + Vite；Electron 桌面壳；Python / FastAPI；桌面 SQLite、服务器 PostgreSQL；内容寻址素材；FFmpeg；统一任务执行接口。OpenAPI / JSON Schema 是前后端唯一跨语言真相。

AI Agent 只产生候选和建议，不能直接修改数据库真相。工作流引擎负责任务状态、版本、依赖、预算、重试、恢复和审批记录。

建议仓库结构保持 `apps/` `services/` `packages/` `infra/` `docs/` `tests/`，不因本文改栈。

### 15.1 核心对象

| 对象 | 职责 |
| --- | --- |
| Project / Episode / Scene | 作品组织 |
| StoryBible / Canon | 故事事实、关系、来源 |
| Character / Outfit / SceneAsset / Prop / Voice | 可复用版本化资产 |
| ShotIntent | 供应商无关镜头意图 |
| PromptPlan / CompiledRequest | 请求计划与供应商编译 |
| GenerationAttempt / AssetVersion | 生成尝试与不可变媒体版本 |
| ContinuityStateBefore/After | 镜头前后连续性 |
| TimelineVersion / ClipVersion | 成片组装与素材引用 |
| **ReviewRound / ReviewAnnotation** | 一轮审片与时间码批注 |
| **ChangePlan / ChangeItem** | 统一修改方案与可执行项 |
| Task / Attempt / BudgetReservation | 确定性任务、尝试、预算预留 |

### 15.2 修改依赖

区分重新检查、重新编译、重新生成、重新导出。字幕错字只需改字幕并重导出；对白变化可能影响 TTS、口型和时间线；表情变化通常只重做当前镜头并检查衔接；角色身份变化扩大到引用该角色版本的镜头。

## 16. 权限、安全、版权与可追溯

- 桌面本地服务只监听随机 `127.0.0.1`，受控 IPC / 令牌；多人协作使用带认证的工作室服务。
- API Key 以 CredentialRef 引用，前端不读明文。
- 模型调用记录供应商、模型、参数、输入输出哈希、费用和任务 ID。
- 角色、声音、图片、音乐和原著来源保存权利信息；系统示例资产必须有许可证。
- 来源事实、用户决定、AI 推断、AI 新增内容明确区分。
- 正式发布前检查缺失媒体、关键声轨/字幕、严重安全问题、权利状态和导出规格。
- Agent 工具白名单；不提供任意 Shell / SQL / 文件系统 / 网络。导入小说与网页一律视为不可信输入。

## 17. 产品指标与验收标准

产品成功必须同时量 **“是否少费力、是否接近意图”** 和 **“工程上会不会把项目做坏”**。

### 17.1 产品体验指标（本文新增，作为产品北极星）

| 指标 | 目标含义 |
| --- | --- |
| 不进入高级提示词编辑器的完成率 | 普通用户是否真正不用学 Prompt |
| 每成片分钟的人工活跃操作时长 | 系统到底替用户做了多少制作工作 |
| 关键意图满足率 | 用户明确要求是否被表达 |
| 非目标内容误改率 | 改一个点时是否连无关内容一起变 |
| 指定修改一次通过率 | “这里改成 X”是否真改对 |
| 角色/服装/道具硬连续性错误 | 资产体系是否降低跨镜头漂移 |
| 每可用成片秒总成本 | 含失败和重试的真实成本 |
| 生成后到用户接受的平均修改轮次 | 可控性与初次理解质量 |
| 批注合并率 / 无效重生成减少量 | 统一审片是否降低浪费 |

### 17.2 工程可靠性指标（不因本文降低）

| 指标 | 门槛 |
| --- | --- |
| 数据丢失 / 重复收费事故 | 目标 0 |
| `REMOTE_UNKNOWN` 自动重提 | 0 |
| 来源覆盖率 | 需依据原著的批准事实 95% 有 SourceSpan |
| 黄金变更集漏失效 | 0 |
| 本地任务恢复 | 60 秒内可解释状态 |
| 已提交产物 | RPO=0 |
| G8 可审计 | 成片资产能追溯到具名人类、时间和输入版本 |

## 18. 风险、边界与决策原则

| 风险 | 处理原则 |
| --- | --- |
| 用户以为 AI 可 100% 精确局部改视频 | 区分设定锁定与像素保持；不支持时提示可能变化 |
| 为了质量不断加长提示词 | 先查参考资产、控制方式、模型能力和镜头设计 |
| Agent 数量导致 Token 与延迟膨胀 | 角色保留，调用按需；合并相关职责 |
| 时间线功能无限膨胀 | 只做漫剧生产所需；复杂调色/VFX/DAW 外置 |
| 内置资产造成版权风险 | 可审计授权；demo-only 阻断 G8 |
| 自动修改扩大影响 | 先出 ChangePlan 和影响范围，确认后再执行 |
| 普通模式静默扣费 | 费用、能力损失、权利阻断在两种模式都可见 |
| 本文被当成替换 ADR 的新规格 | §0.2 效力表；冲突先开 ADR |
| 模型供应商能力变化 | Provider Capability Profile 版本化，编译前检查 |
| 质量检查过多消耗成本 | 硬规则程序化；高风险和用户指定要求才用内容模型 |

后续需求变更优先判断：它是否增强“意图准确、资产复用、AI 自动化、定点修改、成本可控”，而不是单纯加功能数量。

## 19. 研发实施原则

### 19.1 PM 冻结的产品决策

- 定位：AI 原生漫剧/短剧工作台，不转向通用 NLE。
- 普通/专业共享质量标准，模式是视图。
- AI 为主执行者；用户负责意图、关键选择、审片和最终接受；发布权在人。
- 完整审片后统一修改是核心体验，Creator Beta 就必须有。
- 角色/资产/连续性是基础设施。
- 提示词是编译产物，不是产品中心。

### 19.2 SE / 架构冻结的技术契约

- ShotIntent、AssetVersion、ContinuityState、ReviewAnnotation、ChangePlan 等核心 Schema。
- Agent Proposal 与数据库写入边界。
- Provider Capability / CompiledRequest 的能力降级语义。
- 依赖失效分类：检查 / 编译 / 生成 / 导出。
- 任务防重复提交、预算预留、远程未知状态对账。
- 有理数时间基；桌面 sidecar 安全模型。

### 19.3 软件研发优先保证的体验

- 同一项目普通/专业切换无数据割裂。
- 任意镜头都能追溯到角色、服装、场景、声音、生成版本和批注。
- 批注保存后继续播放；审核完成后统一分析。
- AI 修改后自动生成新版本并替换时间线引用，旧版本可回退。
- 默认界面不暴露 Prompt、Seed、模型参数；专业模式可展开。

### 19.4 AI 工程效率原则

- 结构化事实优先；上下文最小化；按需 Agent。
- 批量生成前先做能力和预算检查。
- 内容检查输出偏差证据，不写长篇文学化评价。
- 失败到阈值后停止抽卡，输出根因分类和可执行替代。
- 测试环境默认 Fake Provider。

### 21.3 典型场景 A：普通用户制作 3 分钟漫剧

用户粘贴故事并提供两张主角参考图。AI 完成拆解、角色建档、场景规划、分镜、生成与基础组装。用户做三件事：确认人物和故事、完整看片批注、确认统一修改方案。全程不打开高级提示词。G8 以“确认导出”出现。

### 21.4 典型场景 B：专业用户精修关键表演

导演在专业模式定位 Shot 023，展开表演意图、参考输入和模型能力。上传一段表演参考或调整首尾状态。系统只对 Shot 023 创建新 GenerationAttempt，检查前后衔接并替换 ClipVersion。

### 21.5 典型场景 C：整片审片后批量修改

用户在 8 分钟成片中留下 18 条时间码批注。AI 识别 5 条字幕/错字、3 条声音、6 条对应 4 个视频镜头、2 条剪辑节奏、2 条重复。形成一个 ChangePlan，用户确认预算后一次执行，避免 18 次独立 Agent 链。

## 结语

Aijian Studio 的核心不是让用户学会专业制作，而是把专业制作能力变成 AI 可以调用、程序可以约束、用户可以审阅和修改的系统能力。

最终体验：用户准确说清楚想表达什么；系统自动完成大部分制作；用户看成片、在具体时间点指出哪里不对；AI 理解整轮意见、保护已满意内容，用最小代价修到接近期望。

**发布权始终在人。扣费必须可解释。模式切换不得伤害数据。**

本文作为产品、SE、软件研发、AI 工程、影视制作和 QA 的统一讨论基线（overlay）。后续变更先问：它是否增强意图准确、资产复用、AI 自动化、定点修改、成本可控；再问：它是否触碰 ADR 与质量基线。触碰工程契约就开 ADR，不要改叙事了事。
