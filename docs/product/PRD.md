# Aijian Studio 产品需求规格 v0.1

状态：Draft
目标版本：Creator Beta（第 24 周）、Studio Beta（第 36 周）、1.0 GA（第 48 周）

## 1. 产品定义

Aijian Studio 是 AI 原生的漫剧/短剧生产系统。它接受小说、剧本或创意，协助团队完成来源解析、故事圣经、分集、剧本、分镜、视觉资产、视频、声音、剪辑、审片和发布。与简单“一键视频生成器”的区别是，系统把每一步保存为可编辑、可审阅、可追溯的版本化产物。

产品首先服务中文竖屏漫剧与短剧，同时保证领域模型不锁死画幅、语言和供应商。

## 2. 目标与非目标

### 目标

- 让个人创作者在 Windows 单机完成从文本到可发布短片的闭环。
- 让工作室在服务器工作区内分工、审片、批注、审批和追踪费用。
- 支持整本小说分阶段拆解，并能从任一剧本/镜头反查原文依据。
- 通过 BYOK 接入 OpenAI、xAI 和其他服务；同一项目可混用不同供应商。
- AI 失败或改稿时只重做受影响节点，保留已批准成果。
- 输出普通 MP4、素材包、字幕、配音、提示词/运行清单和专业时间线交换文件。

### 1.0 非目标

- 不训练自有基础模型。
- 不承诺 ChatGPT/Grok 网页会员可直接当 API 使用；账号登录自动化不进入产品。
- 不做与 Premiere/Resolve 完全等价的通用 NLE。
- 不在手机上完成复杂时间线精剪。
- 不做无人监督的自动发布；所有发布必须经过 G8。
- 不在首版做两个离线数据库的双向冲突合并。

## 3. 用户与关键任务

| 用户 | 首要任务 | 成功标准 |
| --- | --- | --- |
| 个人创作者 | 把小说章节快速做成一集漫剧 | 安装后 30 分钟内创建项目并完成第一版镜头表；断点可恢复 |
| 制片人 | 控制范围、工期、预算和审批 | 能看到每集状态、预算消耗、阻塞和负责人 |
| 编剧 | 从长篇原文生成可改剧本 | 每段重要改编可反查来源；改稿不会覆盖旧版 |
| 导演/分镜师 | 把戏转为可执行镜头 | 镜头意图结构化，能锁定角色/场景/服装版本 |
| 美术/生成师 | 批量生成并筛选一致资产 | 候选、选中、批准状态清晰；失败可换供应商 |
| 配音/声音师 | 组织台词、声线、音效和音乐 | 声音与台词/时间线绑定，授权信息可查 |
| 剪辑师 | 快速完成粗剪并局部重做 | 上游变更能精确提示受影响 Clip，不全片重做 |
| 审片人/客户 | 手机上批注和通过版本 | 无需安装桌面软件，可按时间码评论和审批 |
| 管理员 | 管理工作区、成员、密钥和成本 | 成员看不到明文密钥；有审计日志和预算限制 |

## 4. 端到端用户旅程

### 4.1 从整本小说开始

1. 用户创建项目，选择作品类型、画幅、单集目标时长、集数范围和视觉方向。
2. Creator Beta 导入 TXT/Markdown/DOCX；1.0 再加入 EPUB。PDF/OCR 属于 1.0 之后；系统解析章节与段落并显示低置信度项。
3. 用户在 G1 修正章节，系统生成故事圣经和冲突报告。
4. 制片/编剧在 G2 冻结人物、世界观和时间线基线。
5. AI 给出多套季/分集方案以及每套预计镜头数、成本和改编损失；用户选择或混合。
6. 系统生成 Adaptation Ledger 和分集卡，G3 通过后逐集生成场景剧本。
7. 用户像编辑文档一样改剧本；所有台词/动作显示来源和“原著/新增”标记。
8. 导演/美术先完成 VisualBible，导演 Agent 生成镜头表和 CoveragePlan，在 G6A 冻结镜头设计。
9. 系统用临时对白生成 Animatic，并对高风险镜头生成 1–2 秒 MotionProof；G6B 通过后才允许昂贵正式视频任务。
10. 系统编译模型提示词、生成候选资产并管理角色/场景一致性。
11. 剪辑器形成 RoughCut，G7A 输出补拍/重生成清单；完成 FineCut 后在 G7B Picture Lock。
12. 画面锁定后完成 Online/Mix/Subtitle/Legal，在 G7C 冻结 Master 候选。
13. 具名人类审批人完成 G8 Master Release，才能导出正式成片与生产清单。

### 4.2 从已有剧本开始

跳过长篇改编，但仍解析 Scene/Beat/Dialogue/Action、建立角色/场景资产和镜头来源。用户可以选择不关联原著，来源类型标记为 `screenplay`。

### 4.3 从一句创意开始

阿健制片 Agent 先采访约束，形成制作任务书，再由编剧生成故事提案。用户必须先选提案和确认 G0/G2，不能直接消耗视频生成费用。

## 5. 功能需求

里程碑标签是强制范围：`CB`=W24 Creator Beta，`SB`=W36 Studio Beta，`GA`=W48 1.0；`P1/P2` 不进入相应里程碑硬承诺。没有里程碑后缀的旧式 P0 表述无效。

### FR-1 项目、工作区与身份

- P0-CB：创建、复制、归档、导出/导入项目；项目拥有稳定 ID 和迁移版本。
- P0-CB：桌面本地工作区无需联网登录。
- P0-SB：服务器工作区支持登录、邀请、RBAC 和资源隔离。
- P0-CB：项目模板包含画幅、语言、目标时长、Gate、供应商策略和预算。
- P1-GA：跨项目复用经过授权的角色/风格资产。

### FR-2 原文和来源追踪

- P0-CB：导入 TXT/Markdown/DOCX；P0-GA 加入 EPUB。PDF/OCR 延后到 1.0 之后。
- P0-CB：SourceBlock 保存章节、段落、规范化 UTF-8 字节范围、原文映射和哈希。
- P0-CB：故事事实、剧本场景和镜头可以关联多个精确版本 SourceSpan。
- P0-CB：新增、合并、移动、删除均进入 Adaptation Ledger。
- P0-GA：原文更新后显示差异和受影响产物，不自动覆盖。
- P1-GA：敏感内容提示只给风险，不自行篡改原文。

### FR-3 故事圣经和连续性

- P0-CB：人物、地点、组织、道具、服装、关系和事件时间线。
- P0-CB：区分“来源事实”“用户决定”“AI 推断”，推断需置信度和证据。
- P0-CB：版本比较、合并建议和冲突报告。
- P0-GA：角色在不同年龄/时期的形象分支；服装和道具状态随场景变化。
- P0-GA：生成前连续性阻断规则和生成后视觉相似度提示。

### FR-4 分集和剧本

- P0-CB：单故事弧、集弧、钩子、转折、时长/字数预算和场景卡。
- P0-GA：多套方案比较；用户可锁定某些集后重算其他集。
- P0-CB：结构化剧本编辑器，支持场景标题、动作、人物、台词、旁白和备注。
- P0-CB：批注、变更追踪、版本比较、退回和批准。
- P1-GA：导入/导出 Fountain、Final Draft 兼容格式之一。
- P0-CB：台词口语化、平台节奏、临时对白、配音时长和字幕可读性检查。

### FR-5 镜头和分镜

- P0-CB：ShotIntent 结构包括叙事目的、主体、动作、景别、机位、构图、光线、运动、时长、剪辑手柄和声音意图。
- P0-CB：镜头表、卡片墙和故事板三种视图共享同一数据。
- P0-CB：角色/场景/服装/道具使用已批准的具体版本。
- P0-CB：批量生成分镜候选、评分、对比、选中和批准。
- P1-GA：事件图/无限画布，用于人物关系、场景空间和镜头因果。
- P0-CB：带 scratch voice 的 Animatic、CoveragePlan 和高风险镜头 1–2 秒 MotionProof；G6B 未通过禁止完整视频生成。

### FR-6 提示词编译与模型接入

- P0-CB：文本、图像、视频、TTS 四类能力接口；P0-GA 再加入音乐和口型。
- P0-CB：内置 OpenAI、xAI 和安全受限的 OpenAI-compatible 文本适配；其他供应商按真实合约测试加入。
- P0-CB：ProviderProfile 只引用 CredentialRef，不返回明文密钥。
- P0-CB：PromptPlan 可编辑，CompiledPrompt 显示供应商差异和能力损失。
- P0-CB：调用前成本估计/预留；调用后记录服务商任务 ID、模型、参数、费用和哈希。
- P0-CB：限流、熔断、重试、远程未知状态和手动对账；未知结果状态禁止自动重提。
- P0-GA：可视化供应商策略，如质量优先、成本优先、隐私优先。
- P1-GA：外部 ComfyUI 工作流适配，不分发 ComfyUI 代码/模型。

### FR-7 素材和生成

- P0-CB：内容寻址素材库、元数据、代理媒体、缩略图和版本。
- P0-CB：候选/选中/批准/废弃状态，任何覆盖均生成新版本。
- P0-CB：图片到视频、首尾帧、参考角色/场景的输入表达。
- P0-CB：失败先生成影响报告，再局部重跑或换供应商，保留失败证据。
- P0-GA：素材去重、相似度搜索、重复费用警告。
- P0-SB：批量任务队列、优先级、暂停、取消和维护窗口。

### FR-8 声音

- P0-CB：VoicePlan、角色声线卡、台词分配、情绪/语速/停顿、试音和批准。
- P0-CB：TTS、录音上传、对白替换、自动字幕和人工校对。
- P0-CB：SoundSpottingPlan、对白/环境/SFX/音乐基础轨、CueSheet、基础 ducking 和人工 MixApproval。
- P0-GA：ADR/PickupList、口型任务、stems、MixMaster 与具体视频/配音版本绑定。
- P0-GA：响度、峰值、静音和声画同步自动检查。

### FR-9 领域剪辑器

- P0-CB：Assembly Editor——镜头顺序、帧精确入出点、基础转场、多轨声音、字幕、代理预览、自动粗剪、撤销/重做和 MP4 导出。
- P0-SB：保留 CB 编辑能力，增加时间码评论、审片标记和单编辑者锁；不新增核心剪辑命令。
- P0-GA：Core Editorial——insert/overwrite、ripple/roll/slip/slide、linked selection、snapping、markers、轨道锁/mute/solo、J/L cut、代理回连、镜头/台词/提示词/来源联动和版本比较。
- P0-GA：OTIO/OTIOZ 导入导出；FCPXML/EDL 仅在真实消费者测试通过后标 supported，否则为 experimental。
- P2：复杂调色、节点特效和专业音频混音，优先交给外部 NLE。

### FR-10 协作、审片和通知

- P0-SB：工作区成员、角色权限、项目/剧集/镜头责任人。
- P0-SB：时间码评论、@人、状态、修改单和 Gate 审批。
- P0-SB：手机 PWA 查看代理、圈画/语音意见；审批必须在线且版本匹配。
- P0-SB：操作和审批审计日志。
- P1-GA：剧本/卡片多人实时协作；时间线采用编辑锁，不做无约束多人同剪。

### FR-11 导出、发布和可携带性

- P0-CB：MP4、WAV、SRT/VTT、分镜图片、剧本、镜头表和项目清单。
- P0-GA：完整项目归档包含数据库快照、素材清单、哈希、来源、模型和授权信息。
- P0-CB：ReleaseManifest 记录成片使用的每个资产版本和 DeliveryProfile 版本。
- P0-CB：RightsLedger 逐资产记录来源、输入权利、模型/供应商与条款版本、商业使用、肖像/声音同意、音乐同步权、字体许可证和输出哈希；未清权资产不可豁免并阻断 G8。
- P0-GA：OTIO/OTIOZ；外部 NLE 回导需显式冲突处理。
- P0-CB：至少一个版本化 1080×1920/25fps/H.264/AAC/48kHz DeliveryProfile；平台预设只做检查，不保存平台账号密码。

### FR-12 管理和可观测性

- P0-CB：任务中心显示状态、尝试、负责人、费用、日志摘要和可执行动作。
- P0-CB：项目预算、日限额、供应商限额和告警；P0-SB 加工作区预算。
- P0-CB：健康检查区分 API、SQLite、FFmpeg 和供应商；P0-SB 加 PostgreSQL、对象存储和队列。
- P0-CB：日志默认脱敏，不记录完整密钥、未授权原文和签名下载 URL。
- P0-SB：OpenTelemetry 指标/链路，服务器可接 Sentry 或兼容服务。

## 6. 非功能需求

| 类别 | 1.0 指标 |
| --- | --- |
| 数据完整性 | 进程崩溃后已提交产物 RPO=0；破坏性迁移前有验证快照；旧程序不兼容时只读拒绝而非伪装降级；导出清单哈希可验证 |
| 恢复 | 本地任务重启后 60 秒内恢复可判断状态；远程任务不盲目重复提交 |
| 性能 | 10 万 SourceBlock、1 万 Shot 的项目可打开；常用列表虚拟化；1080p 代理播放交互不卡死 UI |
| 安全 | 服务器强制认证/租户隔离；桌面 API 仅回环和会话令牌；密钥不以明文回传 UI |
| 可测试 | 领域/工作流单测，Provider 合约测，数据库双后端测，桌面安装和浏览器 E2E |
| 可移植 | Windows 11 x64 首发，标准用户可运行且无开发工具；ARM64/macOS 不承诺；Electron/Python/经审计 FFmpeg 随安装包；服务器 Linux 容器；PWA 现代 Chromium/Safari |
| 可访问 | 核心表单键盘可操作，颜色不作为唯一状态，字幕/音频内容有文本替代 |
| 国际化 | 业务数据 Unicode；UI 首发简体中文，文案架构支持英文 |

## 7. 产品质量指标

- 来源覆盖率：批准剧本中需要依据原著的事实/场景，95% 以上存在有效 SourceSpan。
- 局部重做正确率：先生成影响报告；只有时长、边界状态和接口均不变时原位替换，否则正确失效相邻转场、字幕、对白、口型、mix 和连续性检查；黄金变更集漏失效为 0。
- 远程提交安全：`REMOTE_UNKNOWN` 状态下自动重提为 0；所有潜在重复进入人工对账。对不支持幂等/查询的供应商不承诺绝对零重复扣费。
- 项目恢复率：模拟强制退出后，100 个任务场景均能恢复为可解释状态。
- 首集成功率：新用户在不看源码情况下可完成一集 30–90 秒粗剪。
- 审批可审计率：所有进入 ReleaseManifest 的资产与 G8 决定必须追溯到具名人类审批人、时间和输入版本；自动批准仅限低风险中间候选。

## 8. 里程碑验收

### Creator Beta（W24）

Windows 单机邀请制安装包可完成：TXT/Markdown/DOCX → 故事圣经 → 单集剧本 → VisualBible → 镜头/Coverage → scratch-voice Animatic/MotionProof → 云端图片/视频/TTS → Assembly Editor → 基础 Mix → 1080p MP4。只承诺一个题材和 `{text,image,video,TTS}` 每类至少一个认证供应商；RightsLedger/G8、崩溃恢复、密钥、成本和来源链必须通过。不得称“完整长篇自动改编”“全动态电影级”或“专业 NLE”。

### Studio Beta（W36）

局域网/私有云部署可供至少 10 名成员、3 个并行项目使用；具备认证/RBAC、对象存储、队列、手机审片、评论审批和可观测性。桌面可连接服务器工作区。

### 1.0 GA（W48）

1.0 定义为“混合 motion-comic 平台”：单部中文作品最多 30 万字/2,000 个 SourceBlock/1,000 个 Shot 的规划与来源链，可靠生产一个故事弧的连续 3 集；具备 Core Editorial、正确失效、ReleaseManifest、项目归档和 OTIO 交换。完整全书/多季生产、三题材各连续三集以及“全动态”标签属于 V2。完成威胁模型、许可证清单、升级/只读回退、备份恢复和 held-out 项目验收。

GA 的质量评审分成 Technical QC、Continuity QC、Editorial QC、Creative Review 和 Rights QC；自动检查只能覆盖前两者的一部分，最终创意与权利必须由人确认。

## 9. 开放决策

- 正式产品名和仓库名。
- GitHub 贡献者治理和首次社区发布时点。自有代码许可证已由 Owner 确认为 Apache-2.0；第三方代码仍必须逐项通过来源和兼容性审计。
- Creator Beta 必须支持的首批视频生成供应商，以真实 API 可用性和成本验证决定。
- 是否在 W36 前加入 macOS 桌面；默认不承诺。
- 中文剧本导出标准优先 Fountain 还是自定义 DOCX 模板。
