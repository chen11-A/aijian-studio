# AIVORA Desktop Creator — UI Demo 开发规格

状态：UI Demo Implementation Spec  
适用分支：`aivora/ui-demo-worldview`  
基线：`codex/phase0-ffmpeg-toolchain`  
范围：仅 UI 演示；不代表真实 AI、Provider、数据库、生成、费用、时间线、审片执行或发布能力已经实现。

---

# 1. 产品 UI 硬约束

1. 五阶段固定：`故事 → 角色与世界 → 分镜 → 制作 → 审片`。
2. 普通/专业不是两套软件；模式属于 `ViewPolicy`，不进入 Project，不参与 Artifact hash。
3. 切换模式不丢 Project / Episode / Scene / Shot / 时间码 / 选中版本 / AI 会话。
4. 分镜 = Storyboard + Animatic；正式 AI 视频只发生在制作阶段。
5. 审片 = 完整看片 → 多条批注 → 审核完成 → ChangeProposal；不边看边改。
6. 字幕/声音/剪辑能解决的问题不默认重生视频。
7. 未生成页面必须显示真实 readiness/空状态，禁止假头像、假世界图、假进度、假成片。
8. 普通模式 Complexity Budget：每页 1 个 Primary Action；默认 0 个技术参数；同页最多 1 条主时间线。
9. 导出不是第六阶段。
10. AI/Codex/Claude 不得自行重新设计几何布局；以下 Layout Contract 为实现约束。

# 2. 全局几何布局契约

## 2.1 基准视口

| 项目 | 值 |
|---|---:|
| 基准设计画布 | `1600 × 900` |
| 第一验收视口 | `1600 × 900` |
| 第二验收视口 | `1440 × 900` |
| 最低 Desktop 宽度 | `1180px` |
| `<900px` | 非第一阶段 Desktop 验收目标 |
| 示例项目画幅 | `16:9` |

## 2.2 普通模式 Shell

```text
┌──────────────────────────────────────────────────────────────────────────────┐
│ Top Bar 72                                                                   │
├──────────────┬────────────────────────────────────────┬──────────────────────┤
│ Left Nav     │ Main Workspace                         │ Aivora AI            │
│ 200          │ min 650 / flex                         │ 320                  │
│ fixed        │ primary scroll container               │ fixed/own scroll     │
└──────────────┴────────────────────────────────────────┴──────────────────────┘
```

冻结 Token：

```ts
export const aivoraLayout = {
  referenceWidth: 1600,
  referenceHeight: 900,
  topbarHeight: 72,
  leftNavWidth: 200,
  assistantWidth: 320,
  inspectorWidth: 300,
  mainMinWidth: 650,
  pageOuterGap: 14,
  pagePadding: 22,
  sectionGap: 16,
  cardRadius: 12,
  controlRadius: 8,
  primaryButtonHeight: 72,
  stageBarHeight: 54,
};
```

## 2.3 滚动与固定规则

这是强约束，避免 AI 把整个 body 一起滚走：

- App 根容器高度 = `100vh`；默认 `overflow: hidden`。
- Top Bar 固定在应用顶部，不跟 Main 一起滚动。
- Left Nav 在 Desktop 下固定在第二行，可自己滚动；项目存储卡固定在左栏底部。
- Main Workspace 是**主要纵向滚动容器**。
- Stage Bar 位于 Main 顶部并 `sticky`；滚动长页面时仍能看到当前阶段。
- Aivora AI 在宽屏固定在右侧，可独立滚动；输入区固定在面板底部或 sticky bottom。
- Drawer/Modal 出现时只锁 Main/App 滚动，不改变底层布局尺寸。

## 2.4 Top Bar

顺序固定：

```text
AIVORA | Project Switcher | flexible spacer | 普通/专业 | 保存状态 | 用户
```

- 高度 `72px`。
- Brand 宽约 `190–210px`。
- Project Switcher 宽约 `170–210px`。
- 模式切换采用 Segmented Control。
- 保存状态和用户信息为辅助权重。
- 不在 Top Bar 再放第二套主流程导航。

## 2.5 左侧 Project Navigation

宽度 `200px`；一级项 `42–44px` 高；二级项缩进 `36–44px`。

唯一结构：

```text
创作
故事
角色与世界
  角色
  世界观
  场景
分镜
制作
审片
────────
素材
导出
────────
AI 服务
设置
```

禁止增加一级项：`AI生成 / 声音制作 / 时间线 / 审片修改 / 工作空间`。

当前子页面使用唯一高亮；父级只显示展开态，不与子项抢高亮。

## 2.6 顶部 Stage Bar

```text
① 故事  ›  ② 角色与世界  ›  ③ 分镜  ›  ④ 制作  ›  ⑤ 审片
```

- 高 `52–58px`，默认 `54px`。
- 位于 Main Workspace 顶部，推荐 sticky。
- 当前阶段蓝色强调；已完成弱完成态。
- 子页面不改变阶段名。
- 旧设计图中的 `生成 / 成片` 两步已经废弃，统一为 `制作`。

## 2.7 Aivora AI

宽屏普通模式 `320px`。

```text
Aivora AI + 状态
当前上下文解释
最多 3 条快捷意图
flex spacer
[附件] [输入框................] [发送]
```

- 不重复主页面所有字段。
- 不抢 Primary CTA。
- 页面主功能与 AI 重复时，以主页面为主。
- 快捷意图单页默认不超过 3 个；更多内容进入对话，不铺成按钮墙。

## 2.8 专业模式

只有 `≥1720px` 才允许完整四栏：

```text
Left 200 | Main min 700 | Inspector 300 | AI 300
```

`1440–1719px`：

```text
Left 200 | Main | [Inspector / Aivora AI] 单一右侧栏 Tab
```

`1180–1439px`：

```text
Left 200 | Main | [Inspector / Aivora AI] 单一右侧栏 Tab（约300）
```

Inspector/Aivora AI 不得把 Main 压缩到 `<650px`。

## 2.9 Responsive

| 宽度 | 规则 |
|---|---|
| `≥1720` | 普通三栏；专业可四栏 |
| `1440–1719` | 普通三栏；专业 Inspector/AI 互斥 Tab |
| `1180–1439` | Left + Main + 右侧单栏；专业 Inspector/AI 互斥 Tab |
| `900–1179` | Left 可折叠；AI/Inspector Drawer；Main 优先 |
| `<900` | 非首期 Desktop 验收；仅保证不崩坏 |

原则：**先收辅助区，再缩主工作区。** 断点代码使用 `<1180` 时写成 `max-width:1179px`，避免 1180px 两套规则冲突。

## 2.10 字体与视觉

| 用途 | 字号 |
|---|---:|
| Page H1 | 30–34 |
| Object/Hero Title | 24–28 |
| Section Title | 18–20 |
| Body | 14–16 |
| Secondary | 12–13 |
| Tiny Status | 10–11 |

- Spacing：`8 / 12 / 16 / 20 / 24 / 32`。
- Card Radius：`12px`。
- Primary CTA 使用高饱和蓝。
- 紫色只做 AI/专业能力辅助强调。
- 主内容层级必须比导航、AI、状态面板更显眼。

# 3. 全局按钮契约

## 3.1 Button Hierarchy

| 类型 | 每页数量 | 用途 | 视觉 |
|---|---:|---|---|
| Primary | `1` | 当前页面唯一“向前/确认/执行”动作 | 实心蓝，高度 64–72 |
| Secondary | `0–3` | 修改、比较、辅助动作 | 深色/描边 |
| Weak/Text | 按需 | 详情、返回、展开 | 文本链接 |
| Danger | 极少 | 删除/放弃等破坏动作 | 红色，仅确认场景 |

规则：

- 同页不得出现两个视觉等价 Primary。
- `下一项` 用于同一阶段内部；`下一步` 用于进入下一个阶段。
- `返回` 恢复访问路径，不代表流程 Gate 回退。
- 所有付费按钮未来接真实逻辑时必须在执行前显示费用/影响；UI Demo 不伪造费用。
- Loading 时按钮保持尺寸不变，文字替换为状态 + spinner。
- Disabled 必须有原因提示，不只变灰。
- Header 只能出现 Weak/Tool Button；不能把页面主要确认动作移到 Header。

## 3.2 Button Placement

普通创作页默认底部动作栏：

```text
[Secondary / Previous]   [status / flex]   [Primary]
```

- Primary 右对齐，宽 `260–340px`，高 `64–72px`。
- Secondary 左侧，宽 `180–240px`，高 `56–64px`。
- 普通模式底部最多 2 个大按钮。
- “详细设定/查看原文/查看详情”放 Header 右侧或 Drawer 入口，使用 Weak 按钮。

## 3.3 Toolbar Button

像播放、筛选、排序、缩放、前后镜头这些属于 Tool Button：

- 高 `32–40px`；
- 不使用 Primary 蓝色大面积填充，除非它代表当前选中 Tab；
- 同一工具组使用一致尺寸；
- 图标必须配 tooltip；关键动作不能只用无标签图标。

# 5. 所有页面布局与按钮契约（逐页深度核对）

## 5.1 创作首页 / 项目入口

Stage Bar：未进入项目时隐藏；进入项目后出现。

区域比例：

- Header：约 72–96px。
- 最近项目：页面主区约 45–55%。
- 新项目/导入入口：约 25–30%。
- Aivora AI：项目首页可隐藏或收成弱入口，避免空项目仍占 320px。

```text
┌──────────────────────────────────────────────────────┐
│ 欢迎回来，陈                         [新建项目]       │
│ 继续你的 Aivora 创作                                  │
├──────────────────────────────────────────────────────┤
│ 最近项目                                              │
│ ┌────────────┐ ┌────────────┐ ┌────────────┐         │
│ │ 星夜之城   │ │ ...        │ │ ...        │         │
│ └────────────┘ └────────────┘ └────────────┘         │
├──────────────────────────────────────────────────────┤
│ 从这里开始：描述故事 / 导入小说或剧本                 │
└──────────────────────────────────────────────────────┘
```

按钮核对：

| 按钮 | 层级 | 位置 | 尺寸/权重 | Demo 行为 |
|---|---|---|---|---|
| 新建项目 | Primary | Header 右 | 120–160×40–44 | 打开本地新建流程 |
| 继续最近项目 | Secondary | 最近项目卡/卡底 | 中等 | 进入最近项目 |
| 导入小说/剧本 | Secondary | 起始区 | 中等 | 打开文件选择占位 |
| 项目 `···` | Weak Tool | 项目卡右上 | 32–36 | 菜单 |

禁止：把首页做成素材管理器、Provider 控制台或五阶段内容页。

## 5.2 故事理解

Stage：①故事。

**核对结论：旧图的卡片信息层次有价值，但电影大静帧已被产品审核明确废弃。故事主结果应该是结构化理解，而不是世界视觉。**

主布局：Main 内 `≈65% 内容理解 + 35% 关键确认/摘要` 或自适应两列；小屏回落单列。

```text
┌──────────────────────────────────────────────────────┐
│ 故事理解                                查看原文 ›    │
│ Aivora 已整理故事结构、人物与需要确认的内容           │
├──────────────────────────────┬───────────────────────┤
│ 故事概要 / 核心主题           │ 需要你确认            │
│ 剧情结构 / 关键事件           │ 只显示高影响歧义       │
│ 主要人物 / 情绪曲线           │ A / B / 直接修改       │
├──────────────────────────────┴───────────────────────┤
│ 哪里不对？                                  确认故事理解 → │
└──────────────────────────────────────────────────────┘
```

按钮核对：

| 按钮 | 层级 | 位置 | 备注 |
|---|---|---|---|
| 确认故事理解 → | Primary | 底部右 | 唯一主 CTA，进入角色 |
| 哪里不对？ | Secondary | 底部左 | 打开 inline/Aivora 修改 |
| 查看原文 › | Weak | Header 右 | Drawer，不抢 CTA |
| 歧义 A/B | Inline Choice | 确认卡内部 | 不是大按钮 |

禁止：`重新分析` 与 `开始分析` 同时出现；禁止世界观 Hero 图作为主内容。

## 5.3 角色总览

Stage：②角色与世界。

参考旧图，但普通模式收敛成：角色卡横排/网格 + 当前角色摘要 + 人物关系弱入口 + 必要确认。

建议 Main 内部：

- 上半角色卡/当前选择 `≈55–60%`；
- 下半世界摘要/关键设定 `≈25–30%`；
- 底部动作栏 `≈10%`。

```text
┌──────────────────────────────────────────────────────┐
│ 角色                                    + 新增角色    │
├──────────────────────────────────────────────────────┤
│ [林晚] [陆沉] [苏璃] [程野]                         │
│ 当前角色卡：身份 / 一句角色定位 / 本集造型状态         │
├──────────────────────┬───────────────────────────────┤
│ 人物关系（弱图/摘要） │ 需要确认（仅高影响）          │
├──────────────────────┴───────────────────────────────┤
│ 修改角色                         确认本集角色 →      │
└──────────────────────────────────────────────────────┘
```

按钮：Primary `确认本集角色 →`；Secondary `修改角色`、`新增角色`；Weak `查看角色关系 ›`。

角色卡中的 `修改` 不允许每卡都做高亮蓝；统一描边小按钮或菜单。

## 5.4 角色详情 / 多视图 / 本集造型

参考图中**中间多视图为视觉中心**，这一点冻结。

Main 三段：

1. Header + 当前角色信息 `≈10%`；
2. 多视图大预览 `≈50–55%`；
3. 本集造型横条 + 状态摘要 `≈25–30%`；
4. 底部动作 `≈10%`。

在 `1600×900` 下可保留左侧“其他角色”窄列表，宽 `160–190px`；若 Main 变窄则折叠，不能与全局 Left Nav 形成两个同等导航栏。

按钮：

- Primary：`确认本集造型 →`，底部右。
- Secondary：`哪里不对？`，底部左。
- Secondary Tool：`新增造型`，造型横条右上。
- Weak：`返回角色列表`、`角色详情 ›`。
- 多视图切换是 Tool/Segment，不是 CTA。

普通模式不显示版本 v4、Prompt、Reference Weight 等技术控制；专业 Inspector 才显示。

Main 内部：

- Header `≈90px`；
- 16:9 Hero `占 Main 可用宽度 90–100%`，高度由画幅决定；
- Summary `≈140–180px`；
- Action Row `72px`。

| 按钮 | 层级 | 位置 | 规格 |

## 5.6 场景

参考图核对后，普通模式应保留**大 Hero + 右侧视角竖 strip + 下方视角/环境状态 strip**，而不是改成传统表单。

Main 建议：

```text
┌──────────────────────────────────────────┬───────────┐
│ 16:9 场景主预览                          │ 视角竖条   │
│ 雨夜街道                                  │ 主参考/全景│
│                                            │ 正向/反向 │
├──────────────────────────────────────────┴───────────┤
│ 场景视角参考横条：主参考/全景/左右/高低/关键区域       │
├──────────────────────────────────────────────────────┤
│ 环境状态横条：默认雨夜 / 白天 / 傍晚 / 夜晚 / 大雨... │
├──────────────────────┬───────────────────────────────┤
│ 修改场景             │ 下一项：分镜 →               │
└──────────────────────┴───────────────────────────────┘
```

可选场景信息放 Hero 右侧窄栏或 Weak Drawer，宽不超过 Main 的 24%。

按钮：Primary `下一项：分镜 →`；Secondary `修改场景`；Secondary Tool `新增场景`；Weak `场景地图/查看空间设定`。

空状态只能显示 LocationCandidate 文本/占位，不放成片质感假图。

## 5.7 分镜 / Animatic

参考图为高权威，必须保留以下层级：

1. 场次 Tab/选择条；
2. **大 Animatic Preview（最大）**；
3. Shot Card 横 strip；
4. **唯一一条分镜时间线**；
5. 右侧场次信息或 Aivora AI（不能再增加第二镜头列表）。

```text

│ 场次Tab：场次1 / 场次2 / ...             工具按钮   │
```

## 5.10 审片（普通模式，高权威）

此页是当前最明确的普通模式 Reference Frame，必须严格：

- 大播放器在左上，宽约 Main 内部 `70–74%`；
- 批注列表在右上，宽约 `26–30%`；
- **一条帧级时间轴**横跨播放器/批注区下方；
- 时间轴上用彩色 Marker 标注批注；
- 底部动作只保留 `添加批注 / 选择时间范围 / 播放控制 / 审核完成`；
- Aivora AI 在最右全局面板，不能抢 `审核完成`。

```text
┌──────────────────────────────────┬───────────────────┐
│ LARGE PLAYER                     │ 批注列表（8）     │
│                                  │ #1 #2 #3 ...      │
├──────────────────────────────────┴───────────────────┤
│ SINGLE FRAME TIMELINE + COMMENT MARKERS              │
├──────────────┬──────────────┬─────────────┬──────────┤
│ + 添加批注   │ 选择时间范围 │ 播放控制    │ 审核完成 →│
└──────────────┴──────────────┴─────────────┴──────────┘
```

按钮：

- Primary：`审核完成 →`，底部最右，大蓝按钮。
- Secondary：`+ 添加批注`，底部最左，可紫蓝强调但低于 Primary。
- Secondary/Tool：`选择时间范围`、`播放控制`。
- Weak：批注卡 `···`；筛选 `全部`；排序 `时间从早到晚`。

点击 `审核完成` 只结束 ReviewSession 并进入 ChangeProposal 分析，不自动执行修改。

禁止：第二条时间线、镜头列表、独立“标注片段”列表同时出现。

## 5.11 修改方案 / ChangeProposal

审片后独立页面或 Drawer，不是第六阶段。

建议布局 `70% 方案列表 + 30% 影响摘要`：

```text
┌──────────────────────────────────┬───────────────────┐
│ 修改方案列表                     │ 影响/费用/风险     │
│ #1 表演调整                      │ 受影响 Shot       │
│ #2 字幕修正                      │ 预计费用           │
│ #3 声音调整                      │ 风险               │
├──────────────────────────────────┴───────────────────┤
│ 返回审片                         确认执行修改 →      │
└──────────────────────────────────────────────────────┘
```

Primary `确认执行修改 →`；Secondary `返回审片`、`调整方案`。

UI Demo 不显示伪造费用，用 `未连接真实费用`。

# 7. 所有页面 Empty / Loading / Error 统一布局

## 7.1 Empty / Waiting

```text
加载失败
原因摘要
[重试] [查看详情]
```

破坏性恢复动作必须单独确认。

# 8. Modal / Drawer / Popover 契约
