# AIVORA Desktop Creator — UI Demo 开发规格

状态：UI Demo Implementation Spec  
适用分支：`aivora/ui-demo-worldview`  
基线：`codex/phase0-ffmpeg-toolchain`  
范围：仅 UI 演示；不代表真实 AI、Provider、数据库、生成、费用、时间线、审片执行或发布能力已经实现。

---

# 1. 产品 UI 硬约束

1. 五阶段固定：`故事 → 角色与世界 → 分镜 → 制作 → 审片`。
2. 普通/专业不是两套软件；模式属于 `ViewPolicy`，不进入 Project，不参与 Artifact hash。
3. 切换模式不丢 Project / Episode / Scene / Shot / 时间码 / 选中版本 / AI 会话。
4. 分镜 = Storyboard + Animatic；正式 AI 视频只发生在制作阶段。
5. 审片 = 完整看片 → 多条批注 → 审核完成 → ChangeProposal；不边看边改。
6. 字幕/声音/剪辑能解决的问题不默认重生视频。
7. 未生成页面必须显示真实 readiness/空状态，禁止假头像、假世界图、假进度、假成片。
8. 普通模式 Complexity Budget：每页 1 个 Primary Action；默认 0 个技术参数；同页最多 1 条主时间线。
9. 导出不是第六阶段。
10. AI/Codex/Claude 不得自行重新设计几何布局；以下 Layout Contract 为实现约束。

- Project Switcher 宽约 `170–210px`。

- 保存状态和用户信息为辅助权重。

```text
① 故事  ›  ② 角色与世界  ›  ③ 分镜  ›  ④ 制作  ›  ⑤ 审片
```

- 高 `52–58px`，默认 `54px`。
- 位于 Main Workspace 顶部。
- 当前阶段蓝色强调；已完成弱完成态。
- 子页面不改变阶段名。

## 2.6 Aivora AI

宽屏普通模式 `320px`。

```text

当前上下文解释
最多 3 条快捷意图
flex spacer
[附件] [输入框................] [发送]
```

- 不重复主页面所有字段。
- 不抢 Primary CTA。
- 页面主功能与 AI 重复时，以主页面为主。

## 2.7 专业模式

足够宽：

```text
Left 200 | Main min 700 | Inspector 300 | AI 300
```

不够宽：

```text
Left | Main | [Inspector / Aivora AI] Tab
```

Inspector 不得把 Main 压缩到 `<650px`。

## 2.8 Responsive

| 宽度 | 规则 |
|---|---|
| `≥1440` | 普通完整三栏；专业按空间决定四栏或 Inspector/AI Tab |
| `1180–1439` | Left + Main + AI；专业 Inspector/AI 互斥 Tab |
| `900–1179` | Left 可折叠；AI Drawer；Main 优先 |
| `<900` | 非首期 Desktop 验收；仅保证不崩坏 |

原则：**先收辅助区，再缩主工作区。**

## 2.9 字体与视觉

| 用途 | 字号 |
|---|---:|
| Page H1 | 30–34 |
| Object/Hero Title | 24–28 |
| Section Title | 18–20 |
| Body | 14–16 |
| Secondary | 12–13 |
| Tiny Status | 10–11 |

- Spacing：`8 / 12 / 16 / 20 / 24 / 32`。
- Card Radius：`12px`。
- Primary CTA 使用高饱和蓝。
- 紫色只做 AI/专业能力辅助强调。

# 3. 全局按钮契约

## 3.1 Button Hierarchy

| 类型 | 每页数量 | 用途 | 视觉 |
|---|---:|---|---|
| Primary | `1` | 当前页面唯一“向前/确认/执行”动作 | 实心蓝，高度 64–72 |
| Secondary | `0–3` | 修改、比较、辅助动作 | 深色/描边 |
| Weak/Text | 按需 | 详情、返回、展开 | 文本链接 |
| Danger | 极少 | 删除/放弃等破坏动作 | 红色，仅确认场景 |

规则：

- 同页不得出现两个视觉等价 Primary。
- `下一项` 用于同一阶段内部；`下一步` 用于进入下一个阶段。
- `返回` 恢复访问路径，不代表流程 Gate 回退。
- 所有付费按钮未来接真实逻辑时必须在执行前显示费用/影响；UI Demo 不伪造费用。
- Loading 时按钮保持尺寸不变，文字替换为状态 + spinner。
- Disabled 必须有原因提示，不只变灰。

## 3.2 Button Placement

普通创作页默认：Primary 位于 Main Workspace 内容底部右侧；Secondary 位于其左侧。Header 只允许 Weak Action。

Stage：⑤审片。

```text

│         LARGE PLAYER             │ #01 00:01:24:18  │
```

比例：右批注栏约 Main 的 `26–30%`；播放器 `70–74%`。

按钮：Primary `审核完成 →`；Secondary `+ 添加批注`；Weak `上一条/下一条批注`。

规则：

- 审核完成只结束 ReviewSession 并进入 ChangeProposal 分析。
- 不边看边自动修改。
- 不同时显示镜头列表 + 批注片段 + 第二条时间轴。

# 5. 所有页面 Empty / Loading / Error 统一布局

## 5.1 Empty / Waiting

Main 主区域中央展示：图标或轻量占位 + 一句话真实状态 + 缺少依赖 + 1 个推荐动作。

示例：

```text
分镜尚未生成
✓ 故事已确认
△ 角色与造型未确认
△ 场景未确认

[前往角色与世界]
```

禁止用“默认成片图”填空。

## 5.2 Loading

- 不改变页面大框架。
- Hero/列表使用 Skeleton。
- Primary CTA 进入 loading，不新增第二按钮。
- Aivora AI 可显示“正在准备 UI Demo 状态”，不得伪造 Provider 状态。

## 5.3 Error

错误卡位于发生错误的区域，不整页弹巨大 Modal，除非无法继续。

```text
生成失败 / 加载失败
原因摘要
[重试] [查看详情]
```

UI Demo 的错误仅本地模拟。

# 6. Modal / Drawer / Popover 契约

- `详细设定`：右侧 Drawer，宽 `420–480px`。
- `哪里不对？`：优先 Inline Panel 或右侧 AI 上下文，不用全屏 Modal。
- 删除/放弃：小型确认 Dialog。
- 付费确认（未来真实能力）：Modal/Sheet，显示影响范围 + 费用 + Primary `确认`。
- Inspector：专业模式固定侧栏，不作为普通 Modal。

# 10. AI 开发执行规则

# 11. UI Demo 验收清单

- 五阶段名称与顺序完全一致。
- 左导航唯一结构一致。
- TopBar / LeftNav / AI 宽度符合 Contract。

- Aivora AI 不抢页面主操作。
- 普通→专业→普通不丢当前页面/对象。
- 1600×900、1440×900 两个视口布局通过。
