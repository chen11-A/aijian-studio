# Manual draft review revision linkage

Status: implementation for integration; schema 42 must follow director schema 41.

Saved exact-output manual notes can be selected with original assembly segment IDs to create an immutable manual revision plan. The server freezes original note content, segment geometry, media/shot references and content hashes. A distinct explicit action approves this exact plan hash for manual work only. Existing assembly editing and draft export remain separate actions.

After approval a newly created assembly and newly queued, successfully verified draft export in the same episode may be attached as a human-selected comparison candidate. The candidate must have an assembly version number higher than the maximum existing at approval and server creation timestamps later than approval. Original and candidate frames/timebases are kept distinct. Segment-ID comparison identifies changed/removed/added IDs, undeclared changes, and changed sequence settings. This is association evidence, not causation or proof of correction.

A separate human recheck records NEEDS_MORE_WORK or MANUALLY_CHECKED plus a reason, pinned to the candidate hash. One final recheck per candidate is immutable; another attempt uses another candidate. No action resolves old notes, edits old versions, launches generation, calls providers, signs formal gates, approves release or changes rights.

At most 100 plans and 20 total comparison candidates are retained per source output. New evidence must also keep the exact history payload below 12 MiB, leaving room under the existing 16 MiB native transport ceiling. Candidate output verification is memoized only inside a single history read; write gates always rehash their required output. All mutation IDs are client-generated. Atomic writes accept only exact identical retries; different content with an existing ID conflicts. Saved requests and immutable event hashes are validated on reads against original notes, assemblies, targets and linkage. Missing original output bytes block new plan and approval actions. Candidate attachment and recheck require verified candidate bytes; already frozen original evidence remains available even if its output is missing. No missing output erases existing history. Revision evidence checks themselves do not update export jobs. The UI deliberately reuses existing export list/get/preview facilities; those facilities retain their established reconciliation of missing or changed completed files into FAILED job status. That status update neither edits nor deletes original bytes, assembly versions or review evidence. Renderer uncertainty persists the same command and reads back exact content before reporting saved; no automatic replay or replacement IDs.

Migration registration and generated shared contracts are coordinated by the integration owner. Added source code has no external dependency or upstream copied code. Runtime tests require the existing unavailable Python/Node dependencies; no installation, build, package or app-install validation is part of this change.

Shared OpenAPI and declaration additions were reconciled additively from authoritative review model source with stdlib AST tooling. Existing definitions remain semantically unchanged. Official FastAPI export, openapi-typescript regeneration, contracts-check, full typecheck/lint/format and dependency-backed tests remain unrun until the existing dependencies are available; this reconciliation is not a generator pass.
