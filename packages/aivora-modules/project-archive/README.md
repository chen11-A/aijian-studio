# 作品打包备份

输入本地作品文件夹，`packProject` 输出 `.aivora` ZIP 文件及清单；`importProject` 校验后输出实际导入文件夹路径。整个过程离线，适用于 Node 20+，支持中文和空格路径。Windows 实机测试尚未进行。

```ts
import { packProject, importProject } from './index.js';
await packProject('/作品/第一集', '/备份/第一集.aivora');
const folder = await importProject('/备份/第一集.aivora', '/恢复');
console.log(folder); // 已有同名作品时自动使用 第一集 (1)
```

Windows 路径由调用者使用 `path.join` 构造，或使用正确转义的字符串。输出备份不得放在原作品文件夹中，也不会覆盖已有备份。

## 大作品与流式处理

默认最大文件内容 **20 GiB**（21,474,836,480 字节），最多10000个文件及目录。第三参数可调整：`{ maxBytes, maxFiles }`。采用 yazl / yauzl 的 ZIP64 与按需打开条目接口，一次只读写一个文件。文件内容经过64 KiB流缓冲计算 SHA-256；不会把视频、整个作品或压缩包读入内存。文件清单与中央目录是有限大小的内存元数据；清单上限4 MiB。

`.mp4`、`.png`、`.ogg`、`.jpg`、`.webp`、`.mov`、`.m4a`、`.mp3`（不区分大小写）采用 **STORE** 原样存储，不再压缩；其他文件采用DEFLATE。清单在最后一个文件完成哈希后写入。ZIP64支持单文件超过4 GiB及总包超过4 GiB；实际大文件测试目前为1 GiB以上，未实测20 GiB极限。

解包先检查中央目录、本地头与清单，再逐文件流式写出并核实长度及 SHA-256。发现坏文件立即报中文错误并删除新建的不完整作品，不触碰已有同名作品。打包过程中源文件大小改变或读取失败，会删除此次创建的不完整备份。调用者应避免在备份时修改作品；没有提供文件系统快照或互斥锁。

## 完整性与安全

清单保留相对路径、文件长度和 SHA-256，空目录也保留。内容逐字节恢复；修改时间、权限和硬链接关系不作保留。拒绝 Windows 保留名称、尾空格、尾句点、反斜杠、绝对路径、`..`、大小写碰撞路径、符号链接、加密及不支持的压缩算法。ZIP本地路径和大小也与中央目录交叉验证；流式解压受预期大小限制。导入只接受本模块清单版本，兼容上一版输出的普通ZIP。

校验值用于检测损坏，不提供来源签名或防篡改认证。请保证目标文件夹由当前用户控制，不要让其他进程在导入期间替换其内部路径。

## 测试与性能记录

在上级目录运行 `npx vitest run project-archive`。包括往返一致、中文路径、空目录、同名改名、坏文件、路径跳出、限制、输入文件变化、失败清理及STORE存储检查。

`large.test.ts` 每次实际生成 **1 GiB + 1 MiB** 的稀疏 `.mp4` 测试文件，完整读取全部字节进行打包、导入及前后独立SHA-256校验。不是仅模拟大小。由于STORE，压缩包和恢复文件都实际占约1GiB磁盘，测试期间需至少3GiB可用空间，结束自动清理。文件是测试字节流，不是可播放视频。

最近一次Linux / Node24实测记录见 [PERFORMANCE.json](./PERFORMANCE.json)：打包约17.42秒，导入约1.93秒，峰值RSS约135.2MiB，比测试开始增加约77.4MiB。计时和10毫秒采样RSS均包含真实IO，受机器负载、页缓存与测试覆盖插桩影响，不能当成跨机器性能保证。运行时另写 `/tmp/aivora-archive-large-report.json`（通过系统临时目录构造，不限定系统路径）。
