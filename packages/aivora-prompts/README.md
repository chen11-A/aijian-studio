# AIVORA 智能体提示词库

8 个角色，每个角色一个 JSON 文件：系统提示词、输入格式、严格的输出结构（都带 JSON Schema），以及用测试小说《雨夜旧书店》写的 3 个示例。这个目录只放提示词和校验脚本，软件里还没有接入，现有的调用仍在 `services/api/src/aijian_api/agents/prompts/` 和 `apps/studio-web/src/aivora/pro/ProWorkspace.tsx`。

## 文件

| 路径                           | 内容                                               |
| ------------------------------ | -------------------------------------------------- |
| `roles/writer.json`            | 编剧：一章分成几场，原文对白一字不改、一句不少     |
| `roles/art.json`               | 美术：画风、固定外貌、服装、定妆照、空镜、道具图   |
| `roles/director.json`          | 导演：多场分镜，起始画面和带参考图的视频提示词     |
| `roles/performance.json`       | 表演指导：微表情、眼神、手势、呼吸和配音提示       |
| `roles/action.json`            | 动作指导：打斗拆成有力度和方向的动作节点，记录受伤 |
| `roles/sound.json`             | 声音设计：每场环境声、对齐动作节点的音效、配乐情绪 |
| `roles/continuity.json`        | 场记：前后镜头的服装、道具、站位、伤妆是否连贯     |
| `roles/review.json`            | 审片：同一镜头几个版本并排对比，推荐一版           |
| `schema/role-file.schema.json` | 角色文件本身的结构                                 |
| `fixtures/test-novel.md`       | 测试小说，三章六场，段落编号 P01–P39               |
| `scripts/validate.mjs`         | 校验脚本                                           |
| `scripts/validate.test.mjs`    | 校验脚本的反例测试（故意改坏，确认会报错）         |
| `scripts/json-schema.mjs`      | 不依赖第三方包的 JSON Schema 2020-12 检查          |
| `scripts/rules.mjs`            | Schema 写不出来的规则，以及示例之间的串联检查      |
| `scripts/reply.mjs`            | `parseReply()`：按软件的方式解析模型回复           |
| `scripts/novel.mjs`            | 读测试小说、取引号里的台词、算台词字数             |

## 流程和分批

```text
小说一章 → 编剧 → 美术 → 导演 → 表演指导、动作指导 → 声音设计 → 场记
                                       ↓
                           生成起始画面和视频（每镜几个版本）
                                       ↓
                                     审片 → 用户在「一选多」里选定
```

| 角色     | 一次发什么                                 | 示例规模                    |
| -------- | ------------------------------------------ | --------------------------- |
| 编剧     | 一整章的全部段落                           | 每例一章，分出两场          |
| 美术     | 一章的场次，加上已锁定的画风、人物和地点   | 第二、三例锁定第一例的画风  |
| 导演     | 一章的全部场次                             | 13、16、10 个镜头           |
| 表演指导 | 导演这一批的全部镜头，没人物的镜头自动跳过 | 同上                        |
| 动作指导 | 这一章所有有肢体动作的镜头                 | 3、7、3 个镜头              |
| 声音设计 | 一章的全部场次和候选素材                   | 每例两场                    |
| 场记     | 一章的全部镜头和上一批结束时的状态         | 13、16、10 个镜头           |
| 审片     | 几个镜头的全部版本，帧图加起来不超过 14 张 | 每例三个镜头，10 到 14 张图 |

示例 1、2、3 分别对应第一、二、三章。同一个编号的示例是接起来的：编剧示例 1 的输出就是美术和导演示例 1 的输入，导演示例 1 的镜头就是表演、动作、声音、场记、审片示例 1 的镜头。校验脚本会核对这些地方一字不差。

## 怎么发请求

1. 系统消息：`system_prompt` 用换行符连起来，把其中的 `{{OUTPUT_SCHEMA}}` 换成 `JSON.stringify(output_format.schema)`。
2. 用户消息：`JSON.stringify(input)`，结构见 `input_format.schema`。
3. 需要示范时，可以把 `examples` 里的输入和输出当成前几轮对话放进去。审片示例里的 `<IMAGE_n>` 没有附真实图片，只用来看结构，不要当成对话历史发出去。
4. 审片要附图（`attach_images` 为 `true`）：按 `<IMAGE_1>`、`<IMAGE_2>`…… 的顺序附上抽帧图，`attached_images` 写附了几张。

回复用 `scripts/reply.mjs` 里的 `parseReply(text, output_format.schema)` 解析：整段文字只做一次 `JSON.parse`，带代码块、前后有说明文字、多了字段都算失败，不去修补。失败时按现有做法先再要一次，还不行就用离线结果并说明原因。

## 共同约定

- 只输出一个 JSON 对象。字段一个不多、一个不少；没有内容写 `null` 或 `[]`。所有对象都是 `additionalProperties: false`，模型写进去的思考过程、分析之类的字段会直接校验失败。需要给用户看的理由只放在 `reason` 字段，一句话。
- 一次处理多场、多镜头。每个角色的输入都是一批，输出按输入顺序全部写完。
- 编号：场次 `S01`，镜头 `S01-01`，版本 `S04-07-T1`，动作节点 `S04-05-A1`，原文段落 `P01`，场记问题 `CI-01`；人物、服装、地点、道具、图片分别以 `char_`、`cos_`、`loc_`、`prop_`、`img_` 开头，声音素材以 `amb_`、`sfx_`、`mus_` 开头。
- 时间单位是秒。镜头长度是 1 到 15 的整数（软件生成时也限制在 1 到 15 秒）。台词按每秒 4 个字估算，标点不算；第一句不早于 0.4 秒开始，说完离镜头结束至少 0.6 秒，两句之间至少隔 0.2 秒。
- 参考图：视频提示词用 `<IMAGE_1>` 到 `<IMAGE_14>` 引用，一个镜头最多 14 张，按顺序编号，列出的每张都要用到。`<IMAGE_0>` 留给软件放这一镜的起始画面（和 `apps/studio-web/src/aivora/film/operations.ts` 里的写法一致），模型不写 `<IMAGE_0>`。起始画面提示词只用文字。
- 人物的固定外貌句（`identity_lock`）由美术定下以后原样放进每个镜头；起始画面提示词还要原样带上这一场的衣服描述。
- 视频本身不出声：`video_sound` 为 `false` 时视频提示词写「视频不要自己出声。」，对白、环境声、音效、配乐都另外做。
- 画风段落由软件在最后统一加一次，角色写的提示词里不重复。受伤只拍衣服上的血迹，不拍伤口特写（画风预设本身写了不要血腥）。
- 字符串里不用英文双引号，需要引号时用「」，免得模型漏掉转义导致解析失败。
- 人物名字、编号只能照抄输入；素材库里没有合适的声音时写 `null` 并说明缺什么，不编造。

## 校验

```bash
node packages/aivora-prompts/scripts/validate.mjs
node --test packages/aivora-prompts/scripts/
```

`validate.mjs` 依次检查：

1. 每个角色文件符合 `schema/role-file.schema.json`，正好 3 个示例，系统提示词里正好有一处 `{{OUTPUT_SCHEMA}}`。
2. 输入和输出 Schema 只用 `json-schema.mjs` 支持的关键字；遇到不支持的关键字直接报错，不会悄悄跳过。
3. 每个示例的输入、输出都通过 Schema，输出能被 `parseReply()` 一次解析。
4. 每个角色自己的规则，例如：编剧的台词和原文引号里的话逐句对上；导演的台词全部落进镜头、放得下、参考图编号合法；受伤部位之后只做力度 1 的动作；每个有接触的动作节点都配了音效；审片把软件查出的黑屏和静帧都写进问题。
5. 同一编号的示例之间数据一致。

全部通过时退出码为 0，否则为 1，并逐条列出问题。脚本只用 Node 自带的模块，不需要安装依赖。这个目录故意没有 `package.json`：加了以后 pnpm 会把它当成工作区的一个包，`pnpm install --frozen-lockfile` 需要同时更新 `pnpm-lock.yaml`。
