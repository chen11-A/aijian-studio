# 峰值安全修复

第二轮先对已有 129 条最终 Ogg 实测；62 条解码采样峰值超过 0 dBFS，最高 +15.332722 dBFS，与反馈一致。共 80 条采样或真峰超过 -1 的文件已修复；所有文件的前后结果和实际衰减量见 `PEAK_REPAIR.json`。

检测使用同一次 FFmpeg 解码的 `astats` 与 `loudnorm`：`astats` 检查解码浮点采样绝对峰值，`loudnorm.input_tp` 检查真峰值。**没有先转换为有界整数 PCM**，因此不会把 Ogg 中超过 0 dBFS 的浮点样本截断后误报安全。

修复采用固定衰减到约 -1.7 dB 峰值，再编码成 48kHz Ogg，并重新测量最终输出。若编码重建峰值仍超过 -1，则进一步衰减并重新编码；只在最终检测通过后替换文件。不把短促瞬态硬压成同一积分响度，也不提升安全但偏安静的素材。为峰值安全降低的文件用 `peakLimited: true` 明示，`loudness`、`truePeak`、`samplePeak` 和 SHA-256 记录最终实测值。原库修复后的最大采样峰值为 -1.052554 dBFS、最大真峰值为 -1.05 dBTP。

`check.py` 独立重新测量每个文件，采样峰值或真峰值任一高于 -1 就失败；同时核对清单值。低于目标 LUFS 只在明确 `peakLimited` 时允许，不能靠放宽峰值阈值通过。极短（不足 400 毫秒）自然音效有时无法测得积分响度；此时只允许 `loudness: null` 且有 `loudnessNote`，必须与实际测量一致，峰值仍照常检查。较长的无声文件不能使用这条例外。

`peak_safety.py` 提供可复用的 `measure_levels` 和 `repair_file`，必须传入 FFmpeg 完整路径。整库 CLI 会按运行当时文件生成新的报告；本轮 `PEAK_REPAIR.json` 是修复前后审计快照，应保留而不要用重复运行覆盖它。新素材应使用同样的最终编码峰值检查。

真实回归测试生成大于 0 dBFS 的浮点 Ogg，确认检查器拒绝，再实际衰减/重编码并确认通过；另有不足 400 毫秒音效的真实积分响度不可测回归。未做主观试听，客观峰值安全不代表场景内容或听感已经人工批准。
