## Proposed matrix and required evidence

1. Establish a synthetic existing LOCAL Sub2API connection by one explicit repository CAS on a fresh copied DB; read back mode, canonical loopback URL, revision and unchanged credential reference. Record the baseline before each subsequent case.
2. Edit that LOCAL connection with omitted `origin_mode` and its local URL. Parse an actual request model or equivalent fields-set representation, call the same-version service, and assert rejection **before** `update_metadata_cas`; spy count 0, complete logical DB snapshot unchanged, no approval/consumption row change.
3. Repeat the omitted-mode edit with a valid public HTTPS URL. The request model defaults to PUBLIC, but the existing LOCAL policy must still reject before CAS: spy count 0 and unchanged DB. This is the regression-sensitive branch.
4. Explicit `LOCAL_LOOPBACK_HTTP` with matching revision and canonical local URL may edit metadata once; read back revision + 1 and exact mode/URL. A stale revision must fail with no committed mutation. Keep the displayed/authoritative revision distinction visible in the case record.
5. Explicit `LOCAL_LOOPBACK_HTTP` → `PUBLIC_HTTPS` with a valid public origin and matching revision must make exactly one repository CAS; read back PUBLIC, URL, revision + 1 and unchanged credential reference, rotation history and scope rows. Invalid public origin and stale revision must not commit.
6. An existing PUBLIC connection with omitted `origin_mode` remains compatible: request-model default PUBLIC, one CAS with matching revision, PUBLIC readback and revision + 1.
7. Pin an approval to the old LOCAL origin, mode and revision. After an explicit switch to PUBLIC, the same-version approval-binding policy must return `APPROVAL_SCOPE_MISMATCH` for that old approval. Record the old and new origin binding hashes, mode and revision. This QA01 assertion is policy-level invalidation evidence; it does not claim atomic consumption behavior.

For every case: record exact input hashes, module `__file__`, copied DB hash, raw exception/status, repository CAS invocation count, readback values, full logical DB dump, schema version, `integrity_check`, `foreign_key_check`, rotation/scope/approval/consumption counts, and no WAL/SHM after close. One failure or uncertain result stops the one-shot run. No retry.
