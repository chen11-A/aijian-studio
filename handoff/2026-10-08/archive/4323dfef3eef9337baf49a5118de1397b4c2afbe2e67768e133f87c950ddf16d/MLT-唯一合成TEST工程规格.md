# MLT 唯一合成 TEST 工程规格

日期：2026-09-28。用途：验证本地双视频轨、独立提示音与 BGM、一次视觉叠化、字幕、保存重开及 MP4 导出。工程和产物均标 `SYNTHETIC_TEST_ONLY`，不使用《离别》、待核权利 JPG 或真实供应商媒体。

## 1. 现有交接点

- A 线须提供独立 TEST 作品、分集、脚本版本与两个脚本块；对白提示音和字幕引用这些测试 ID，不引用《离别》版本。所有媒体经选定资产版本、实际 SHA256、权利决定和 pinned ffprobe 记录后才能进入受控工程。
- C 线现有 `EpisodeMediaAssemblyContentV1` 只允许视觉段无空隙、无重叠顺接；本规格的 V1/V2 重叠属于 MLT 适配验证目标，不能塞入旧合同后称已支持。现有 64 帧代理 WebM 仅能先验证单视频解码与时间基。
- D 线现有 `product_timeline_export_*` 是只读阻断预检，返回 `BLOCKED/NO_EXPORT_CLAIM`；开发工具链为 `DEVELOPMENT_ONLY`。本地 MLT 渲染通过不自动解除正式导出、权利或发行门。

## 3. 唯一工程时间线

总长 **125 帧＝5.000 s**，时间基 **25/1 fps**，输出画布 **1080×1920**。所有区间均从 0 起、左闭右开；48 kHz 下每帧正好 1,920 个样本。

本合成 TEST 的 V1/V2 源均为 320×568，映射到 1080×1920 时固定用 **`STRETCH_TO_CANVAS`**：填满画布，不裁切、不留边，左右白色识别竖条必须完整可见。源与输出画幅比相差约 0.16%，此处允许该轻微变形以便检查转场；正式作品须按自身画幅与构图单独确定映射策略，不以本 TEST 的 stretch 作默认。

| 轨道/事件 | 帧区间 | 预期 |
| --- | --- | --- |
| V1 | `[0,75)` | 蓝底；帧 75 起底轨为空。 |
| V2 | `[50,125)` | 与 V1 重叠 25 帧；唯一视觉转场是 `[50,75)` 的蓝→红叠化，帧 75 起仅 V2 红画面。 |
| DIALOGUE_TEST 1 | `[25,50)` | 1.000–2.000 s，1000 Hz；输出采样区间 `[48000,96000)`；轨道 `gain_millidb=0`。 |
| DIALOGUE_TEST 2 | `[75,100)` | 3.000–4.000 s，1000 Hz；输出采样区间 `[144000,192000)`；轨道 `gain_millidb=0`。 |
| BGM_TEST | `[0,125)` | 0–5.000 s，220 Hz；输出采样区间 `[0,240000)`，叠化前后连续；轨道 `gain_millidb=0`。 |
| 字幕 S1 | `[25,50)` | `TEST 提示音一（非语音）`。 |
| 字幕 S2 | `[75,100)` | `TEST 提示音二（非语音）`。 |

两条音轨均用**精确轨道增益 `gain_millidb=0`**，即单位增益；源文件约 −12/−30 dBFS 峰值只是生成目标，不是轨道增益。不做响度归一化、限幅或自动鸭式压低；QA 量实测混合峰值及削顶，若有削顶保留失败，不能静默改变增益。字幕文本与两个合成脚本块绑定；QA 生成前 TEST 脚本版本/块 ID、内容哈希、SRT SHA 与字幕段 ID 均为待填，不得预造。保留 V1/V2、两个独立音轨和字幕在工程文件中的真实资源引用与选定版本；保存、正常关闭、重开后逐字段读回同一工程。SFX 本轮无输入，明确记 `ABSENT_TEST_SCOPE`；这份工程不能通过完整 P14/P19 五类轨道验收。

MLT XML 若使用含末帧的 `in/out` 表示，先把上述半开业务区间换成 V1 `0..74`、V2 `50..124`、视觉叠化 `50..74`、提示音 `25..49` 与 `75..99`、BGM `0..124`；回读 XML 后还原半开区间比较。MLT 多轨需显式验证视觉叠化与声音混合是否实际生效，轨道存在不算混合通过。MLT 的 [XML 文档](https://mltframework.org/docs/mltxml/) 给出 playlist、multitrack 和 `50..74` 转场示例；声音混合可用适配器所需机制，本规格只计一次**视觉**转场。

## 4. 可观察结果与停止条件

1. **视频**：导出 MP4/H.264、1080×1920、25/1 fps、125 帧、5.000 s。解码帧 0/49 中心为蓝、62 同时有红蓝贡献、75/124 为红；白色竖条帮助辨认来源。逐帧取避开字幕的中心区域，允许编码色差，不用单像素 RGB 精确相等判定。
2. **声音**：实际播放并解码输出 PCM。0–1、2–3、4–5 s 只听到低电平 220 Hz；1–2、3–4 s 同时可辨 220 Hz 与 1000 Hz。留两轨 stem、混合峰值和波形/频谱证据；无削顶、爆音、转场处静音或 BGM 断续。核 1000 Hz 起止相对帧 25/50/75/100 的实际采样偏差，系统性偏移目标 ≤1 帧（40 ms）；AAC 延迟和尾填充单列，不用容器音频 duration 单值代替听测。
3. **字幕**：帧 24/25/49/50 与 74/75/99/100 对照两条字幕显隐；文字可读、无乱码或遮挡，与提示音边界一致。若输出为独立字幕流，实际播放器开启字幕后再验；字幕数据存在本身不算可见。
4. **持久化与同版**：在同一 TEST 工程内保存、正常关闭并重开；核资源版本、哈希、轨道位置、转场、音量、字幕和总帧数。重开前后预览及重新渲染的关键帧/声段一致。记录 MLT profile/工程版本、渲染命令、输入/输出路径与 SHA、ffprobe 原始结果、播放器结果及失败原文。
5. **放行边界**：QA 先固定合成输入清单及 A/C/D 依赖和文件 owner；C 的重叠表示、D 的执行/输出回执、权利与技术 probe 未就绪时保持 `BLOCKED`，不手改数据库或绕过预检。即使本地技术测试通过，也不证明《离别》、普通话语音、口型、真实运动、正式发行编码器或最终用户验收。ART04 只对实际可播放且版本固定的产物另作观感审片。

## 5. 中文对白验收边界

当前已核范围只有合成图案、正弦波和一份内含 Opus 音调的代理 WebM，没有附权利凭证的本地中文 TEST 语音。`dialogue-test.wav` 的 1000 Hz 仅验证独立轨、混音、帧边界和字幕显隐；本工程对白状态固定为 **`DIALOGUE_SPEECH_NOT_TESTED`**。即使上述技术检查全部通过，也不能报告“中文对白清晰”“台词与字幕同步”或“口型通过”。

将来若 QA 获得无需 provider 的许可清楚的本地 TEST 语音，只在本工程的新输入版本中替换提示音：先封存来源、权利决定、准确中文短语、生成或录制方法、48 kHz PCM 文件、实际时长、SHA256 与对应 TEST 脚本块；再按实际语音时长重新固定对白和字幕半开帧段，独立试听、逐句比对文字、首尾对齐并核 ≤1 帧系统性偏移。没有这些收据时保持 `DIALOGUE_SPEECH_NOT_TESTED`，不得默认使用系统声音或真人录音。
