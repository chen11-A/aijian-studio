## Source entrances affected by a long managed blob path

| Module | Current operation and consequence at a 266-character blob path |
| --- | --- |
| `media_asset_store.py` | `os.link` line 234 raises WinError 3. `_availability` uses ordinary `Path.stat` (line 133), so a blob created with an extended hardlink would still report `MISSING`. `_verified_size_and_hash` and `read_verified_preview` call `_open_local_source` with the same unprefixed path. |
| `media_asset_selected_reader.py` | `_verify_blob` assembles the same path; `_open_local_source(blob)` is unprefixed, so authoritative selected readback cannot become `VERIFIED` merely by fixing the writer. |
| `media_asset_probe_store.py` / `media_probe.py` | `_managed_path` calls `source.is_file()`; `probe_local_media` calls `source.resolve(strict=True)`, `is_file`, and `stat`; `_open_windows_source` passes `str(path)` to `CreateFileW`. Thus persisted video probe registration is unavailable with an ordinary long path. |
| `media_asset_audio_inspection.py` | `_managed_path` calls `path.is_file`, then `_read_same_file` uses `_open_local_source` and `path.stat`; derived WAV inspection fails for the same long path. |
| `episode_media_assembly_store.py` | `_availability` uses `Path.stat` and `_open_local_source`, so a production assembly read can misclassify this stored blob as `MISSING`/unknown. |
| `mlt_execution_adapter.py` / `mlt_execution_worker.py` | Adapter uses selected `identity.path.is_file/stat`; worker holds `_open_local_source` then rechecks `path.stat`. The TEST plan/resource preflight would fail before MLT, even if preceding reads were fixed. Passing an extended path inside MLT XML is a separate unverified external-tool boundary. |
| `product_export_single_video_service.py` | Constructs the same blob path and sends it to the encoder. Its downstream path handling needs owner review; no formal-export claim follows from this analysis. |

The parent directories in the observed profile are shorter than 260 characters; the 64-character blob filename makes the full path cross the boundary. Other workspace roots may differ. The source audit is a list of reachable ordinary path operations, not a runtime acceptance claim for each module.

## Candidate source design and ownership gate

1. Define one Windows-only function for **already validated absolute local drive paths** that converts a logical filesystem path to a `Path` with `\\?\` prefix for OS file operations. Reject relative paths, UNC/remote drives, reparse/symlink surprises, `..` components, and unsupported prefix forms before conversion. Do not treat prefixing as a security bypass or canonicalization step. On other platforms, preserve the original `Path`.
2. Keep logical, unprefixed paths in product identities, manifests, audit records and user-visible responses. Use the converted path consistently for `os.link`, `Path.stat/exists/is_file/is_symlink/resolve`, and `CreateFileW`/file opening at each managed-blob boundary; retain same-handle SHA/size/stat checks. A one-line `os.link` patch is insufficient.
3. For Stage-A, the minimum complete source slice is the writer (`media_asset_store.py`) and selected readback (`media_asset_selected_reader.py`) plus their common file-opening helper (`media_probe.py`). Subsequent probe, audio, assembly, adapter, worker and export consumers need owner-coordinated changes before claiming a long-path TEST render or formal export. If a short QA profile is used to progress normal-path ASV import, it is an independent QA run and does not close this defect.
4. MGR01 must confirm sole writer per shared file before DEV06 source edits; MGR02 owns independent new-run approval and QA02 owns execution. Retain the original RED and compare exact source/closure hashes in a new frozen candidate. No automatic Stage-A retry.
